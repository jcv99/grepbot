# Audit — 2026-08-24 — v5.10.36

Post-fix audit. Sweep ran against the v5.10.34 (BroadcastChannel captcha
events) and v5.10.35 (gbAbortFeature) feature commits, which had bypassed
the v5.10.33 phase 8 audit. Five investigator agents in parallel covered
hard-rules, XSS/wire-value injection, numeric-read discipline, recent diff,
and post-layer correctness. Source code at v5.10.36 (post-fix).

## Findings

### 1. BroadcastChannel ping-pong escalates captcha ladder (HIGH)

**Where:** `src/core.js:1679-81` (pre-fix).

The cross-tab captcha receiver called `captchaTrip(feature, detail)`
unconditionally on every received message. `captchaTrip` increments
`state.captchaBreakers[feature].trips`, sets a longer `until` from the
5/15/60min ladder, and re-emits via `gbEventsEmit('captcha', …)`. Two
GrepBot tabs on the same world therefore escalated a single observed
captcha from the intended 5-minute backoff to the 60-minute cap within
milliseconds, and each re-trip also cleared `state.csrf` + `csrfForceHunt`
on the receiving tab (the captcha hadn't actually been observed there —
the receiving tab was only hearing about a peer's captcha).

The "Idempotent: captchaTrip on an already-paused feature is a no-op"
comment was wrong: `captchaTrip` always bumps `trips` and always re-emits.

**Fix:** receiver now validates `feat` is a non-empty string and skips
the trip if `captchaPaused(feat)` is true. Re-emission stops at most one
hop past the original captcha.

**Secondary:** the receiver previously stored `captchaBreakers['undefined']`
if any caller ever omitted the feature (payload-shaped edge case). The
string guard closes that.

### 2. BroadcastChannel dispose leak (HIGH)

**Where:** `src/core.js:1671` (pre-fix).

The BC `'message'` listener was added with
`_gbEvents.addEventListener('message', …)` rather than through `gbListen`,
so `gbListenerAbort.abort()` could not detach it. `__grepbotDispose`
cleared timers, aborted XHRs, restored hooks, unregistered menus, and
disconnected the DOM observer — but never closed the BroadcastChannel.
A hot reload (TM editor save, devtools re-inject) therefore leaked the
previous instance's listener and channel handle; a long-lived tab could
accumulate stale listeners that still fired against a dead instance.

**Fix:** disposer now calls `_gbEvents.close()` and nulls the reference.

### 3. gbAbortFeature dead helper (HIGH)

**Where:** `src/core.js:240` + `src/core.js:2165` (pre-fix).

`gbAbortFeature(feature)` was added in v5.10.35 to cancel per-feature
in-flight `gbXhr` calls when a feature was toggled OFF mid-flight. The
helper compared `handle.feature === feature`, but the `gbXhr` factory
set `handle.feature = opts.feature || ''` and no caller ever passed a
`feature:` opt — every handle was tagged with the empty string. The
helper therefore could not match anything and was effectively dead code.

Six call sites were unwired: `src/farms.js:1341`, `src/towns.js:43`,
`src/towns.js:137`, `src/spy.js:338`, `src/phoenician.js:204`,
`src/alerts.js:154`.

**Fix:** each call site now passes `feature: '<feature-key>'` where the
key describes the scrape/webhook purpose (`farm-scrape`, `town-list-scrape`,
`town-scrape`, `spy-report`, `pt-trade-view`, `webhook`). The keys are
arbitrary match strings, not write keys, so they do not need to be
registered in `TX_WRITE_FEATURES`.

### 4. CSRF thrash on cross-tab captcha (HIGH, subsumed by fix 1)

The CSRF thrash was the downstream symptom of finding 1: every
re-emission cleared `state.csrf` and called `csrfForceHunt()` on the
receiving tab. Closed by the same receiver guard.

## Other audits (no findings)

### Hard-rules sweep

`src/boot.js:113` carries a naked `3000` ms literal. The comment on
that line already flags it as needing to follow `RELEASE_DEDUP_MS`.
Spirit violation only — the constant is the same value. Deferred to a
dedicated constants sweep.

Seven `replaceChildren()` calls in HUD/intel/stats/cave/build-tab
renders are bare in timer callbacks. All are gated by `sameSet`
membership checks (or dataset-key signatures), so they don't wipe on
every tick. Spirit violation only — no user input is lost. Deferred.

### XSS / wire-value injection

`innerHTML` calls in `src/`: 9 safe, 0 unsafe, 1 mechanical nit
(`src/ui.js:1018` panel template assigned directly without routing
through `gbLit`; literal-only today). `outerHTML`,
`insertAdjacentHTML`, `document.write`: 0 usages. `setAttribute` and
`classList` reviews clean. `gbSafe` / DOMPurify references: 0 live (3
grep hits are documentation comments referencing the v5.10.2 removal).

### Numeric-read discipline

`gbNum` defined at `src/core.js:21` with 16 call sites. Systemic
violation: `Number.isFinite(+wire)` and unguarded `+wire` reproduce the
exact CLAUDE.md failure mode (`+null → 0 → isFinite → guard passes`)
across `recruit.js`, `farms.js`, `intel.js`, `god-spells.js`,
`phoenician.js`, `dump.js`, `hud.js`, `wonder.js`, `parse-inline.js`,
`build-tab.js`, `build-targets.js`, `ui.js` Config handlers, and
local `txNum` / `favorNum` / `wonderNum` closures that duplicate
`gbNum`.

Highest-impact reproductions: `recruit.js:248-252` (cost-per-unit math),
`cave.js:32` (hide-level 0 collides with -1 sentinel), `farms.js:610`
(relation level 0), `phoenician.js:42` (town id 0 collision),
`dump.js:107` (fill % never triggers → silent skip), `hud.js:90` (eta 0s).

Out of scope for v5.10.36. Requires a dedicated sweep that unifies
`txNum` / `favorNum` / `wonderNum` into `gbNum` and migrates the
read sites. Tracked as a follow-up.

## Process note

v5.10.34 (BroadcastChannel) and v5.10.35 (gbAbortFeature) shipped
through the regular feature-commit path and were not caught by the
v5.10.33 phase 8 audit (which ran before either feature landed). The
periodic audit had drifted from catching feature defects to re-checking
existing code. Future audits should include a diff-vs-last-audit
recency slice so any feature commit that lands between audits gets
the same sweep.
