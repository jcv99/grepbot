# Grepbot Audit — 2026-08-13

Generated by a 5-agent parallel audit (`AgentSwarm`). Scope: the entire
`/media/vol/linux/Backups/j/Documents/DeV/grepbot` repository — 50 modules in
`src/*.js`, the `build.py` concat pipeline, and the shipped `grepbot.user.js`
artifact. Each finding cites `src/<file>.js:<line>` so the original evidence
is recoverable. Severity (HIGH/MEDIUM/LOW) reflects impact *and* ease of
fix; severity is not "my bug is worse than yours."

## How to read this

1. Start with [Cross-cutting Top 10](#cross-cutting-top-10). The same underlying

## Cross-cutting Top 10

Ranked by combined severity across the five lenses. Each row links the
issue to where it is fully discussed.

1. **No lint / format / type / test infrastructure anywhere.**
   No `package.json`, `eslint`, `prettier`, `tsconfig`, `jsconfig.json`,
   `.editorconfig`, no `tests/`, no CI. With 50 modules / ~24 k LOC / 1 154
   top-level function declarations, the build's only safety net is
   `node --check`. Discussed: §A (H3, H4), §D (H7, M2, L4).
   *Fix:* drop a minimal `package.json` + ESLint flat config + JSDoc-with-
   `// @ts-check` (replaces the missing types) + a smoke-test page that
   flips `__grepbotTestMode = true`.
2. **No `@updateURL` / `@downloadURL` / `@icon`.** `src/header.js:2-20`
   declares everything except the four URLs that make Tampermonkey
   auto-update. The version-bump gate in `build.py:469-489` is only
   enforced locally. Discussed: §E (H1).
   *Fix:* add the four URLs (one PR).
3. **`bindConfig` is an 829-line monolith (`src/ui.js:1743`) and its
   rebind path silently goes stale.** The function attaches ~120 listeners
   on first call and then short-circuits via `configBound = true`; presets,
   undo/redo, snapshot restore, and tab-switch ALL hit the short-circuit and
   leave inputs showing stale values. Discussed: §A (H1), §B (H1, M1).
   *Fix:* split into `bindConfigAttach` (listener install) +
   `bindConfigSync` (state → DOM), and call `bindConfigSync` unconditionally
   on every invocation. Cache the `[data-cfg]` lookup table once.
4. **`WORLD_SCOPED_BASES` covers 111/225 STORE keys — the other 114 leak
   across worlds.** Most `AUTO_*` feature flags and world-pace tunables
   (`FARM_MIN`, `TOWN_MIN`, `IB_FREE_THRESH`, `CAVE_THRESH`, …) are shared
   between worlds on the same browser. Discussed: §C (H1), §D (M3), §E (M5).
   *Fix:* invert the gate — keep a small `CROSS_WORLD_KEYS` set for the
   keys that genuinely belong to the user (theme, keybindings, panel geom,
   notify, webhook) and default everything else to `wkey()`-scoped.
5. **`preflightRun` is 563 lines of 30 probes (`src/stats.js:155`).**
   `bindConfig` and 17 other functions are > 100 lines. Discussed: §A
   (H2, M1).
   *Fix:* convert the probes to a `PROBES = { name: () => ({ ok, warn?, detail }) }`
   table; extract the same `bail → pick → run → log` shape from each `*Scan`
   runner.
6. **No source maps / no path from installed exception to `src/file:line`.**
   `build.py:320` strips comments and `build.py:331` squeezes whitespace; the
   artifact is `\uXXXX`-escaped. Discussed: §D (H2).
   *Fix:* ship a `dist/grepbot.dev.js` *un-stripped* build for dev install
   only (TM has no `@sourcemap`, but un-stripped comments preserve grep
   locality of error sites).
7. **`src/native-ui.js` is hand-minified source (1124 lines, avg 72 chars/line,
   72 single-letter locals).** The `--prod` whitespace pass already exists
   in `build.py:331` — it belongs at author time, not at install time.
   Discussed: §A (H5), §B (H4).
   *Fix:* re-format `native-ui.js` to readable 4-space style and let
   `compact_whitespace` do the source-size work.
8. **`bindConfig` makes 131 `sec.querySelector` lookups per invocation
   (`src/ui.js:1743-2700`).** `updateStatus` reads ~7 `Object.values(state.*)`
   every 5 s. `Object.keys(state.towns)` is rebuilt per queue-center paint.
   Discussed: §B (M1, M2, M8).
   *Fix:* cache `Map<key, element>` on first bind; cache town-id list
   keyed by a small signature; compute `_statusLast` once and short-
   circuit identical updates.
9. **Silent errors are the norm: ~688 `try { … } catch (_) {}` blocks,
   almost all swallowing.** A swallowed exception is invisible unless the
   caller explicitly logs. Discussed: §A (M2, L1), §C (M5).
   *Fix:* one helper `gbSafe(fn, fallback, logKey)` that calls `gbLogT` on
   the throw and returns the fallback. Every silent catch becomes
   greppable and count-able.
10. **`navigator.locks` leader election is acquired but never used for
    coordination** (`src/core.js:11,61`). Every tab still runs every tick
    independently. Discussed: §C (H2), §E (H3).
    *Fix:* either gate the high-stakes writers (`txRun`, `nativeQueueSweep`,
    `bandit`) on `gbTabLeader`, **or** delete the lock plumbing entirely.
    Half-implemented coordination is worse than none.

Additional items that should be done *in this audit's wake*:

## Per-lens findings

### A — Code Quality & Best Practices

#### A. Executive summary

- **Massive hand-rolled IIFE.** 50 files / ~25.8 k LOC collapsed into one
  ~1.12 MB `grepbot.user.js` (prod: 0.99 MB). 1 155 function declarations,
  306 `const`-prefixed constants, ~688 `try`/`catch` blocks, ~25 k LOC of
  actual code (only ~9.7 % is comments). The codebase has clearly invested
  years of design — there is a real `gb*` (121 helpers) + `GB_*` (15
  constants) namespace, a storage helper, an instance ID for hot-reload
  safety, a lock primitive, and a deliberate `build.py` with duplicate-
  decl gates and `node --check`. The bones are good.
- **Tooling is missing entirely.** No `package.json`, no `eslint`/
  `prettier`/`tsconfig`, no `tests/`, no JSDoc, no `npm`-style dev loop.
  The only safety net is `build.py` — `node --check` (gated behind
  `shutil.which('node')`), the `DECL_RE` duplicate scan, the `version_gate`,
  and the `compact_whitespace` step. That is an unusual amount of
  discipline for a userscript repo but it covers only the compile/structure
  layer; nothing covers style, naming, or correctness.
- **Several functions are pathological.** `bindConfig` in `src/ui.js:1743`
  is **829 lines** (single-handedly ~26 % of `ui.js`), `preflightRun` in
  `src/stats.js:155` is **563 lines**, `migrateConfig` in `src/core.js:593`
  is 165, `renderAttack` is 188, and 19 functions overall exceed 100
  lines. Most are "scan"-shaped runners that mix bail-gate checks, score/
  candidate-building, locking, and posting — each could be a 30-line
  orchestrator + 4 helpers.
- **Style is wildly inconsistent across modules.** `core.js`/`ui.js`/
  `queue-center.js` are readable 4-space indent with English-style names.
  `native-ui.js` is **hand-minified** (no spaces around operators,
  single-letter vars `q/t/d/j`, max line 1 632 chars). That is a deliberate
  source-size minimization at the cost of every contributor who ever has
  to read it.
- **Silent error handling is the norm, not the exception.** 688 `try { }`
  and 689 `catch (` blocks; the most common pattern is
  `try { GM_setValue(...) } catch (_) {}` or
  `try { updateStatus() } catch (_) {}`. The catch-all `catch (_) {}`
  swallows everything (missing `gbLogT` call, no error counter), so
  failures are observable only through `gbLog` paths that already exist.
  There is no structured error policy, no `ErrorBoundary`-style aggregator.

#### A. HIGH severity

**H1. `bindConfig` is a 829-line monolith in `src/ui.js:1743`.** This
single function is roughly one quarter of `ui.js`'s line count, and `ui.js`
is itself 3 207 lines (~12 % of the codebase). It has two distinct modes —
an "already-bound" repaint branch (`src/ui.js:1750-1801`, ~50 lines) and
the initial bind path (`src/ui.js:1803-2571+`). Both modes touch the same
~60 inputs and the same `addEventListener` wiring. Reading either mode
requires holding the other's structure in your head. Extract: one
`bindConfigSyncInputs(sec)` for the repaint path, one
`bindConfigAttachListeners(sec)` for the bind path, and a small
`data-cfg` → `{ load, save }` table that drives both. The 60-input volume
itself is the real design smell: the Config tab is the public face of 225
GM keys (`src/header.js:25-251`) and most of them are present-tense
scalars that could be table-driven rather than per-input hand-written.

**H2. `preflightRun` is 563 lines in `src/stats.js:155`.** A single
function that runs ~30 health probes (`out.push(preflightProbe('bridge', …))`,
…). Each probe is two-three lines and could be one entry in a
`PROBES = { name: () => ({ ok, warn?, detail }) }` table. The "what is being
checked" intent is currently lost in the noise of the function body.

**H3. No JS tooling at all.** `grep -E 'eslint|prettier|tsc|@ts-'`
across `src/`: 0 matches. No `package.json`, no `.eslintrc*`, no
`jsconfig.json`, no `.editorconfig`. With 50 modules and ~1 155 function
declarations, the codebase needs at minimum:
- `eslint` with `eslint:recommended` plus `no-empty` (the silent
  `catch (_) {}` is everywhere), `eqeqeq` with `null` smart exception,
  `no-unused-vars`, `no-magic-numbers` for the 100+ magic literals.
- `prettier` to lock down `native-ui.js`-style drift.
- Either JSDoc typedefs or a small `tsconfig.json` with `// @ts-check`
  for the 1 472 `state.*` accesses alone.

The repo's own `src/qol.js` style would benefit hugely even from a 5-line
`.editorconfig` (line width, indent, quote style).

**H4. No tests.** `Glob '**/test*/**'`: 0 matches. `src/__pycache__`
exists (`build.cpython-314.pyc`) and `archive/src-1.6.9/` has a complete
older copy of the source, but nothing exercises `bridge.js`'s
`gbAjaxFpNorm`, `gbXhr`'s captcha detection (`responseIsCaptcha` in
`src/core.js:1719`), the planner (`src/planner.js`), the tx state machine
(`src/tx.js:706`), or any of the 19 `*Scan()` runners. The test-mode
surface `GB_ROOT.__grepbotTest = { … }` in `src/boot.js:160-286` is a
deliberate public API for tests but there are no tests that use it. With
a quarter-million tokens of behavior in 25 k LOC, that is a structural
gap.

**H5. `src/native-ui.js` is hand-minified source.** Stats: avg 72 chars/
line, max line 1 632 chars, 113 lines that begin with `[{(,;`, 72 single-
letter `const`/`let` declarations. Sample: `src/native-ui.js:22` — a
single 6-line block of nested `for`/`if`/save. This file is 1 124 lines
and 21 % comments (high ratio because the inline comments compensate for
the unreadable code). The `--prod` build step in `build.py:331` already
strips leading whitespace and blank lines and saves 11.3 % — that work
belongs there, not at author time. The author-time version should be a
normal, readable file.

**H6. `panel` is an implicit global closure variable in `src/core.js:578`,
written from `src/ui.js:794` and read from 60+ sites in `src/ui.js`.**
Mutation of a closure-scoped `let` from a different module is a code smell
that becomes a real problem if any module ever moves out of order (the
whole `MODULES = [...]` ordering in `build.py:31` exists to keep these
ordering dependencies intact). A `gbPanel` accessor or `getPanel()` factory
would let `ui.js` know whether the panel exists without depending on a
literal declaration site.

The scan-shaped runners (`*Scan(reason)`) are the pattern: they own bail-
gate checks, candidate construction, lock acquisition, post execution, and
logging. Each could be split into `checkX()` + `pickX()` + `runX()` +
`logX()`.

**M2. 688 `try { }` blocks, almost all swallow.** Per-file counts:
`core.js:73`, `ui.js:41`, `bridge.js:31`, `farms.js:29`, `boot.js:28`,
`tx.js:28`, `research.js:27`, `qol.js:34`, `intel.js:23`, `stats.js:21`,
`spy.js:20`. The dominant shape is
`try { /* read world state */ } catch (_) { return defaultValue }` or
`try { updateStatus() } catch (_) {}`. The repo's own comment at
`src/core.js:1283` (and many similar) explains *why* the swallow is
intentional ("unsafeWindow may be missing on a wrong page"). The fix is
not "stop catching" — it is a single helper `gbSafe(fn, fallback)` that
logs at `gbLogT` and returns the fallback, so every silent catch becomes
greppable and count-able. As-is, a swallowed exception is invisible
unless the calling code explicitly logs.

**M3. Magic numbers dominate `boot.js`'s scheduling.** `grep -cE '\b60000\b'`
across `src/`: **229 occurrences**; `\b30000\b`: **141**; `\b1000\b`:
**149**; `\b5000\b`: **55**. Many are real cadences (the
`gbInterval(..., 15000)` loop in `src/boot.js:45` etc.) and they are not
centralized. `src/boot.js:37-141` schedules roughly 18 timers using
literals like `1000, 5000, 10000, 14000, 15000, 30000`. `src/core.js:243-276`
does the same with lock TTLs in a table (`GB_LOCK_TTL`), but `boot.js`
does not. A single `const GB_CADENCE = { farmTick: 15000, renderTimers: 1000, … }`
would let `qol.js`'s config UI surface them as sliders.

**M4. 225 GM storage keys (`src/header.js:24-251`), 111 in the
`WORLD_SCOPED_BASES` set (`src/header.js:258-281`).** No
`src/storage-keys.js` table; the keys are spelled out as
`'grepbot:findings'` strings inside a hand-edited 200-line object. Adding
a new key means editing `STORE`, `WORLD_SCOPED_BASES`, and
`state = { … }` (`src/core.js:322-576`) in three places. The naming
convention is consistent (`grepbot:<feature>[-<sub>]`), but the discovery
problem ("what keys exist, who uses which?") is solved only by `grep`.

**M5. Inline DOM-string concatenation is still present.** Four
`innerHTML =` sites:
- `src/ui.js:802` — entire 491-line panel HTML chunk (the only one with
  any user data in it; `runningVersion()` is interpolated, which is fine).
- `src/queue-center.js:618` — full QC chrome.
- `src/ui.js:2706` — `<input …>` rows with a single `attacker filter`
  placeholder. No user data interpolated.
- `src/attack.js:798` — `<span>town</span>…`. Pure static.

None of the four is currently an XSS sink, but `src/queue-center.js:618`
and `src/ui.js:802` are big enough that any future interpolation is one
PR away from injection. `src/ui.js:802` uses `runningVersion()`
interpolation, which is a controlled value — fine, but a brittle pattern.

**M6. `core.js` state initialization is a 250-line literal object
(`src/core.js:322-576`).** 200+ `state.X = load(STORE.X, default)` lines,
mostly the same shape. The defaults are scattered between
`src/header.js`, `src/core.js`, and the `STORE` keys. The
`src/core.js:524` `plannerCfg` default is a 7-line inline object; many
others are 1-3 line nested literals. A `STATE_DEFAULTS = { … }` table
next to `STORE` would let `loadOr(key, default)` collapse into one line
per key.

**M7. Only 3 `async/await` usages total (`grep -c 'async function'`).**
The codebase uses a strict callback (`onDone`) convention everywhere —
including `src/bridge.js:61 bridgeRaw()`, `src/core.js:1558 gbXhr()`,
`src/stats.js:165 detail`, and ~30 other sites. That is consistent and
intentional, but it leaves modern error-propagation patterns (try/catch
around awaits, AbortController) unused. `gbXhr`'s `onerror` callback
pattern at `src/core.js:1599-1610` has to forward three different shapes
(`{ error: 'captcha' }`, the raw XHR error, the timeout) — an
`AbortSignal`-aware Promise wrapper would unify them and let the 30+
`gbXhr({ onload, onerror, ontimeout, onabort })` callsites collapse to
`.then().catch()`.

**M8. `compact_whitespace` saves 11.3 % (`build.py:331`, prod is 1.04 MB
vs dev 1.17 MB).** The comment at `build.py:332-341` justifies avoiding
a real minifier, which is reasonable for a paste-only userscript. But
the saving is small relative to the cost (the function is 50 lines of
`out.push(line)` logic and it runs on every prod build). The single
biggest size lever is `src/native-ui.js` becoming a normal file (see
H5) — a minified-source file compresses badly because its long
identifier names were already compressed.

**M9. `async`/`await` count is 3, but `native-ui.js:22`
`nativeQueueRoot()` embeds a triple-nested `for`/`for`/`for` with side-
effects** (`save(STORE.NATIVE_QUEUE, q)` inside the loop, calling itself
recursively). That 1-line expression is the most expensive single
instruction in the file by far — both runtime and reading cost. Compare
to `src/ui.js:2718 renderFindings()` which builds the same data without
nesting.

**M10. The IIFE-bound `state` object has 1 472+ accesses across the
codebase (`grep -cE 'state\.[a-zA-Z]+'`).** Without JSDoc/typedefs, every
read site has to look up the actual shape. A single `STATE_SCHEMA`
typedef would let `// @ts-check` (or a single JSDoc pass) catch
`state.autoDOdge` typos. (`grep` finds `autoDodge` referenced 3 times —
`src/core.js:475` is the canonical key, `src/dodge.js:415,466` are
readers — but there is no compile-time guarantee `state.autoDodge` and
`STORE.AUTO_DODGE` agree on case.)

#### A. LOW severity

**L1. `catch (_) {}` is the universal swallow pattern (see M2).** Even
when the catch *does* log (`src/boot.js:46 try { … gbLog('interval error', String(e)) } catch (_) {}`), the inner `try/catch (_) {}` around the log line itself means a logging failure is doubly silent.

**L2. `src/footer.js` is exactly `})();` (1 line, 6 bytes).** The IIFE
is opened by `header.js` and closed by `footer.js`. This is structurally
fine but slightly surprising — a casual reader expects a footer to be a
"footer" of content. A 1-line module dedicated to closing a paren invites
accidental editing.

**L3. `src/ui.js:3120`, `src/stats.js:990`, `src/stats.js:1066`,
`src/towns.js:75`, `src/core.js:1229,1452,1537,1543` use `console.log/info/
warn` directly** instead of `gbLog`. `core.js:1219` *is* `gbLog` (which
calls `console.info('[grepbot]', …args)`), so the two paths coexist. The
inconsistency is minor but means `qolExportConfig` (`src/qol.js`) can
dump logs the user can't filter through the panel.

**L4. Loose `==`/`!=` totals 347/489 vs strict 2 111/482 (`==`/`!=` is
acceptable when paired with `null`/`undefined`).** The ratio is roughly
right; offenders are concentrated in `src/bridge.js` (21 loose `==`) and
`src/core.js` (15). An `eslint` with `eqeqeq: ['error', 'null']` would
normalize this.

**L5. Module ordering is load-bearing but undocumented.** `src/recruit.js:1-3`
and `src/favor.js:1-3` both contain `// Declared with their only consumer.
These used to sit at the tail of dodge.js, so recruit.js silently depended
on dodge.js being concatenated first — a build-order footgun with no
compile-time signal.` This is exactly the kind of bug that `build.py`'s
`DECL_RE` check (`build.py:86-95`) is supposed to catch — but it only
catches duplicate top-level *declarations*, not cross-module *call-before-
define* ordering. A `--hoist` step that records each module's first
symbol-use and refuses to concat when symbol ordering fails would close
the gap.

**L6. IIFE-strict mode is set (`src/header.js:23`) but there are no
module-level checks for `typeof unsafeWindow !== 'undefined'` beyond the
`GB_ROOT` block (`src/core.js:3`) and a few `try { gameUw().ITowns… } catch
(_)` sites.** A single `gbGetUnsafe()` helper that returns a sane fallback
would replace ~30 inline typeof checks (`src/tx.js:18`, `src/bridge.js:30`,
`src/core.js:1322,1349,1387,1394,1529` …).

**L7. `src/boot.js:159-286` exposes a 130-line test-mode export object
that is gated on `GB_ROOT.__grepbotTestMode === true`.** That's an
excellent API design, but the names are duplicated from the live function
names (`txRun`, `txIntent`, `txCapture`, `txClearUnknown`, `circuitOpen`,
`circuitClear`, `gbLock`, `gbUnlock`, `gbLocked`, `gbLockTouch`,
`planner`, … ~140 exports). Without a build-time check, it is easy for
the export list to silently drift out of sync with the actual
definitions. A `Object.keys(GB_ROOT.__grepbotTest)` versus a
`grep '^  function '` check would catch drift.

**L8. Comment ratio is 9.7 % overall but very uneven.** `god-spells.js`
is 25 %, `core.js` 12 %, `tx.js` 4 % (`grep -cE '^\s*//'`). Several
modules are under 5 % — `journal.js`, `dump.js`, `favor.js` — and their
key functions have only inline single-line comments. The repo's actual

### B — Performance & Efficiency

#### B. Executive summary

- **The repaint primitive is solid and pervasive.** `gbPaint` /
  `gbPaintPatch` (`src/core.js:92`/`src/core.js:122`) is the right fix
  for the "dead UI under cursor" problem the recent commits landed, and
  `queue-center.js` shows the right consumption pattern (keyed patch +
  1 s ticker that only touches `data-eta` text nodes —
  `src/queue-center.js:587`).
- **A timer-storm at boot is now structurally well-gated.** `gbWakeDrain`
  (`src/core.js:924`) serializes bfcache/visibility bursts with a
  configurable spacing (`WAKE_SPACING_MS = 800`), so the 12 intervals
  kicked off in `boot.js:45-135` no longer stampede the server on wake.
  Combined with `reqBudgetOk` (`src/core.js:893`) and `REQ_SCOPE_FRACTION`
  (`src/core.js:887`), this is a well-engineered admission control layer.
- **Selector density is the single highest-frequency perf cost.** `src/ui.js`
  alone has 247 `querySelector*` calls and 110 `panel.querySelector(...)`
  calls — `bindConfig` alone (`:1743-2700`) does 131 `querySelector`
  lookups every time it's invoked.
- **Listener bookkeeping is mostly correct** (`gbListenerBag` + `gbDispose`
  at `src/core.js:216-219`), but the body-level `MutationObserver` in
  `src/collect.js:184` (re-armed on every SPA nav by `ensurePanelGeom` →
  `ensureDomObserver`) observes the *entire* document subtree and feeds
  auto-collect/bandit/native-ui rescans from any body append — the
  `ownOnly` filter (`src/collect.js:201`) is a sound guard, but the
  underlying cost is unavoidable on every nav.

#### B. HIGH severity

**H1. `bindConfig` rebind path is silently broken → user-visible stale
state.** `src/ui.js:1743-1802` (especially `:1750` / `:1803`).

`bindConfig` runs ~50 `sec.querySelector('[data-cfg=...]')` lookups and
writes `checked`/`value` on the *first* call only, then sets
`configBound = true`. Every later call (every tab switch to Config —
`:448`, `:461`; every preset apply — `:2681`; every undo/redo —
`:1431`/`:1435`; every wizard import — `:1421`; every snapshot restore —
`:2444`) takes the `if (configBound)` branch and `return`s at `:1801`.
The `setNum`/`setChk` block at `:1750-1800` *does* re-sync values, but
only for a subset, and any element touched by `saveNum`/inline
`addEventListener` further down (`:2232-2359`) is left alone.

**Impact:** switching tabs and back to Config (or applying a preset)
does NOT update every checkbox/select from `state.*`. The user sees stale
controls, then a click writes the stale value back. For 26 distinct
`GM_*`-backed config keys this is the most likely cause of "I clicked it
but the setting didn't change" reports.

**Fix:** when `configBound`, walk *every* `[data-cfg]` control with the
same `setChk`/`setNum`/select-sync logic and `return`. Make the rebind
branch a clone of the bind branch's value-sync portion — drop the
listener-install portion.

**H2. ~12 timed loops at boot with no idle adaptation beyond "double the
interval".** `src/boot.js:37-135` (12+ intervals), `src/orchestrate.js:155`
(`orchTick`), `src/farms.js:1217` (`farmTick`).

`gbInterval(scrapeInboxDom, 30000)`, `farmTick` (15 s), `checkThresholds`
(30 s), `renderTimers` (1 s), `updateStatus` (5 s), `renderTownSwitch`
(5 s), `caveTownsTick` (10 s), `questScanTick` (`QUEST_SCAN_MS`),
`ibScan` (`IB_CHECK_MS`), `dodgeScan` (`DODGE_CHECK_MS`),
`dodgeReturnTick` (15 s), `orchTick` (`ORCH_MS`), `nativeUiScan` (5 s),
`nativeQueueSweep` (60 s). Each runs forever even when the relevant
feature is OFF in config (e.g. `auto-farm=false` still ticks `farmTick`,
just bailing fast).

**Impact:** with 12+ loops each holding a JS closure + GC-rooted callback
in `gbTimerBag` (`src/core.js:16`), a hidden/background tab still does
~12 `Date.now()` calls + state reads per second. The `orchAdaptive` flag
exists (`:505`, documented at `src/ui.js:1101`) but only "doubles its
interval up to 8x" — it never stops.

**Fix:** the only timer that should run unconditionally is `renderTimers`
(1 s — UI clock) and `updateStatus` (5 s — status pill). Everything else
should be gated on its `state.auto*` flag and started on `state` change,
not on boot.

**H3. Body-level `MutationObserver` on the whole document.** `src/collect.js:184-230`
(re-armed on every SPA nav by `ensurePanelMounted` → `ensureDomObserver`
in `src/boot.js:7`).

Observes `document.body` with `childList:true, subtree:true,
attributes:true` and a nine-element `attributeFilter`. Any record that
touches a non-own node schedules `autoCollectResources` +
`scheduleBanditScan` + `scheduleNativeUiScan`. The `ownOnly` filter
(`src/collect.js:201`) is correct, but: (a) every SPA nav tears it down
and re-creates it via `gbDomObserver.disconnect()` (`src/collect.js:225`),
(b) the re-attach cost itself is non-trivial on a deep subtree, (c) the
observer's `records` array is rebuilt for *every* mutation even when
nothing relevant moved.

**Impact:** any time the game opens/closes a window or updates a unit
count, all three scans are *scheduled* — the `schedule*` timers debounce
to 800 ms / 1.2 s / 5 s, but the body-walk on each schedule is
unavoidable. Grepolis opens dialogs constantly.

**Fix:** narrow the target to `.window_content` + `#ui_box` (the
`if (!targets.length)` fallback at `src/collect.js:216` already mentions
`#ui_box`). Body-level is justified by WindowsView's `el:"body"`
parentage (`src/collect.js:209-213`), but a `MutationObserver` scoped to
a stable set of `#grepbot-panel`-sibling roots avoids the body's
`grepbot-` subtree walk on every record.

**H4. The 1.17 MB artifact ships a 250 KB theme CSS block that's
duplicated for dark + light.** `src/ui.js:468-1293` (~825 lines of CSS
inside `GM_addStyle`), `src/queue-center.js:51` (queue-center CSS),
`src/native-ui.js:748` (native-ui CSS).

`grepbot.user.js` is 1 174 KB; `grepbot.user.js.prod` is 1 042 KB. The
`.gb-theme-dark` block (`:532-586`) is an EXACT copy of the default
`:root` block (`:478-531`) — 54 lines of `--gb-bg:#181a1f…` repeated
verbatim because the comment at `:470-476` says "explicit anchor for
the system resolver." `compact_whitespace` in `build.py:331-358` strips
blank lines and indentation but not duplication, and `--prod` is what
gets pasted to Tampermonkey for ~all installs.

**Impact:** every install pays 54 lines of identical CSS parsing and one
extra `<style>` tag worth of memory. On mobile devices (the user runs
GrepBot from mobile per the I18N locales) the parse cost on
`GM_addStyle` injection is non-trivial.

**Fix:** delete the `.gb-theme-dark` rule entirely. `applyTheme`
(`src/ui.js:411`) always adds `gb-theme-dark` or `gb-theme-light`, so a
default `:root` rule with the dark values plus the `.gb-theme-light`
override is sufficient. Saves ~2 KB pre-minify and one full CSS pass.

#### B. MEDIUM severity

**M1. `bindConfig` makes 131 `querySelector` calls per invocation.**
`src/ui.js:1743-2700`.

131 calls to `sec.querySelector(...)`. Every checkbox sync + every
listener install is one selector walk through the config subtree (~200+
`[data-cfg]` controls, see `src/ui.js:991-1232`). `setChk`/`setNum`
(`:1806-1809`) repeat the same pattern via `sec.querySelector`. With no
caching, every config-tab render is ~131 DOM-tree walks.

**Impact:** the first `bindConfig` after a `GM_setValue` (e.g. after
undo/redo/snapshot restore) takes 131 tree walks; on a slow laptop with
the panel mounted under heavy game DOM, this is ~5-15 ms.

**Fix:** cache `sec._gbCfgEls = {}` (or a `Map`) on first call:
`els[k] = els[k] || sec.querySelector('[data-cfg=' + k + ']')`. Or build
a flat dictionary at the end of `bindConfig`'s bind branch and reuse it
on rebind.

**M2. `state` is one giant object read on every `updateStatus` /
`renderTimers` tick.** `src/core.js:322-566`, `src/ui.js:2973`
(`updateStatus` — runs every 5 s), `src/ui.js:3034` (`renderTimers` —
runs every 1 s).

`updateStatus` walks `Object.values(state.townResources)`,
`Object.values(state.captchaBreakers)`, `Object.keys(state.circuits)`,
`Object.values(state.txState)`, `Object.values(state.farmResources)`,
`state.towns`, `state.farmsParsed`, `Object.values(state.alerted)`,
`Object.values(state.health)` — every 5 s. `renderTimers` runs every
1 s and re-renders the next-farm/town countdowns. With a 100-town
account, each `updateStatus` does ~600 key reads and ~7 `Object.values`
allocations.

**Impact:** minor by itself, but `updateStatus` is also called from
`gbWakeDrain` (after every wake-burst item), `captchaTrip` (after every
captcha), `gbPanicActivate`, `gbPanicRecover`, and `bumpUserActivity` —
so the per-event cost is on top of the 5 s cadence.

**Fix:** compute `updateStatus`'s text once into a module-level
`_statusLast` (already partially done with `_statusLast` at `:2970`,
but the diffing is only for the *output*, not for the *inputs* — every
read still happens). Short-circuit if `automationPaused(pauseInfo)` and
`_statusLast` haven't changed.

**M3. `_mmColCache` and `gameUw` cache TTL of 400 ms but unbounded
keys.** `src/core.js:1332-1340` (`uwCached`, 400 ms TTL),
`:1341-1361` (`mmCol`).

`_mmColCache = Object.create(null)` is cleared every 400 ms by `mmCol`
itself (`:1346`), but the keys accumulate between clears — calling
`mmCol('Town')` then `mmCol('FarmTown')` then `mmCol('PlayerAttackSpot')`
between flushes leaves three entries. Not a leak per se, but `uwCached`
returns the same `uw` for 400 ms which means a stale snapshot of game
data for that window — and `txRecent` checks (`src/tx.js`) read the
cached collection.

**Impact:** `mmCol` is called from many hot paths (`queue-center.js`,
`native-ui.js`, `intel.js`). 400 ms is short enough to miss a real
mutation, but long enough that two rapid `nativeQueueAddBuild` calls
read the same stale snapshot.

**Fix:** drop the cache to 0 ms (`UW_CACHE_MS = 0`) or remove it
entirely — `gameUw()` itself is cheap (two `try { unsafeWindow }`
blocks). The cost of caching is that callers may operate on stale
models; the cost of not caching is two `typeof` checks per call.

**M4. `seen` map can grow to 2000 entries and prune-on-overflow sorts
the whole keyset.** `src/core.js:1275-1294` (`rememberSeen`).

```js
const keys = Object.keys(state.seen);
keys.sort((a, b) => state.seen[a] - state.seen[b]);
const drop = keys.length - SEEN_MAX;
for (let i = 0; i < drop; i++) delete state.seen[keys[i]];
```

Every time `seenCount > 2000`, full `Object.keys` + `sort` + 2 000
deletions. `state.seen` is then `save()`d via `STORE.SEEN`. The sort is
O(n log n) on 2 000 keys — small — but `Object.keys` allocates a new
array each call, and `delete` on a plain object deoptimises its hidden
class (V8). This happens whenever a new id pushes `seenCount` over the
cap, which is exactly when the system is already under load.

**Fix:** keep `seen` as a `Map` (preserves insertion order, faster
deletion, no hidden-class deopt). Or maintain a sorted insertion order
via two small structures. Or use an LRU keyed by `Map` iteration.

**M5. `GM_setValue` writes do not debounce.** `src/core.js:1508-1536`
(`save`), called from 100+ sites.

Every `save(STORE.XXX, value)` immediately calls `GM_setValue`. There's
no write coalescing — toggling 10 checkboxes in quick succession on the
Config tab produces 10 synchronous `GM_setValue` round-trips. The
`healthSaveSoon` function (`src/core.js:750`) is the one place that
debounces — but only for module-health updates.

**Impact:** the `bindConfig` rebind path + the `saveNum` chain
(`src/ui.js:2239-2341`) fires 26 saves in a row when the user clicks
26 checkboxes quickly. Tampermonkey in Chromium batches these into one
IDB transaction, but Violentmonkey / Firefox variants don't.

**Fix:** a `saveSoon(key, val)` microtask-debounced wrapper that
flushes once per animation frame. `state[key]` reads always return
the live in-memory value; only the persistence is debounced.

**M6. `panel.innerHTML = …` at boot parses ~500 lines of HTML in one
shot.** `src/ui.js:802`, `:618` (queue-center), `:2706` (findings filter).

The first three uses are unavoidable: they define the panel/QC chrome.
But the `panel.innerHTML = …` at `:802` is **491 lines** of HTML
(`:803-1293`) and is parsed by the browser on every boot.
`compact_whitespace` (`build.py:331`) collapses leading whitespace, but
the actual HTML structure is unchanged. `GM_addStyle` for the panel CSS
at `:468-1293` is another 825 lines parsed on every boot.

**Impact:** measurable first-paint delay on lower-end devices. Mobile +
Firefox feels the most.

**Fix:** the panel HTML could be split: chrome (`<header>`, `<nav>`,
`<section data-tab=findings>`) built with `createElement`/`textContent`,
and only the config-tab HTML (which is the big one) stays as a template
literal. The cost is the same at runtime but the work is interleaved
with browser layout instead of blocking it.

**M7. `logThrottle` pruning does an O(n) walk and re-prunes only on
overflow.** `src/core.js:1240-1259` (`gbLogT`).

```js
if (logThrottle.size > LOG_THROTTLE_MAX) {
  const cutoff = now - 60000;
  for (const [k, ts] of logThrottle) {
    if (ts < cutoff) logThrottle.delete(k);
  }
  if (logThrottle.size > LOG_THROTTLE_MAX) {
    let n = logThrottle.size >> 1;
    for (const k of logThrottle.keys()) { if (n-- <= 0) break; logThrottle.delete(k); }
  }
}
```

Only runs when size > 200. Until then, every key accumulates
indefinitely. With `gbLogT` called from `captchaTrip`, `csrfLoop`,
`farmTick`, `questScanTick` etc., `logThrottle` grows to 200 in roughly
200 distinct events (~minutes of active automation), then stays there
until the periodic `gbLogT` call hits the > 200 check. The pruning walk
itself is fast, but the *steady-state* 200-entry map holds every
distinct `key` for the lifetime of the script.

**Impact:** negligible memory (~5 KB), but the pruning on overflow also
deletes the *wrong* half: half the keys by iteration order, not by
timestamp. An "unused for 60s" key survives alongside a "just inserted"
one.

**Fix:** use a doubly-linked structure or an LRU `Map` so old entries
fall off naturally without a sort or full scan.

**M8. `Object.keys(state.towns)` rebuilt on every `queueCenterTownIds`
call.** `src/queue-center.js:84`, called from `queueCenterPaint`
(`:535`).

Every paint of the queue center calls
`Object.keys((gameUw().ITowns && gameUw().ITowns.towns) || {})` — even
though the town list only changes on `fetchOwnedTowns`. The fallback
`state.towns.map(t => String(t.id))` allocates a new array per call.
With 50+ towns and 50+ paints per minute, this is ~50 `Object.keys`
walks and 50 array allocations per minute.

**Fix:** cache the id list keyed by a signature
`Object.keys(towns).length + ':' + lastFetchAt`; recompute only when
the signature changes.

**M9. `_gbQcReconciledAt`/`gbQcReconciledAt` and the 2 s reconcile
throttle.** `src/queue-center.js:482-498`, `:550`.

Every background paint triggers `nativeQueueReconcileTown
(gbQueueCenterTown)` (`:552`) if it's been > 2 s. The reconcile is
described in the comment as "the expensive half of a paint" (`:548`).
This runs even when the user has zero automation enabled.

**Fix:** only reconcile when `state.autoBuild` or `state.autoQueue` is
on AND the queue has work.

### C — Robustness & Safety

#### C. Executive summary

- **Disposal story is solid and unusual for a userscript of this size.**
  `core.js:206–241` (`__grepbotDispose`) walks five bags (timers, XHRs,
  listeners, menus, DOM observers) plus hooks (`fetch`,
  `XMLHttpRequest.prototype`, `pushState`/`replaceState`) and is invoked
  on the *next* script run via `core.js:4–6` — a hot-reload from
  devtools or a TM version bump disposes the prior instance before
  re-entry.
- **The biggest real finding: `WORLD_SCOPED_BASES` is the only thing
  preventing GM_setValue entries from one Grepolis world bleeding into
  another, and it covers fewer than half the keys.** Of **225 declared
  STORE keys**, only **111** are listed in the world-scope Set. The 114
  un-scoped keys (most of the `AUTO_*` feature flags and the numeric
  tunables like `TOWN_MIN`, `TOWN_MAX`, `FARM_MIN`, `IB_FREE_THRESH`,
  `REQ_BUDGET`, etc.) are written through the un-namespaced path and
  shared between worlds on the same browser.
- **XSS surface is genuinely tiny.** Only four `innerHTML=` sites in
  the entire repo (`src/ui.js:802`, `src/ui.js:2706`,
  `src/queue-center.js:618`, `src/attack.js:798`); all four are hardcoded
  literal HTML strings with no template interpolation. All other DOM
  construction uses `textContent`, `createElement`, and `replaceChildren`.
  `GM_addStyle` calls (`src/ui.js:468`, `src/native-ui.js:748`,
  `src/queue-center.js:51`) are likewise pure literal CSS. No user/
  server string ever lands inside an HTML attribute or style body.
- **Cross-tab coordination via `navigator.locks` is implemented but the
  LOCAL lock bag is per-tab.** A bridge post that races across two
  tabs can hold a "leader" lock in tab A while tab B (also leader,
  briefly) posts the same `model_url|action_name`; the dedup relies on
  the `lastSelfBridge` 10-second fingerprint window
  (`src/bridge.js:131-140`), which is not the same as the lock.
- **Error handling is consistent and thorough.** 428 `try {` blocks
  across the codebase; `gbInterval`/`gbTimeout` wrappers
  (`core.js:23-44`) swallow and log errors with `gbLog`.

#### C. HIGH severity

**H1. `WORLD_SCOPED_BASES` covers only 111 of 225 STORE keys → cross-
world bleed + quota pressure.** `src/header.js:24-252` (STORE),
`src/header.js:258-282` (`WORLD_SCOPED_BASES`), `src/core.js:1410-1430`
(`load`), `src/core.js:1508-1536` (`save`).

The world-scoping check is:

```js
if (!scopedCall && WORLD_SCOPED_BASES.has(key)) {
  const wk = wkey(key);           // 'grepbot:farms@es100.grepolis.com'
  …
} else {
  const v = GM_getValue(key, null); // legacy global
}
```

**Why this matters:**
- A user toggles `autoFarm` on world A, plays world B with

- Many of the tunables are world-specific by design (e.g., `FARM_MIN`,

**Fix shape:** add all world-specific tunables to `WORLD_SCOPED_BASES`.
Even simpler: invert the gate — have a much smaller `CROSS_WORLD_KEYS`
Set containing only those that should NOT be per-host (`THEME`,

**H2. Cross-tab leader election is racy with local lock bag, and the
bridge dedup window is fragile.** `src/core.js:10-11` (`gbTabCoordSupported`,
`gbTabLockName`), `src/core.js:59-63` (`gbTryAcquireTabLeader`),
`src/core.js:243-275` (`GB_LOCK_TTL`), `src/core.js:277, 291-313`
(`gbLocks`), `src/bridge.js:131-140` (`isSelfBridge`).

`gbTabLockName` is `grepbot-leader:<hostname>` — good.
`gbTryAcquireTabLeader` correctly uses `navigator.locks.request(…,
{ mode: 'exclusive', ifAvailable: true })` so it doesn't deadlock. But
the per-feature lock map (`gbLocks[name]`) lives in module scope, NOT in
the `navigator.locks`-managed shared state. Two leader tabs both run
their own `gbLock('claim', ttl)` simultaneously and both succeed.

The bridge layer compensates with `lastSelfBridge`
(`src/bridge.js:164-168`) — a 10-second fingerprint. Mitigated by the
fingerprint string at `src/bridge.js:137` (must match `model_url` +
`action_name` + `arguments` + `town_id`), which is good but not
invincible.

**Fix shape:** move the `gbLocks` map into a
`BroadcastChannel('grepbot-locks')`-backed shared state, or just check
`navigator.locks.request(name, { mode: 'exclusive', ifAvailable: true })`
per feature with a `name` derived from `feature+entity` (e.g.,
`'grepbot:lock:claim:'+townId`).

**H3. `releaseLocks` only fires on `beforeunload`/`pagehide`; hot-reload
during a thrown script depends on `__grepbotDispose`.** `src/boot.js:142-156`
(`releaseLocks`), `src/core.js:4-6` (chain-disposal at script start),
`src/core.js:206-241` (`__grepbotDispose`).

`releaseLocks` is registered for `beforeunload` AND `pagehide` — that
covers normal page exits but not:
- Tampermonkey editing the script in the editor and clicking "Save" —
  the page does NOT unload, the script reloads.
- DevTools "save as" workflow while the page is open.
- A Vite/extension reload that injects a fresh `<script>` without
  firing unload.

In those cases the prior instance disposes only because `core.js:4-6`
runs the chain at the start of the next script run. **This is correct,
but only as long as the next script run gets far enough to execute
`core.js:4`.** If a syntax error in a fresh edit makes the script throw
during `eval`, the prior instance is leaked: timers keep firing, XHRs
keep in-flight, fetch/XHR hooks still wrap the game's `unsafeWindow`.

**Fix shape:** in `releaseLocks` also wire
`setInterval(releaseLocks, 60000)` (or piggyback on `gbInterval` already
running in `boot.js`) so locks are reaped even if a fresh script never
runs. Or: install a `MutationObserver` on `<head>` that watches for
`unsafeWindow` re-injection.

#### C. MEDIUM severity

**M1. `storagePruneForQuota` underestimates bytes and may not free enough
for the worst offenders.** `src/core.js:1454-1507` (`storagePruneForQuota`),
`src/core.js:1508-1536` (`save`).

The quota handler prunes DECISIONS (>50), SEEN (>2000), ALERTED (>3d),
FINDINGS (>100), FARM_RES (>1d), with rough byte estimates (`drop * 80`,
`drop * 24`, `drop * 200`, `drop * 40`). After pruning, it retries the
write once; if it still fails, the write is lost with `'quota FULL'` on
the status pill.

**Two concerns:**
1. The estimates ignore JSON-serialization overhead — `JSON.stringify({ key, ts })`
   is ~58 bytes, not 24. Logs are misleading but not unsafe.
2. Other rings (`tplHealth`, `dodgeReturns`, `snapshots`,
   `profileRings`, `txState`) are NOT pruned on quota. If any of them is
   the offending write, the prune runs against the wrong rings and the
   retry still fails.

**Fix:** add `state.tplHealth`, `state.dodgeReturns`, `state.snapshots`
to the prune set with sane caps. Switch the byte estimate to
`JSON.stringify({...}).length` for honesty.

**M2. (Verified safe.)** `nativeUiTimer`, `collectBgTimer`,
`collectTimer`, `banditTimer`, `gbQcPaintTimer`, `gbQcTickTimer`,
`healthSaveTimer` (`src/collect.js:105, 175`, `src/bandit.js:391`,
`src/native-ui.js:767`, `src/queue-center.js:484, 600`,
`src/core.js:759`) are all `gbTimeout`-registered handles; they ARE
inside `gbTimerBag` and WILL be cleared by `gbClearTimers` at dispose.
The local `let timer = null` mirror variables are just to debounce
re-arming, not for cleanup — the cleanup happens via the bag. ✅

**M3. The body's `MutationObserver` has correct gating but a fragile
allow-list.** `src/collect.js:182-230` (`ensureDomObserver`).

The observer is registered on `document.body` with `childList:true,
subtree:true, attributes:true` and a narrow attribute filter. The
`ownRecord()` helper returns `true` ONLY when every added/removed node
is inside `GB_OWN_SEL = '.gb-native-qctl,.gb-native-panel,.gb-flash,
#grepbot-panel,#grepbot-queue-center'`. **A body-level mutation that
adds ONE GrepBot-owned node and ONE game-owned node at the same time
will be misclassified as game-driven** — harmless but redundant.

The risk is that the `GB_OWN_SEL` list silently drifts: adding a new
top-level GrepBot element without extending the list will turn auto-
collect into a no-op the first time the new node is the only thing in a
record batch.

**Fix shape:** log a one-time warning if a body-level record's
`addedNodes` include at least one non-`GB_OWN_SEL` element AND no game-
relevant class — that's the actual "game updated its DOM" signal.

**M4. Disposal path doesn't await async work; `gbAjaxPending` watchers
can outlive the instance.** `src/core.js:206-241` (`__grepbotDispose`),
`src/bridge.js:30-46` (`gbAjaxWatch`), `src/core.js:164-169` (`gbAbortXhrs`).

`gbAjaxPending` is NOT cleared. If a bridge post is in-flight and its
watcher is in `gbAjaxPending`, the XHR spy (`src/spy.js:74-81`) will
call `settle(status, raw)` after disposal. The bridge's `finish()`
correctly checks `gbInstanceAlive()` (`src/bridge.js:154, 215`) so the
post is dropped, but the entry stays in `gbAjaxPending` until the 8 s
TTL or until it gets evicted by `GB_AJAX_PENDING_MAX`.

**Fix:** add a `gbAjaxPending.length = 0` to `__grepbotDispose`, or
expose `gbAjaxClear()` and call it.

**M5. The 4 `innerHTML=` sites are safe today; the next author who adds
one may not be.** `src/ui.js:802, 2706`, `src/queue-center.js:618`,
`src/attack.js:798`.

All four are pure literal strings. No template interpolation, no
`+ userVariable`, no concatenation. **Safe today.** But there is no
convention / no ESLint rule preventing the next author from
interpolating a player-supplied name into one of these strings. Worth a
one-line comment in each of the four sites saying "literal only — no
interpolation".

### D — Architecture & "Out of the Box"

#### D. Executive summary

- **The whole userscript is one IIFE shared across 50 source files /
  25 768 lines**, with ~1 154 top-level `function` declarations living
  in a flat closure. Every module sees every other module's identifiers,
  so all cross-module calls are free but all cross-module contracts are
  informal.
- **Configuration has decentralised taxonomy but no schema.** ~225
  storage keys, a world-scoping set, a config-export allow-list, 12
  schema migrations, a config-ver stamping system — all maintained by
  hand with no types, no shared validators, and ~28 different "is this
  thing actually an object?" guards scattered across modules.
- **Build pipeline is over-engineered for the constraint it cannot
  relax.** `build.py` runs `node --check`, scans for duplicate top-level
  declarations, strips comments, escapes everything to `\uXXXX` ASCII,
  and verifies the `@version` bump. None of this generates source maps,
  none tree-shakes, and the ~1.2 MB artifact includes modules that
  contain only one or two helpers.
- **There is a clean way out (ESM userscripts) that the codebase could
  reach in stages**, but the chosen structure — a god module per
  concern + one flat closure + ad-hoc globals on `unsafeWindow.*` — is
  currently being held together by handwritten scaffolding
  (`__grepbotDispose`, `__grepbotInstanceId`, `__grepbotTest`,
  `__grepbotPlanner`).
- **No dev affordances whatsoever exist out of the box.** No watcher,
  no `npm run dev`, no source maps, no incremental builds, no
  `eslint`/`.prettier`/`.editorconfig`, no fixtures, no test runner,
  no contract tests.

#### D. HIGH severity

**H1. Single IIFE → no compile-time module isolation or namespacing.**
`src/header.js:22` opens one `(function () { 'use strict';`;
`src/footer.js:1` closes the matching `})();`. Every `function`/`const`/
`let` in the 50 files shares that closure. The build gates collisions
with `check_duplicate_decls` (`build.py:431-444`) but only catches
**6 top-level shapes** (`DECL_RE`, `build.py:86-95`); it can't see
block-scope collisions or `var` hoisting.

**H2. No source maps or any path from installed exception to
`src/<file>.js:<line>`.** `strip_artifact_comments` (`build.py:320`) and
`compact_whitespace` (`build.py:331`) erase every comment and squeeze
leading whitespace before `node --check`. After `ascii_escape_artifact`
(`build.py:382`) the artifact is `\uXXXX`-encoded. A stack trace from
`grepbot.user.js:1247:5` has no recovery. Tampermonkey has no
`@sourcemap` semantics, but the *comment stripping* in particular is
gratuitous: Tampermonkey parses `//`/`/*` lines as text inside
`==UserScript==` blocks only, not in the body.

**H3. Test hooks are gated behind a flag the repo never sets.**
`src/boot.js:159-287` exposes ~110 functions via `GB_ROOT.__grepbotTest`
*only* if `GB_ROOT.__grepbotTestMode === true`. Nothing in `src/`,
`build.py`, or `archive/` ever sets that flag, and there is no `tests/`
directory, no fixture loader, no headless harness. The contract surface
is defined (`abortAttack`, `txClearUnknown`, `simulateTown`, etc.) but
unexercised.

**H4. Configuration is hand-shaped across four overlapping taxonomies
with no central schema.** The same logical concept lives in multiple
places:
- `STORE` constants (225 keys) at `src/header.js:24-252`.
- `WORLD_SCOPED_BASES` set at `src/header.js:258-281`.
- `CONFIG_SNAPSHOT_KEYS` allow-list at `src/qol.js:485-492` (intentionally
  excludes `webhookUrl`, `csrf`, learned templates, `findings`,
  `decisions`).
- `CONFIG_PRESET_HIGH_RISK` at `src/qol.js:628-640`.
- Inline `load(STORE.X, default)` lines in the 250-line `state`
  constructor at `src/core.js:322-566` (and another 224 `load(STORE.*, …)`
  calls across `src/`).
- Validator table inside `qolImportConfig` at `src/qol.js:599` (29 entries
  hard-coded next to the importer).

Adding a new config key requires touching **all six** for full
correctness (key declare → world-scope decide → export-allow-list decide
→ preset decide → state default → import validate). Forgetting the
export allow-list silently drops the value from the user's exported
config file.

**H5. Cross-module contracts are untyped and unversioned.**
`src/recruit.js:1-4` has a comment that admits the original problem:
*"Declared with their only consumer. These used to sit at the tail of
dodge.js, so recruit.js silently depended on dodge.js being concatenated
first — a build-order footgun with no compile-time signal."*

**H6. God modules swallow concerns that need to be split.** `src/ui.js`
is **3 207 lines**, `src/core.js` is **1 763 lines**, `src/qol.js` is
**918 lines**, `src/native-ui.js` is **1 124 lines**, `src/farms.js` is
**1 235 lines**, `src/intel.js` is **1 183 lines**, `src/stats.js` is
**1 097 lines**. `src/core.js` alone carries the central `state` object,
every cross-cutting primitive (`gbXhr`, `gbLock`, `gbPaint`, `gbWake`,
`gbLog`, `gbInterval`, `gbListen`, `gameUw`, `gameBridgeStatus`,
`captchaTrip`), the persisted-state normaliser, the full config
migration ladder, and the disposal routine.

**H7. No test, lint, type-check, format, or CI config anywhere.**
Stripping `package.json` makes sense for a paste-install userscript but
nothing in `AGENTS.md`, `CLAUDE.md`, or `docs/DOCS.md` documents an
equivalent developer workflow either. A single ESLint rule (`no-undef`,
`no-redeclare`) would have caught `H1` and `H5`.

#### D. MEDIUM severity

**M1. The ASCII-escape dance is no longer load-bearing but still ships.**
`ascii_escape_artifact` (`build.py:382-417`) replaces every non-ASCII
byte in the JS body with `\uXXXX`. In 2026 the paste flow is `utf-8`
everywhere; `@charset utf-8` is honoured by Tampermonkey, Violentmonkey,
and Greasemonkey 4+. The escape's only remaining consumer is file://
drag-into-tab, which is one of three install paths (`build.py:4-13`).
**Gate it on install path** (`--utf8` for paste/GitHub, escape-on for
file-drop), or drop it and rely on Tampermonkey's charset detection.

**M2. Hot reload is half-built and undocumented.** `GB_ROOT.__grepbotDispose`
(`src/core.js:206-241`) plus `gbInstanceAlive` (`src/core.js:12-14`) and
`GB_INSTANCE_ID` (`src/core.js:7`) implement hot-reload correctly. But
there is **no `watch` script** anywhere. The presence of all that cleanup
machinery means a 100 ms watcher on `src/` could provide dev reload with
zero new logic.

**M3. Decentralised per-account vs world-scope logic is implicit and
easy to break.** A new key whose author forgets to add it to
`WORLD_SCOPED_BASES` will leak across worlds at write-time and silently
migrate at read-time. There is no compile-time or test-time check that
every `load(STORE.X)` where X is in `WORLD_SCOPED_BASES` corresponds to
a write that uses `wkey(STORE.X)`.

**M4. Inner HTML is the single biggest XSS / performance smell but
built into the panel literal.** `src/ui.js:802` is a 491-line
`panel.innerHTML = \`...\`` template literal containing every section,
button, and `aria-label`; the renderer pays full reflow cost once on
every theme / panel-geom change.

**M5. State is a 50-key inline literal with no shape guard.**
`src/core.js:322-566` is one ~250-line object expression handed to
whatever scratches at `state.X`. Validation lives in ~28 inline
`if (!state.X || typeof state.X !== 'object' || Array.isArray(state.X))
state.X = {}` lines. Migration is `migrateConfig` (`src/core.js:583-747`),
**one big function with `if (ver < N)` blocks** that mutate `state` and
`save(...)` inline rather than producing a delta or returning a result.

**M6. No JSDoc, no `.d.ts`, and the only annotation is `//` line
comments.** Zero `@param`, zero `@returns`, zero `@typedef`, zero
`/** */` blocks across `src/`. The code carries *excellent* prose
comments — `src/research-graph.js:1-12`, `src/planner.js:1-23`,
`src/core.js:74-89` are exemplary — but they're prose.

**M7. Aggressive config allow-list with optional additions is a foot-
gun.** `CONFIG_SNAPSHOT_KEYS` at `src/qol.js:485-492` is currently 24
keys (allow-list), but `qolImportConfig` at `src/qol.js:599` uses a
*separate* `validators` table that also has 29 entries. They are kept
in sync by author discipline.

#### D. LOW severity

- **L1.** The `STORE` map and the `STORE` allow-list are two literal
  objects with no shared source.
- **L2.** The IIFE is `'use strict';` but `unsafeWindow` access doesn't
  have a uniform contract. The pattern `gameUw().MM.getOnlyCollectionByName(name)`
  is repeated ~50 times; `mmCol` helper exists but most call sites
  reimplement the lookup by hand.
- **L3.** The internal test surface (`__grepbotTest`, `__grepbotPlanner`)
  is `window`-globals, not typed contracts.
- **L4.** No `index.test.js`-style entrypoint. The artifact is the
  program.
- **L5.** The build pipeline writes one sibling for `--prod` and not
  two otherwise. There is no diff-style artifact, no manifest of module
  sizes, no source-map index, no `--watch`, no `--json` of the module
  list.
- **L6.** State and config export round-trips through
  `JSON.parse(JSON.stringify(...))` five times. Each step pays the cost.
- **L7.** Multilingual strings are scattered across the codebase in
  Spanish. The thin `I18N` map at `src/core.js:1641-1648` covers exactly
  3 keys for 6 languages. There is no full i18n table.

### E — Userscript-Specific (Tampermonkey / Violentmonkey realities)

#### E. Executive summary

- **The `@grant` list is complete and correctly minimal** (6 grants).
  No `GM_notification`, `GM_listValues`, `GM_deleteValue`,
  `GM_setClipboard`, or `GM_getResourceText` are granted, and none are
  called. `Notification` is used directly (`src/alerts.js:81`) — fine
  on Chrome, but Violentmonkey does not define it; an unguarded
  `typeof Notification === 'undefined'` check is there
  (`src/alerts.js:79`), so the call is at least safe.
- **Cross-tab coordination via `navigator.locks` is wired up but
  cosmetic**: it elects a "leader" boolean (`src/core.js:11,61`) and
  nothing in the code reads `gbTabLeader` to gate writes — every tab
  still runs its own loops. It is only used as a heartbeat / status
  indicator via `updateStatus()`. Real cross-tab serialization does
  not happen.
- **Paste-install and GitHub install paths are not equivalent**: the
  `@match` line accepts any `*.grepolis.com/*` host, but the header has
  **no `@updateURL` / `@downloadURL` / `@icon` / `@supportURL`**. TM
  therefore cannot auto-update. The version bump gate in `build.py:483`
  is enforced only for paste-install; a GitHub-URL install would
  silently stay stale.
- **Boot-time GM storage I/O is a 217-call synchronous storm**:
  `src/core.js:322-566` initializes the entire `state` object via
  `load(STORE.X, …)` — and the constructor block is executed before
  the GM menu commands are registered.
- **ASCII-escape dance is still justified in 2026** because the install
  workflow is paste-or-drag-drop. But `ui.js` and `native-ui.js`
  inject their `GM_addStyle` blocks without a dedupe guard, so two
  instances double-inject the stylesheet.

#### E. HIGH severity

**H1. No `@updateURL` / `@downloadURL` — no auto-update path.**
`src/header.js:2-20` declares `@name`, `@namespace`, `@version`,
`@description`, `@author`, `@match`, `@run-at`, `@noframes`, six
`@grant`s, and four `@connect`s — and **nothing else**. No
`@updateURL`, `@downloadURL`, `@icon`, `@supportURL`, `@resource`,
`@require`. TM will only auto-update when those are present. The
version-bump gate in `build.py:469-489` is therefore local to the dev
workflow; a deployed script on grepolis.com stays on whatever version
the user last pasted. For a 24 k-line script that auto-evolves, this is
a footgun.
*Action:* add `@updateURL https://raw.githubusercontent.com/<owner>/<repo>/main/grepbot.user.js`
and a matching `@downloadURL`, plus an `@icon`.

**H2. `@noframes` + `@match https://*.grepolis.com/*` is a mismatch.**
`src/header.js:7,9`. `@noframes` tells TM the script refuses to run
inside iframes, but the game itself may load Grepolis inside a launcher
iframe in some embed configurations. With `@noframes` set, the script
silently does nothing in those embeddings and the user sees a dead
panel.
*Action:* drop `@noframes` unless deliberately blocking embed
deployments, and add a note.

**H3. `navigator.locks` is acquired but never used for coordination.**
`src/core.js:11` declares `gbTabCoordSupported`, `gbTabLeader`,
`gbTabLockPending`, `gbTabLockRelease` and `src/core.js:61` calls
`gbTryAcquireTabLeader()` once at boot — then `gbTabLeader` is only read
inside `updateStatus()`. Every feature module runs on **every tab**
independently. The cross-tab storm that motivated the lock is still
happening. Worse, with `mode:'exclusive', ifAvailable:true` the lock
never blocks — a slow tab releases instantly and never defers.
*Action:* gate at least the high-stakes writes (e.g. `txRun`,
`nativeQueueSweep`, `bandit`) on `gbTabLeader`, OR drop the lock entirely
if the design truly is "every tab acts independently."

**H4. 217-key synchronous GM bootstrap can starve the page.**
`src/core.js:322-566` constructs the entire `state` object via
`load(STORE.X, …)` — each `load` is a synchronous `GM_getValue`
(`src/core.js:1415-1426`). That is ~217 round-trips through TM's value
store on every page load, **before** any tab can paint. On Firefox +
Violentmonkey this is the single biggest source of "the page is blank
for a second" complaints.
*Action:* split `state` into an "always-needed" core (~30 keys) loaded
eagerly and the rest via `load(STORE.X)` lazily on first access.

**H5. Storage-quota prune is destructive.** `src/core.js:1454-1507`
(`storagePruneForQuota`) drops: the user's last 50 decisions, anything
past `SEEN_MAX` (2 000) of seen alerts, all alerted entries older than 3
days, the first 100 findings, all farm resource entries older than 1
day. The function does this *once on quota* and then *retries the
original write*. If the original write is the one that consumed most of
the budget, the retry re-trips quota — and the user is in a loop. The
2nd-attempt error path (`src/core.js:1524-1531`) gives up silently.
The user never knows their writes were dropped.
*Action:* write a small "drop these 5 ring buffers, then retry" loop
that bounded-retries; surface a user-visible "storage full — older data
trimmed" toast instead of just a `gbLog`.

#### E. MEDIUM severity

**M1. `GM_addStyle` is called three times with no dedupe.** `src/ui.js:468`
and `src/native-ui.js:748` call `GM_addStyle(\`...\`)` at module init.
`src/queue-center.js:51` does, but guards it with `state._gbQcCssInjected`.
The first two do not — and on hot-reload (`__grepbotDispose` at
`src/core.js:206`), the previous instance's CSS is **not removed**. A
second inject doubles every selector.
*Action:* apply the same `state._gbCssInjected` guard to the `ui.js`
and `native-ui.js` `GM_addStyle` calls.

**M2. GM menu commands can leak across hot-reloads.** `src/core.js:191-204`
registers and unregisters via `gbMenuCmds`, and `grepbotDispose` walks
the list (`src/core.js:215`). However, the original instance's disposal
runs from `src/core.js:5` *before* the new instance overwrites
`GB_ROOT.__grepbotDispose`. If the previous instance had any menu-
registration failures (the `try/catch` at line 198 swallows them), those
entries are never tracked and never unregistered. After N hot-reloads,
the menu becomes a graveyard of stale entries.
*Action:* on the new instance's boot, walk `GB_ROOT.__grepbotMenuIds`
(a parallel global) and re-unregister anything older than
`GB_INSTANCE_ID`.

**M3. `unsafeWindow` is the right pattern but wrapped inconsistently.**
The repository correctly uses the `typeof unsafeWindow !== 'undefined'`
guard (`src/core.js:3,172,1324`), and falls back to `window.wrappedJSObject`
for Firefox (`src/core.js:1327`). But `src/quests.js:521` has its own
private copy: `const _uw = (typeof unsafeWindow !== 'undefined' &&
unsafeWindow) ? unsafeWindow : window;` — bypassing the shared `gameUw()`
cache (`src/core.js:1321`). That cache has a 400 ms memo and is the
right thing to use here.
*Action:* replace ad-hoc `unsafeWindow` lookups with `gameUw()` or
`uwCached()`.

**M4. World-scoped key space is fine, but the migration dance doubles
write traffic.** `src/core.js:584-747` (`migrateConfig`) writes every
world-scoped key on every config bump. For `ver<2` that is ~150 keys × N
worlds. Each save is a `GM_setValue`, which serializes the value
through TM's value store. On a multi-world account, the very first
install after upgrade touches the quota wall.
*Action:* guard the v1→v2 migration behind a single
`world-migrated-v2:{host}` flag rather than re-touching every key.

**M5. `worldScoped` set lives only in the artifact and is per-build.**
`src/header.js:258-281` (`WORLD_SCOPED_BASES`) is the source of truth
for which keys get the `@hostname` suffix. Adding a new `STORE.X`
without also adding it to this set silently produces a **cross-world
leak** — data from `*.es.grepolis.com` ends up visible on
`*.de.grepolis.com`.
*Action:* add a build-time lint in `build.py` that compares `STORE.X`
keys vs the `WORLD_SCOPED_BASES` set.

**M6. The hot-reload dispose path silently leaves `navigator.locks`
released but `gbTabLeader=true`.** `src/core.js:209` clears
`gbTabLockRelease`, sets `gbTabLeader=false`, but `__grepbotInstanceId`
is also cleared (`src/core.js:238-240`) — so the **new instance** starts
with `gbTabLeader=false` (correct), then re-tries to acquire the lock
at `src/core.js:63`. The timeout retry at `src/core.js:61` chains 5 s/10
s retries on top of a hot-reload that may happen every devtools-refresh.
*Action:* document `gbTabLeader`'s semantics, or gate the heavy writers
now.

## Positive notes

What the agents agreed is well-engineered and should be **preserved** through
any refactor:

- **The `gb*` + `GB_*` prefix convention** (`src/core.js`) creates a
  stable internal API and an obvious "this is a primitive" signal. Worth
  expanding, not replacing.
- **The disposal architecture** (`src/core.js:206-241`) tears down
  timers, XHRs, listeners, menus, observers, and hooks — unusual for a
  userscript of this size. Hot-reload works because of it.
- **The `gbWakeDrain` burst serializer** (`src/core.js:924`) with
  `WAKE_SPACING_MS` is the right shape — equivalent to a reliable
  `requestIdleCallback` for the userscript runtime.
- **`reqBudgetOk` + `REQ_SCOPE_FRACTION`** (`src/core.js:887,893`) is a
  well-engineered admission control layer that wraps every network
  interaction.
- **The build pipeline is unusual and good** for a userscript: `node
  --check` gate, duplicate-decl scan, version-stamp gate, comment
  stripping, ASCII-escape justification. Worth keeping even as it grows.
- **`build.py:382-417`'s reasoning for not adopting a real minifier is
  correct** — a wrong rename in a paste-only userscript is unfixable
  from the user's side. Keep that comment in-tree.
- **The prose comments are exemplary.** `src/core.js:74-89`, the v4
  plan references at `src/core.js:1039`, `src/queue-center.js:1-11`,
  `src/alerts.js:30-39`, `src/diagnostics.js:1-9`, `src/qol.js:1-19` are
  reference-grade. Don't let tooling churn replace them with stub
  docblocks.
- **The `__grepbotTest` test-mode surface** (`src/boot.js:159-287`) is
  excellent API design — it's just unused today (see §A H4 / §D H3).
- **The `navigator.locks` integration** for *leader* election itself
  (i.e. the API contract, separate from the "no caller uses it" gap)
  uses the right primitive (`{ mode: 'exclusive', ifAvailable: true }`).
- **All 4 `innerHTML=` sites are literal.** Zero XSS sinks today. Worth
  a one-line comment per site to keep it that way (see §C M5).
- **All `addEventListener` calls route through `gbListen`** except a
  small number of one-shot DOM handlers — no listener leak surface
  beyond nav-button handlers in `paintNav` (see §B L3).
