## 2. Preconditions and blind reads

- **v5.10.2 `+x` + `isFinite` read unreadable as `0`**: `gbProbeNum` coerced the getter result with `+` and then tested `isFinite`, so a client getter answering `null`, `''`, `[]` or `false` returned a perfectly finite `0` that every caller treated as a real reading — pop 0, warehouse capacity 0, "academy level 0" — and a guard then blocked on a value it had never read. Its own sibling `gbProbeAttr` already guarded `a[n] != null` first, which is what made the asymmetry visible. Same idiom sat in `gbBuildingLevel`, `researchConstant`, `researchResMod`, the academy/library level probes, the cave hide-capacity read and the culture stock read. All of them now go through `gbNum`, and there is no bare `isFinite(` left in `src/`. Rule: `+` is not a readability test.

- **v5.10.2 `gbSafe` was an unescaped sink named "safe"**: the sanitizing half of the `innerHTML` pair fell back to `return gbLit(html)` — raw pass-through — whenever `typeof DOMPurify === 'undefined'`, which is exactly the case its CDN `@require` fails to prevent. It had zero call sites in the whole repo, so the only thing the `@require` bought was a third-party fetch from cdnjs on every game page load. Removed both. A future feature that needs markup from the wire adds its own sanitizer deliberately instead of inheriting a dead one that is only safe when the network cooperates.

- **v5.9.9 random fallback never posted**: `abRandomPick` only ran when `abPickNextFromLevels` returned null, then handed its pick to `abBuildUp` — whose `abFinalValidate` re-ran `abPickNextFromLevels` and answered `no-valid-build` every single time. Whole feature shipped dead in v5.9.8. Worse, the failure was invisible: the catch-all called `noteBlocked`, which early-returns when the native lane is empty — always true on this path. Fix: `abFinalValidate` accepts an explicit `plan.randomFallback` pick (still re-validating max level, prerequisites, affordability, dedup and queue gates against the live model), and the fallback logs through its own `gbLogT` instead of `noteBlocked`. Rule: when a caller reaches a validator only in the state that validator treats as fatal, the validator needs an explicit-input branch, not a second opinion.

- **v1.5.4 preconditions**: gaps closed were **research** (post techs with no resource / research-point check — every scan burned budget slot on guaranteed rejection), **merchant** (buy without read gold balance), **rural trade** (no per-relation trade cooldown check, and it traded `wantRes` into town whose `wantRes` stock already at capacity — haul evaporates on arrival; dead `if (!blocked && !state.autoRuralTrade)` line it replaced could never be true, `autoRuralTrade` asserted at top of scan), and **militia/dodge** (`request_militia` with no farm / militia already standing / no free population, and `dodgeSafeTown` dodging *into* town that itself had incoming — one lost town become two). Do not "simplify" any of these into unconditional post; server rejection not free, cost request budget slot and decision-memory strike every cadence.
- **v1.5.3 audit**: free instant require model gold===0 + `gameNow()`; never `buyInstant` fallback on timeout; olympic need `allowPremiumCulture`+budget; quests `every()`+no DOM fallback; dodge hostile-only; attack town targets + overdue refuse; favor `temple_plunder`; recruit by unit building; host-gated scrapes/reports; claim/sleep reconcile; `gbXhr` budget+captcha skip.

## 3. Scheduling and locks

- **v5.10.2 orchestrator invented two feature keys**: `ORCH_CAPTCHA` and `ORCH_JRN` translate an orchestrator key into the key the POST layer actually uses, and both are the `feature` argument `bridgePost`/`gameAjaxPost` was called with — never the orchestrator's own key, never a lock name. Two entries were invented and matched nothing: `villrecruit: 'villageRecruit'` (recruit.js posts and gates on `'villrecruit'`) and `godspell: 'godspell'` (every cast goes out through `spellCastPost` as `'spell'`). Both failed silently in the same two ways: `captchaPaused()` on a key no post ever trips is permanently `false`, and `orchJrnOkSince` counted zero `ok` rows forever, so the adaptive backoff read a busy feature as idle and widened its cadence to the 8× ceiling. `god-spells.js` had the same mistake at the feature level — it gated on its LOCK name `'godspell'`, so a captcha on a cast never backed the scan off at all. Rule: a captcha key and a journal `f` are whatever was handed to `bridgePost`; a lock name is not a feature key.

- **v5.9.9 guard order**: `txActionGate` checked captcha, the breaker and decision memory *before* dry run, and charged the request budget before the planner ever ran. Dry run is documented as first for a reason — a captcha-paused or budget-starved feature is exactly when you want to inspect the payload it would send, and dry run sends nothing, so no downstream guard has anything left to protect. Restored order for writes: dry -> breaker -> safe -> health -> dedup -> planner -> budget -> captcha, with captcha re-read immediately before the send (a ladder that opened mid-tick still stops it; one that expired does not cost the slot the planner holds). Cost: one `aborted` tx record per attempt while a ladder is open, pruned at `TX_TERMINAL_TTL`, and `aborted` never blocks the next attempt.

- **v1.1.0**: `orchTick` sole econ scheduler (cadence-aware). Do not re-add per-feature `gbInterval` for cave/culture/trade/farm/ab/… alongside orch — that was thrash bug.
- **v1.4.0 lock registry**: never reintroduce module-local `*InFlight` boolean. Boolean can only be cleared by path that set it, so callback that never fires strand feature until reload, and `beforeunload` reset block did not run on bfcache/mobile exits. Use `gbLock(name)` / `gbUnlock(name)` / `gbLocked(name)` and add TTL entry to `GB_LOCK_TTL` for new features.
- **v1.4.0 orch**: one-feature-per-tick was throughput ceiling (3 actions/min) AND starvation bug (strict list order). Keep per-tick budget + overdue tie break; do not "simplify" back to single `return` after first match.
- **v1.4.0 adaptive cadence** infer "did feature act" from journal entry count for that feature, sampled 4s after run — feature scans return void, so no return value to trust.
- **v1.6 instant arming**: armed timer *accelerator*. Never delete 10s `gbInterval` or click hook in favour of it — clamped background timer can fire minutes late, and interval what recover that.
- **Farm/town scrape deadlines**: `nextFarmScrape` / `nextTownsScrape` added v0.3.2, **persisted to storage in v0.4.1** so cadence survive reloads. Stamp deadline at START of every scrape (prevents double-fire when manual `Farms now` / `Towns now` zero them); manual buttons zero deadline + call `farmTick()`, never arm own timer. Never use chained `setTimeout(scrape, 5min)` — background tabs throttle it to ~20min.
- **`scrapeAllFarms` empty-list early-return bug** (fixed v0.3.1): next deadline MUST be stamped even when `state.farmsParsed.length === 0` (stamp happens before fetch queue since v0.4.1).
- **Parallel farm fetch bursts** (N farms × 6 endpoint guesses) got throttled by game server — only first farm updated (v0.4.1: sequential queue + cached `farmAction`).
- **v1.3.5**: log/reqBudget use head-index rings (no `shift()` thrash); bandit wakes off `banditIdleUntil` instead of fixed 1.5s interval; DOM MutationObserver scope to `#ui_box`/windows/quests; CSRF hit poll 120s + force-hunt on captcha/auth errors.

## 4. Transport, ack and templates

- **v5.9.9 `cave-emergency` took the READ path**: `emergency.js` posts `caveStoreIron` under its own feature key so its captcha ladder and circuit stay separate from routine stashing — but the key was never added to `TX_WRITE_FEATURES`, so `txRun` skipped dry run, the circuit breaker, safe mode, template health, tx dedup, the planner and the action budget on an irreversible resource move. This is the exact failure mode the `airaw` comment in `planner.js` warns about; a new feature key is a new write registration, always.
- **v5.9.9 dodge borrowed `attackTpl`**: `dodgeSendOut` posts `arguments.type === 'support'` but read `state.attackTpl.action_name`. Templates key to the PAYLOAD, not the feature: dodging was coupled to whether the player had ever hand-sent an *attack*, and on a world where the support and attack action names differ it would have replayed the wrong one. Now reads `supportTpl` with the same `'sendUnits'` fallback. `favor.js` keeps `attackTpl` on purpose — temple plunder really is an attack payload.

- **v1.6.1 gpAjax callback contract** (was: *everything* logged `err timeout` while action actually executed). Read `GPAjax` in `archive/captures/grepo-dump/js/game.min.js`: `_ajax` wrap **bare function** callback as SUCCESS-ONLY handler (`u=function(e,i,o,r){if("function"==typeof a)a(i,r)}`), and success branch skipped whole when response lack `json`/`_srvtime`. So server-side rejection (`json.error` → HumanMessage) and empty bridge payload both leave caller hanging until `BRIDGE_TIMEOUT_MS`. Two consequences: (1) bare callback args `(data, t_token)`, **not** `(wnd, data)` — window handle only passed to `{success,error}` object form; (2) every post now also register `gbAjaxWatch(sig, settle)` and XHR spy settle it from raw response on `loadend` (`gbAjaxClaim` match by `model_url|action_name` for bridge, `controller/action` otherwise). Do not drop watcher and go back to trust gpAjax callback, and do not drop callback either — whichever fire first win, `settled` dedupe. `captcha_required === true` real captcha flag game itself keys on.
- **v1.6.3 template health** charged per **learned payload**, never per feature key. Feature `build` carry two different posts: auto-queue `buildUp` (hardcoded payload — no template can be stale) and instant complete (only user of `ibAction`/`ibActionR`). Because both journaled under `build`, five ordinary auto-queue server rejections invalidated `ibAction`, and `tpl-stale` gate in `bridgePost` then blocked *both* features until hand-click. v1.6.1 lit it: those rejections used to settle as `timeout`, which `jrnHard` exclude. `tplNameFor(feature, payload)` now resolve by `action_name`/`model_url`; add new learned template to that resolver, not just to `TPL_FEATURE_MAP`. `tplHealthOk` also treat unlearned template as healthy (caller fall back to constant) and expire invalidation after 30min — gate block only post that could ever record `ok`, so without expiry one bad streak permanent.
- **v1.4.0 dry run**: `state.dryRun` short-circuit inside `bridgePost` / `gameAjaxPost` only. Any new transport must route through those two or dry run silently stop covering it.
- **v1.1.0 journal scoping**: decision journal keys world-scoped (`wkey`) — town/village id mean nothing on other world, so unscoped journal would skip valid targets after world switch. Skip windows must ignore `skip:*` results: night pause fire thousands of times and would otherwise look like dead endpoint. `renderLog` also bail when `.log-list` `hidden` (Decisions sub-view active).
- **v1.6 phoenician**: offer parser (`ptParseOffers`) written against server-rendered markup **without live sample** — treat parse miss as unknown (post nothing), and confirm with Config → *Copy offer HTML* before trust bulk trade. Never let scraped stock be only bound on bulk amount.

## 8. Better-practice helpers (v4.62–v4.65 sweep) — full notes

Platform primitives, no new dependencies. `CLAUDE.md` list names; detail here.

- **`structuredClone(value)`** — prefer over `JSON.parse(JSON.stringify(x))` for any config / state snapshot. Preserve `Date` / `Map` / `Set` / `RegExp` / `ArrayBuffer` / typed arrays / `Error` with `cause` / `stack`, handle circular references, throw `DataCloneError` instead of silently drop `undefined` / functions / `Symbol`s. Used in `qol.js` (`qolConfigSnapshot` / `qolSaveTemplate` / `qolApplyTemplate` / `qolImportConfig`).
- **`BOOT_TIMING`** (`src/boot.js`) — frozen module-scope object of every cadence boot block use (INBOX_SCRAPE_MS, FARM_TICK_MS, THRESHOLD_CHECK_MS, STATUS_UPDATE_MS, OVERVIEW_RENDER_MS, LOCK_SWEEP_MS, NATIVE_QUEUE_LOOP_MS, plus boot-step delays FARM_WAKE_MS / QUEST_SCAN_BOOT_MS / IB_SCAN_BOOT_MS / AB_TARGETS_MS / NATIVE_UI_SCAN_MS / NATIVE_QUEUE_BOOT_MS / ORCH_FIRST_TICK_MS / HUD_RESTORE_MS / IB_CLICK_HOOK_MS, plus FIRST_FARM_DEADLINE_MS / FIRST_TOWNS_DEADLINE_MS that pair with persisted `state.nextFarmScrape` / `state.nextTownsScrape` deadlines). Naked `30000` / `15000` / `10000` in `boot.js` regression.
- **`gbNum(raw)`** (`src/core.js`) — the only numeric read of a client value. Returns a finite number or `null`; rejects `null` / `undefined` / `''` / `' '` / booleans / arrays / objects instead of coercing them. `+raw` maps every one of those onto a finite `0`, so the old `const v = +getter(); if (isFinite(v))` idiom accepted an unreadable getter as a real reading. `gbProbeNum` / `gbProbeAttr` / `gbBuildingLevel` / `researchConstant` / `researchResMod` / cave hide capacity / culture stock all route through it.
- **`gbLit(html)`** (`src/core.js`) — the one named bucket for `innerHTML`: LITERAL HTML ONLY (pass-through; an audit pass greps `innerHTML = gbLit(...)` and confirms no `${…}` interpolation). Wire values go in as `textContent`. There is deliberately no sanitizing sibling — see § 2 for why `gbSafe` and its DOMPurify `@require` were removed in v5.10.2.
- **Listener bag `AbortController`** (`src/core.js`) — one per-instance `AbortController`; every `gbListen` call pass `{ signal: gbListenerSignal }` so dispose call `gbListenerAbort.abort()` and detach every listener in one call. Bag survive as debug mirror only.
- **`gbPaint` selection preservation** (`src/core.js`) — snapshot `document.activeElement.id` + `selectionStart` / `selectionEnd` / `selectionDirection` before structural replace; restore focus + caret in new tree via `CSS.escape(id)` + `setSelectionRange`. Patch path already safe via `activeElement` skip on `.value` / `.checked`; this guard rarer REPLACE path.
- **`renderLog` rAF coalesce** (`src/core.js`) — visible tab coalesce per frame via `requestAnimationFrame` so burst of log lines paint once, not once-per-line. Hidden tab keep 250ms `gbTimeout` (rAF paused).
- **`scheduleAutoCollect` rAF** (`src/collect.js`) — same pattern for `MutationObserver` → auto-collect path; visible tab coalesce per frame, hidden tab keep 800ms timer.
- **JSON.parse size cap** (`src/bridge.js`) — `gbAjaxUnwrap` cap `JSON.parse` input at `GB_AJSON_PARSE_MAX = 256 KB`. `noteCaptchaBody` still sniff only first 4 KB upstream; this guard second line against oversized hostile body. Largest legitimate bridge payload today all-towns scrape at ~32 KB.
- **Captcha status pre-check** (`src/bridge.js`) — `gbAjaxWatch`'s settle callback classify status-first: 429 / 503 open server-pressure bus with `Retry-After` parsed to seconds; 200 with empty body short-circuit to `'soft-empty'` (skip class, not hard error, so three in row don't open `JRN_BACKOFF` skip window for nothing). `captcha_required === true` precedence preserved.
- **`saveSoon(key, val)` / `saveFlush()`** (`src/core.js`, v5.3.0) — 400ms coalesced `GM_setValue`. `state` stay live in memory; only write debounced, last value per key win. Village sweep was motivating case: `fetchFarmResources` write **whole** `state.farmResources` map and `towns.js` whole `state.townResources` map once **per village/town**, so 40-village account paid 40 full serializations per 5min cycle. `whyNote` had same shape (entire 200-row `whyLog` re-serialized per decision note). **Debounced write only safe because of flush**: `saveFlush()` called from `releaseLocks` (`boot.js`, on `pagehide`/`beforeunload`) as LAST step — after every other handler had chance to queue write — and from `__grepbotDispose` BEFORE `gbClearTimers()`, or pending timer die with its payload. `txSave` deliberately left synchronous: `committed` transaction must be durable immediately, since recovery path for lost write re-posting irreversible action.
- **`renderFarmsSoon` / `renderWorldSoon` / `checkThresholdsSoon`** (v5.3.0) — same fix on paint side of that cascade; `checkThresholds` full walk of `farmsParsed`, and call it per village made sweep O(N²) for answer that only depend on finished state.
- **Hidden-tab render guards** (v5.3.0) — `renderTimers` (1s) called `farmClaimTiming()`, which walk whole `FarmTownPlayerRelation` collection, against tab nobody looking at; `contextMenuScan` (750ms) ran `querySelectorAll` + `getBoundingClientRect` + `elementFromPoint`, three forced layout flushes 80×/min, likewise. All now bail on `document.hidden`, and `boot.js` repaint on `visibilitychange`/`pageshow` so first visible frame correct instead of frozen countdown. Context menu deliberately does NOT dispose while hidden — hidden tab not closed popup. **Note:** `renderFarms` / `renderWorld` also grew hidden-section guard, but their hosts (`.farms-list`, `.world-list`, `.world-totals`, `#gb-sleep-status`) **absent from panel markup** in current tab set, so both functions early-return on every call today. They left in place rather than deleted: restoring those tables product decision, not cleanup.
- **`SPY_LOAD_GATE_RE`** (`src/spy.js`, v5.3.0) — XHR `load` reader used to attach to **every** game request and, under 100KB, read `responseText` and run full `JSON.parse` plus recursive report walk. SPA issue these constantly. Listener now attach only when URL could plausibly carry report or quest reward. Bare `/index.php?...` deliberately NOT in gate — game's generic endpoint and match nearly every request, which exact cost being removed. Tradeoff: >100KB "report_id buried in unnamed payload" scavenger no longer run on those responses; named report URLs still caught on send path by `queueReport` / `queueReportList`.
- **Keyboard fingerprints** (`src/qol.js`, v5.3.0) — `gbKeyFingerprints` had `if (e.altKey) return []`, so **every** `Ctrl+Alt+…` binding unreachable, and `gbKeyChars` only emitted single printable characters, so any binding on named key (`Backspace`, `Escape`, …) could never match either. New defaults: `Ctrl+Shift+Backspace` (panic — no confirm on way in on purpose, kill switch and itself reversible via `gbPanicRecover`), `Ctrl+Alt+P` (profiler), `Ctrl+Shift+B` (copy bundle).
