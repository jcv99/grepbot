# 8.7 — Minification knob (dev/prod build)

**Bucket:** v4.1 · **Risk:** Low · **Size:** S
**Module:** `build.py` (only). No `src/` edit, no new module.
**Depends on:** none
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.9.0
(header.js:4; `.build-stamp.json` carries `version: 3.9.0` and the
artifact at `grepbot.user.js` is `838,274 B` — one bump past plan
27's stated baseline of `3.8.2`).

## 1. What exists today

The artifact is already partly minified. `build.py` runs three
shaping passes that today are unconditional:

- `strip_artifact_comments` (`build.py:305-313`, bodies of
  `strip_js_comments` at `build.py:92-302`) drops every `//` and
  `/* */` outside strings/templates/regex, keeping the
  `==UserScript==` block raw.
- `ascii_escape_artifact` (`build.py:316-351`) rewrites every
  non-ASCII char to `\uXXXX` (surrogate pairs above U+FFFF).
  Purity-checked (`build.py:441-443`); non-ASCII in the metadata
  block is a hard error (`build.py:335-341`).
- `strip_js_comments` runs two further rules at
  `build.py:300-301`: collapse `\n[ \t]*\n+` to `\n\n`, collapse
  `[ \t]+\n` to `\n`.

Existing size: raw `src/` = `901,949 B` across 40 modules
(`build.py:31-72`); artifact = `838,274 B` — the comment +
whitespace + ASCII-escape pipeline already recovers ~63 KB / ~7 %.
Line-level comment ratio is ~5 % across the tree (counted
`^\s*//` lines per file); the remaining size comes from
indentation, in-line spacing, and newline runs.

The build gates that already run, all in `build():` at
`build.py:426-454`: duplicate top-level decl detector anchored on
**two-space indent** (`build.py:74-80` + `365-378`, since the
whole script is one IIFE), `==UserScript==` presence
(`build.py:435-438`), ASCII escape, `node --check` on a sibling
`.build.js` (`build.py:381-392`, soft-warns when `node` is
missing), version gate (`build.py:403-423`) hashing the concat
into `.build-stamp.json`.

There is **no** `--dev` / `--prod` flag, **no** minifier call,
**no** rename pass, and no package manifest — `ls` of the repo
root confirms `build.py`, `.build-stamp.json`, `.gitignore`,
`AGENTS.md`, `CLAUDE.md`, `grepbot.user.js` only.

CLAUDE.md binds the workflow: *"bump `@version` in
`src/header.js`, run `python3 build.py`, paste into Tampermonkey.
Never start a local server."* (`CLAUDE.md:201-205`,
`389-399`); and in the Tooling section: *"No linter, no test
runner, no Node workflow — paste-only mode. Phase 7 explicitly
removed the parser test harness."*
(`CLAUDE.md:251-256`). `node --check` survives only because it
is gated on `shutil.which('node')` (`build.py:382-385`).

Plan 27 §0 (*Out-of-scope*, `27-v4-wishlist-2026-08-10.md:27-48`)
explicitly bans "variable rename in artifact" because renaming
would break sniff contracts (`claimTpl`, `attackTpl`, `ibAction`,
`ibActionR`, `cancelTpl`, `acceptUnitsTpl`, `farmOptionMap` —
captured in `spy.js`, `farms.js`, `attack.js`, `phoenician.js`,
`quests.js` and watched via `gbAjaxWatch`).

## 2. Gap

The artifact ships in **one** shape. A developer chasing a runtime
warning in Tampermonkey reads `src/`, not the artifact, because
`build.py:300-301` already nukes comments and the IIFE indent is
preserved but ugly. Production users get an 820 KB paste with no
identifier-mangling benefit to show for it. The two goals —
*easy debug* and *small artifact* — are coupled today, and
splitting them is the entire point.

The gap is **not** "no minifier is wired up". A real minifier
either needs Node (banned) or downloads a binary (no
provenance). The gap is that `build.py` has no knob: there is no
way to pick "readable" vs "denser" without changing source
comment density, which is the wrong lever.

The plan-27 module hint (`extend build.py`) is right: this is
the only file to touch.

## 3. Design

Two output shapes, chosen by a build-time CLI flag. Both share
every existing gate (dup-decl, header presence, ASCII escape,
`node --check`, version, stamp).

- **dev** (default, today's behaviour exactly):
  comment-strip + ASCII escape + the two collapse rules already
  at `build.py:300-301`. Line offsets still match `src/` well
  enough for Tampermonkey console → grep in source.
- **prod** (`python3 build.py --prod`): same pipeline plus a
  pure-Python `compact_whitespace(text)` that runs **between**
  `strip_artifact_comments` and `ascii_escape_artifact`. Writes
  `grepbot.user.js.prod` alongside the dev artifact (sibling
  path, **not** in place — a stuck prod install never breaks
  the dev paste path).

What `compact_whitespace` does:

1. collapse `\n[ \t]*\n+` → `\n` (promote the existing
   `build.py:300` rule to the top so it always runs).
2. collapse `[ \t]+\n` → `\n` (existing `build.py:301`).
3. strip leading two-space IIFE indent from non-blank lines
   whose first non-whitespace token is **not** in
   `function|class|const|let|var|return|await` — the IIFE
   depth is uniform and DECL_RE's anchor (`build.py:74-80`) is
   the litmus; this rule is the safe-degradation point if it
   ever needs to be dropped.
4. trim trailing whitespace from each line; collapse consecutive
   `\n` runs to single `\n`.
5. *Optional*, only if §9's gate still passes:
   join `^\n` to `(` / `{` on lines that are purely a closer.

Crucially, **no identifier renaming, no AST rewrite, no
`eval`-strip, no constant folding**. The sniffer contracts in
`src/` are *runtime state-object keys* (`claimTpl`,
`farmOptionMap`, `attackTpl`, …) and are already strings, so
whitespace stripping is the only safe reducer. The plan-27 §0
ban on "variable rename in artifact" only rules out AST-rewriting
minifiers — whitespace stripping is a different class.

Estimated sizes against the current `838,274 B` artifact:

| Path | Estimated size | Delta vs today |
|---|---|---|
| Dev (today) | 838,274 B | — |
| Prod: rules 1+2+3+4 | ~795,000–810,000 B | −30–45 KB / 4–5 % |
| Prod: rules 1–5 | ~755,000–790,000 B | −50–85 KB / 6–10 % |
| Hypothetical `terser --mangle` | ~280,000–380,000 B | −460–560 KB / ~55 % — **forbidden** |

The honest conclusion: we are already 63 KB into the easy-minify
space, have ~30–80 KB more to give without crossing the rename
line, and the rest is real-minifier territory at the cost of
CLAUDE.md's no-Node rule.

## 4. Work items

1. `build.py` — add `import argparse`. New constants near the
   top (`build.py:26-29`): `MODE_DEFAULT = 'dev'`,
   `OUT_PROD = OUT + '.prod'`. Parse argv in
   `if __name__ == '__main__'` (`build.py:457`); on an unknown
   mode, `SystemExit(1)` with one-line help.
2. `build.py` — new `compact_whitespace(text, mode)` placed
   physically next to `strip_artifact_comments`
   (`build.py:305-313`). In `mode == 'dev'` it returns `text`
   unchanged so the dev build is byte-identical to today.
3. `build.py` — `build(mode=MODE_DEFAULT)`
   (`build.py:426-454`). Insert
   `body = compact_whitespace(body, mode)` between
   `strip_artifact_comments` (`build.py:434`) and
   `ascii_escape_artifact` (`build.py:440`), gated on
   `mode == 'prod'`.
4. `build.py` — final `os.replace(tmp, OUT)` (`build.py:453`)
   becomes `os.replace(tmp, OUT_PROD if mode == 'prod' else OUT)`.
   `.build-stamp.json` digest (`build.py:408`, `422`) stays
   mode-independent — the stamp tracks *source* change, not
   *output* shape, and a parallel prod build must not perturb
   the next legitimate dev `python3 build.py`'s version gate.
5. `build.py` — print the chosen mode at the start of `build()`
   so a future failed-build log shows which shape was being
   assembled.
6. `docs/error-patterns.md` — one-line entry: the on-disk artifact
   may be either `grepbot.user.js` (dev) or `grepbot.user.js.prod`
   (prod); Tampermonkey install path is the dev file. Prevents a
   stale paste URL pointing at a long-ago prod build.
7. No `src/` change. No header.js change. `.build-stamp.json`
   schema unchanged (`{src, version}`, `build.py:422`).
8. Sanity: `python3 build.py --prod && python3 build.py` must
   produce two artifacts sharing the same gate verdicts and
   differing only in on-disk size; the second (dev) run must
   be byte-identical to a `python3 build.py` today.

## 5. State & storage

No `state.*`, no `STORE.*`, no `WORLD_SCOPED_BASES` change.
`configVer` is not bumped (no runtime behaviour change). The
Prune TTL convention (`journal.js` 7d uniform, plan 27 §13) is
unaffected. The mode is a *build-time* parameter, not a runtime
preference — selecting prod means re-running `build.py --prod`
and switching which file is pasted.

## 6. Config surface

No runtime toggle, no Config-tab field, no DOM mount. Build is
a one-shot `python3 build.py` operation; dev is the default so
today's workflow (`CLAUDE.md:200-205`) needs no muscle-memory
change. Documented surface:

- `python3 build.py` → dev (writes `grepbot.user.js`).
- `python3 build.py --prod` → prod (writes `grepbot.user.js.prod`).
- `python3 build.py --mode=prod` → alias.

Per CLAUDE.md HIGH-RISK default-OFF rule: not applicable — this
is build tooling, not a runtime feature. Default (dev) keeps the
existing paste-debuggable artifact.

## 7. Post surface & safety

Read-mostly. **No post surface.** Minification changes the
artifact shape on disk; it does not change what the artifact
posts, reads, or triggers. `bridgePost` / `gameAjaxPost` /
`gbXhr` / `gbAjaxWatch` (`src/bridge.js:7`, call sites
`bridge.js:131,176`) / `gbCaptchaPause` / `gbLock` /
`GB_LOCK_TTL` (`src/core.js:145-…`, `189-…`) / `tplNameFor` /
`TPL_FEATURE_MAP` are untouched. No new template name to
register, no captcha feature key, no lock to add.

Per `v4/README.md` "Hard rules for authors" §6 (read-mostly
features must state plainly that they add no post surface) —
stated.

The only safety knob is that prod must not silently replace the
dev artifact. That is why §4 item 4 writes to a sibling `.prod`
path: a failed prod build leaves the dev file intact for the
next dev run.

## 8. Failure modes

Build-time only; precondition invariant is not applicable.

1. **Regex-literal breakage.** Compact runs *after*
   `strip_js_comments`, which has already tokenised
   `/loyal|lealtad|…/i` and `/^\d{1,2}\s*min$/` (the
   `_RE_PREV` + `_RE_KEYWORDS` lookahead,
   `build.py:84-89`, `113-117`). Whitespace does not touch
   `/`-literals; closed by construction.
2. **Template `${…}` brace collision.** The four compact rules
   collapse *between-line* whitespace only; they never cross
   a `${…}` boundary (the regex-prev machinery at
   `build.py:113-117` is what marks the boundary, and it is
   still in scope after stripping).
3. **Indent-offset mismatch.** A module that opens at
   four-space indent (because it nests inside another
   closure) would break rule 3. Mitigation built in:
   skip the indent strip on lines whose first token is in
   `function|class|const|let|var|return|await`. If even that
   is ambiguous, drop rule 3 (still saves ~10–20 KB,
   `grep -rE '^  '` shows the indent is uniform; this is
   paranoia, but cheap paranoia).
4. **Prod-only syntax regression on rule 5.** The
   `node --check` gate at `build.py:386-391` catches it;
   `os.remove(tmp)` (`build.py:447-448`) keeps a broken prod
   artifact off disk; dev artifact is unaffected.
5. **Stamp drift.** `python3 build.py --prod && python3 build.py`
   writes the same source-hash twice to `.build-stamp.json`;
   the next legitimate post-`src/`-edit run still triggers the
   version-reminder gate (`build.py:416-420`).
6. **Flag typo.** `--prdo` → `argparse` exits with usage; on
   the Python `argparse` default (exit 2), `build.py` never
   starts building, no dev artifact touched.

## 9. Validation gate

Manual, Low-risk, five shell-local steps:

1. `python3 build.py` → exit 0; `grepbot.user.js` byte-identical
   to today's `838,274 B` (dev path is a no-op pass-through).
2. `python3 build.py --prod` → exit 0;
   `grepbot.user.js.prod` exists; size in the `755,000–810,000`
   window from §3; `node --check` clean; file is pure ASCII (last
   byte ≤ `0x7F`).
3. `head -c 2000 grepbot.user.js.prod` shows zero `//` lines
   outside the `==UserScript==` block, zero `/* */` block
   comments in code, every non-ASCII as `\uXXXX`, ≤ 1
   consecutive blank line.
4. `cmp -l grepbot.user.js grepbot.user.js.prod | head` shows
   only whitespace divergence in the first 1 KB past the metadata
   block.
5. Paste `grepbot.user.js.prod` into a Tampermonkey test slot on
   `es146`; panel renders; Log shows
   `GrepBot v3.9.x cargado`; toggle one Config field (e.g.
   `exportRedact`) — Log shows the new state, then the old
   state. **No diff in any in-game behaviour** vs the dev
   install. Stats request budget identical at idle.

A fail in (1) → (4) blocks (5) and the change is reverted by
removing the `compact_whitespace` branch; `grepbot.user.js` is
the workflow's trusted artifact.

## 10. Out of scope

- **Real identifier minification** (terser / esbuild /
  uglify). Crosses CLAUDE.md's no-Node rule (`CLAUDE.md:251-256`)
  and plan 27 §0's variable-rename ban. Deliverable would be
  ~280 KB instead of ~790 KB, at the cost of a hand-pinned
  allow-list of `gbLock` / `bridgePost` / `txRun` /
  `gbAfford` / etc. that the runtime relies on, which has
  exactly the §1-cost of plan 26 §B6's load-but-never-read
  drift.
- **A `dist/` directory.** Today the artifact is the one file
  at `grepbot.user.js`; the prod counterpart is a sibling `.prod`
  file in the same place. Splitting out a `dist/` is what a
  release pipeline looks like, and this repo deliberately has
  none (`CLAUDE.md:14-35`, *"Repo root is deliberately minimal"*).
- **A runtime Config toggle** ("minified vs readable" inside the
  panel). Making it runtime means shipping both artifacts plus a
  download/swap step — exactly the surface CLAUDE.md §"Build"
  was written against.
- **A test harness** for `compact_whitespace`. Plan 27 §0
  ("Automated test harness … CLAUDE.md: 'No linter, no test
  runner'") and `CLAUDE.md:251-256` reinforce the manual-gate
  approach; §9's five-shell-step gate **is** the test.
- **Auto-rename of read-only model fields.** Restated for §0
  compliance: the prod pass must not change
  `state.farmOptionMap` / `state.farmAction` / `state.attackTpl` /
  `state.claimTpl` / `state.ibAction` / `state.ibActionR` /
  `state.cancelTpl` / `state.acceptUnitsTpl` keys (sniff
  contracts — `CLAUDE.md:294,467-481`, plan 27 §0, §11).
  Whitespace compaction does not change keys (whitespace does
  not survive `JSON.stringify`, which is how these payloads are
  captured), so this rule is free by construction.
