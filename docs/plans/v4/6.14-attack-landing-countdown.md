# 6.14 — Attack landing timeline visual countdown

**Bucket:** v4.1 · **Risk:** Low · **Size:** S
**Module:** extends `ui.js` (widget body) + `intel.js` (sort/filter helper).

## 1. What exists today

- `src/dodge.js:53-84` — `dodgeIncomingMovements()`. Returns one row per
  hostile inbound movement: `{id, dest, origin, type, hasCs, arrival,
  units, model}`. The hostile-only filter is the v1.5.3 audit rule
  (`DODGE_HOSTILE_TYPES` regex at `dodge.js:39`, `dodgeIsHostileMovement`
  at `dodge.js:41-52` — never trust `incoming`/`started_at` alone, see
  CLAUDE.md "dodge hostile-only").
- `src/dodge.js:175-180` — `dodgeEtaSec(mov)`. Returns `Math.max(0,
  arrival - gameNow())` in seconds. Handles the >1e12 ms-vs-seconds
  heuristic. **This is the function the widget renders against.**
- `src/intel.js:72-74` — `intelThreatBoard()` already calls
  `dodgeIncomingMovements()`. `renderIntel` at `src/intel.js:75-114` prints
  a text-only line per incoming attack with `riesgo`, `ETA`, `apoyo`,
  `esquivar` columns. The data is **already** in the Intel tab — but it
  is text, sorted by arrival order only by accident (the underlying
  collection returns in arbitrary order), and there is no visual
  countdown ticking down each second.
- `src/qol.js:162` — `dodgeIncomingMovements()` is also called from
  `renderDashboard` for the Overview "Amenazas" card.
- `src/dodge.js:175-180` already exists; the function is exported and
  reachable.

Plan 27 §9's 15-item "already shipped" list does **not** contain 6.14. The
nearest neighbours are "Support ETA, attack pattern, watchlist why"
(plan 27 §9 line 249 — `intel.js:89, 109-111, 133-193`) but those are
threat-board heuristics, not a visual countdown widget. **This is a
genuinely missing surface.**

## 2. Gap

A player under attack has to:
1. Switch to the Intel tab.
2. Read the text line.
3. Mentally subtract `gameNow()` from the displayed `arrival` epoch.

The Intel tab is one click + one mental subtraction away from "is this
attack landing in 30s or 30m?". Plan 6.14 closes that gap with a small
floating widget that ticks the ETA down each second, sorted by arrival
(soonest first), with a colour escalation (green → yellow → red) as the
landing window approaches.

## 3. Design

Single widget, mounted via `gbWidget` (plan 6.2). Body renders one row per
incoming hostile movement, sorted by arrival ascending. Each row has:

```
[ETA mm:ss ticking] type → dest from origin [CS] [units summary]
```

Cells:

- **ETA cell** — `dodgeEtaSec(mov)` formatted `m:ss` (≥1h shows `1h 02m`,
  per `queueCenterFmt` pattern at `queue-center.js:55-60`, reuse it). Updates
  every tick.
- **type** — `mov.type || 'atk'` (lowercased canonical form already from
  `dodge.js:71`).
- **dest / origin** — `townNameById` (already a global helper used by
  `military.js:176`). Falls back to the raw id if the model is unreadable.
- **CS badge** — only when `mov.hasCs` (the existing flag from
  `dodge.js:73`). Colour: red `#c44` regardless of ETA, since CS is its own
  alarm.
- **units** — sum of `Object.values(mov.units).reduce(+)` for a quick
  "180" badge. Do **not** enumerate unit types in this widget — that is
  the Intel tab's job and the panel already shows it.

**Colour escalation** by ETA (CSS only, no logic changes to `intel.js`):

- `> 30 min` — `#6cf` (cyan, calm)
- `5–30 min` — `#fc6` (amber)
- `< 5 min` — `#f66` (red, pulses via CSS animation)
- `0` (landed) — row gets `.gb-widget-eta-landed` class, dimmed text,
  removed after 30s of absence (when `dodgeIncomingMovements` no longer
  returns it — the collection itself drops landed movements).

**Refresh cadence**: 1s, owned by the widget's `tickMs` (same as 6.11).
Per-tick cost: `dodgeIncomingMovements()` is **not** cached — it walks
`MM.getOnlyCollectionByName('MovementsUnits')` (`dodge.js:57`) every call.
The collection is small (one row per inbound/outbound movement, dozens in
practice) and the read is O(N) in JS object property access. Plan 8.3
profiler is not yet shipped; if it surfaces a hot spot, add a 1s memo
mirroring `TOWN_RES_CACHE_MS` (`bridge.js:234`). Out of scope here.

**Sort order**: by `arrival` ascending. `intelThreatBoard` does not sort
today (`dodgeIncomingMovements` returns in collection order). Add a sort
at the top of `render(host)`:

```
const sorted = threats.slice().sort((a, b) => (+a.arrival || 0) - (+b.arrival || 0));
```

Patch only changed rows (`textContent` writes are idempotent; the DOM
keyed-row pattern from `ui.js:92-101` keeps the row set stable across
ticks so a tick that adds a row does not blow away the user's widget
position).

## 8. Failure modes

- **`dodgeIncomingMovements()` returns empty**. Render `(sin entradas)`
  empty state, no crash. The Intel tab already handles this at
  `intel.js:84` — copy the wording.
- **`mov.arrival` is 0 or negative** (game-side race during collection
  refresh). `dodgeEtaSec` returns `0` in that case; render `0:00` and let
  the colour flip to "landed" — it disappears within 30s on its own.
- **Player owns >20 towns under attack**. Render only the first 20 rows;
  add an `+N más` line that links to the Intel tab (set
  `hostEnabled && showTab('intel')` on click — `showTab` is at
  `src/ui.js:353`). The widget body itself stays small.
- **SPA nav detaches the widget host**. Same as 6.2 §8: `ensurePanelMounted`
  (`src/boot.js:1-8`) is extended by 6.2 to re-append any missing widget
  host. No additional fix here.
- **Tab hidden, `setInterval` clamped to ~1 min**. The widget stops
  ticking — same as `renderTimers` and `updateStatus` (`boot.js:66-67`).
  Acceptable: ETA will catch up on the next visible tick. The widget's
  own `gbInterval` is subject to the same clamping; the SPA's
  `visibilitychange` handler at `src/boot.js:50-56` does **not** currently
  poke the widget — a follow-up could add a `gbWidget.refreshAll()` call
  there. Out of scope here.

## 9. Validation gate

Manual, per plan 27 §11 (Low risk). One in-game session on `es146`:

- Toggle `Ataques entrantes: widget visible` ON. Widget appears empty
  (no incoming on this world).
- Use the **Attack tab** `gb-atk-now` button (`src/ui.js:225`) to fire a
  test attack against an ally's town, then **switch perspective** to that
  ally's world (or test on a friend's account you control). On the
  receiving side, the widget shows one row within 1s, ETA ticks down.
- Wait until ETA < 5 min; row turns red and pulses. ETA = 0; row dims
  and disappears within 30s. Log shows no errors.
- Drag the widget, close, reopen. Position persists (6.2 contract).
- **Preflight**: `attack countdown` row green.
- **Cross-check Intel tab**: text-only threat board still renders the
  same incoming row (regression check on `renderIntel`, `src/intel.js:75`).
- **Negative**: with `state.dryRun = true` (`STORE.DRY_RUN`,
  `header.js:138`), the widget still renders — it does not post. Log
  shows the dry-run chip in the footer but widget content is unaffected.

  (`src/dodge.js:39`). Friendly traffic has its own row in the threat
  board.
- Mobile drag — defer with 6.2.
- Webhook firing on ETA-crossing thresholds. Plan 6.4 ("Desktop
  notifications + sound") already owns alert fan-out; do not duplicate.
