# 6.9 — Config import/export wizard

**Bucket:** v4.1 · **Risk:** Low · **Size:** M
**Module:** `src/qol.js` (pure prepare/validate/export helpers) + `src/ui.js` (wizard UI); both are existing MODULES slots in `build.py:61-70`
**Depends on:** 6.8 (so profile-auto rules are included as an optional section), 6.10 (import is one undoable config transaction)
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.8.2

## 1. What exists today

- Config JSON export already exists: `qolExportConfig` returns schema, config version, host, selected planner/queue/target/profile/template data, notes, and watchlist (`src/qol.js:223-252`). Plan 27 §9 therefore correctly marks the JSON mechanism CODED (`docs/plans/27-v4-wishlist-2026-08-10.md:239-263`).
- The current GUI is only two buttons in the Overview backup section (`src/ui.js:673-691`). Export serializes `qolRedactConfigDump(qolExportConfig())` to the clipboard (`src/ui.js:985-987`); import prompts for raw pasted JSON, parses it, and immediately mutates state (`src/ui.js:989-996`). There is no preview, field-selection, validation report, or cancel step.
- The redaction path is real and defaults to protecting player/alliance notes and watchlist values: `qolRedactConfigDump` leaves raw output only when `state.exportRedact === false`, otherwise replaces note keys/values and sets `redacted` (`src/qol.js:223-246`). The Config checkbox reflects that default (`src/core.js:339-347`, `src/ui.js:1311-1314`).
- `qolImportConfig` already refuses a different host and a newer schema, validates each known section, normalizes priority/build order/targets/queues, writes accepted sections, sets the current config version, disables legacy `autoFavor`, and logs a count (`src/qol.js:254-267`). It is an apply path, not a pure validator.
- The export allow-list does not include the webhook URL, Telegram chat id, CSRF, captcha state, learned bridge templates, or other transport state (`src/qol.js:248-252`; the corresponding sensitive keys exist separately in `src/header.js:54-65`, `src/header.js:61-62`, and `src/header.js:107-108`). This omission is part of the safety boundary and must remain true.
- The current Config tab is a large set of direct controls (`src/ui.js:706-843`) whose handlers mutate `state` and call `save` directly (`src/ui.js:1193-1291`, `src/ui.js:1364-1533`). The wizard must not pretend those controls are already covered by an import/export UI.

## 2. Gap

Replace the prompt-and-immediate-apply path with a local GUI wizard that produces a sanitized export, parses pasted JSON into a previewable candidate, reports host/schema/section errors before mutation, lets the user cancel or apply, and routes the final apply through the existing validated importer. It must not add cloud sync, a server, a download endpoint, or any secret-bearing export field.

## 3. Design

1. Add `qolPrepareConfigImport(rawOrObject)` as a pure helper in `qol.js`. Parse JSON if given text; require a plain object; enforce the existing host and schema ceilings (`src/qol.js:254-256`); run the existing per-section validators/normalizers without assigning `state`; return `{ok, sections, ignored, errors, candidate, sourceHost, schema, ver}`. Unknown keys are listed as ignored, never copied.
2. Keep the existing allow-list as the source of truth. Extend it only for the optional `profileAutoCfg` section from 6.8; do not add `webhookUrl`, `webhookEvents.telegramChatId`, CSRF, captcha breakers, learned templates, findings, decisions, or alert transport state. The raw export object remains internal until redaction has run (`src/qol.js:248-252`).
3. Add `qolExportConfigForUi()` that clones `qolExportConfig()`, passes it through the existing `qolRedactConfigDump`, and returns the sanitized object. Every copy/export button must use this helper; no UI code may stringify `qolExportConfig()` directly. The redaction OFF warning remains the existing throttled machine-log path (`src/qol.js:225-228`).
4. The wizard is a modal `<dialog>`-style panel built with the repository's existing DOM creation/string markup in `ui.js`; it has `Exportar`, `Importar`, `Copiar JSON`, `Pegar JSON`, `Validar`, `Aplicar`, and `Cancelar`. Export shows read-only sanitized JSON. Import shows section statuses (`válida`, `ignorada`, `inválida`) and a compact before→after diff based on the canonical config snapshot used by 6.10.
5. `Aplicar` requires a second confirmation and calls `qolImportConfig(prepared.candidate, {source:'wizard'})`; 6.10 records the pre-apply snapshot and supplies Undo. On success close the wizard, call `bindConfig`, `renderCaveTowns`, `renderDashboard`, and `updateStatus`; on failure keep the modal open with the exact error list.

## 5. State & storage

- No new persistent wizard state or id-bearing key is needed. The modal is transient DOM state; accepted config continues to use the existing `STORE.*` keys through `qolImportConfig` (`src/qol.js:256-267`).
- Do not add a new migration solely for the wizard. If 6.8 adds `profileAutoCfg`, its key and `configVer` migration remain owned by 6.8; the wizard accepts a missing optional section as “not supplied.”
- Do not persist pasted raw JSON, preview text, clipboard data, webhook URLs, Telegram chat ids, CSRF, or learned templates. Storage scope and versioning remain those of the existing keys (`src/header.js:193-215`).

## 6. Config surface

- Existing buttons keep their Spanish labels: `Exportar configuración` and `Importar configuración` (`src/ui.js:690`). Add the wizard labels `Copiar JSON seguro`, `Pegar JSON`, `Validar`, `Aplicar configuración`, and `Cancelar`.
- The existing `Redact names/ids in Copy + Export` checkbox remains default ON (`src/core.js:339-347`, `src/ui.js:788`); the wizard must visibly warn `Redacción desactivada: el JSON puede contener nombres` when it is OFF, but must never add secrets to the export.
- No new automation toggle is introduced here; no `configVer` bump is required unless the export schema is changed for the 6.8 section. A schema bump is separate from `configVer` and must be documented in the helper constant (`src/qol.js:223`).

## 7. Post surface & safety

No post surface: import/export is local clipboard/DOM work and has no route, payload, `gbAjaxWatch`, `TPL_FEATURE_MAP`, `gbCaptchaPause` feature key, or lock. The wizard must not use `gbDomClick`, `bridgePost`, `gameAjaxPost`, or any network API; this preserves the paste-only/no-server boundary (`CLAUDE.md:40-49`, `CLAUDE.md:252-255`). An imported setting may enable an existing loop, but the validated import preserves the existing `dryRun` value unless the accepted config explicitly contains it, and all resulting writes remain behind existing transaction gates (`src/qol.js:254-267`, `src/tx.js:531-555`).

## 8. Failure modes

- Invalid JSON, arrays, non-object roots, a different host, or a schema newer than supported stops at `Validar`/`Aplicar`; no `state` or storage mutation occurs (`src/qol.js:254-256`).
- Invalid sections are shown as `ignorada: <key>` and omitted exactly as the current importer does (`src/qol.js:256-267`). A valid file with zero accepted sections cannot be applied.
- A malicious or accidental secret field is unknown and ignored. Export safety is enforced by the allow-list plus `qolRedactConfigDump`, not by hiding a field in the modal (`src/qol.js:223-252`). Never display a raw webhook/Telegram value in the diff.
- A quota failure is handled by the existing `save` prune/retry path (`src/core.js:1130-1213`); the wizard reports apply failure and does not claim success. The precondition invariant still applies to any existing write-capable setting: every guard names the value read; unreadable getter ⇒ `blind` ⇒ `gbLogT` once ⇒ let the server decide (`src/core.js:298-309`).
- A dropped callback is irrelevant because there is no asynchronous game request. Clipboard rejection is a UI error only; leave the sanitized JSON visible for manual copy.

## 9. Validation gate

Low risk requires Preflight plus one in-game session with no failure (plan 27 §11). Open Overview → `Exportar configuración`, confirm the displayed/copyable JSON contains `redacted:true` and no webhook URL, Telegram chat id, CSRF, learned template, or raw player/alliance names (`src/qol.js:223-252`). Paste a valid same-host JSON, click `Validar`, verify section statuses and diff, then click `Cancelar` and confirm exported config is byte-equivalent. Reopen, `Aplicar configuración`, verify the Log `config imported: ... validated section(s)`, controls persist after reload, and Undo from 6.10 restores the prior snapshot. Paste malformed JSON, a different `host`, a future `schema`, and an invalid section; each must show an error, send no request, and leave state unchanged. Run Stats → Preflight once after applying; no new post or `UNREADABLE` error may appear.

## 10. Out of scope

No cloud sync, REST/WebSocket endpoint, webhook export, credentials, automatic import, arbitrary JavaScript conditions, plugin system, or test harness. Existing JSON validation/redaction is not rewritten into a new transport; this is a GUI delta over `qolExportConfig`/`qolImportConfig` (`src/qol.js:248-267`). Profile rule semantics belong to 6.8; undo/redo transaction/history belongs to 6.10.
