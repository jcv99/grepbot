# 3.5 — Emergency cave mode

**Bucket:** v4.5 · **Risk:** High · **Size:** L
**Module:** new `src/emergency.js` (slot after `culture.js`, before `trade.js` in `build.py:31-72`)
**Depends on:** 5.3 threat assessment engine (a no-op when eta is null reads as 0, plan 27 §5), `cave.js` `caveTownInfo`, `cave.js` `caveStoreIron`
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.8.2

## 1. What exists today

- `cave.js:166 caveScan(reason)` fires from `orchTick` (`orchestrate.js:4`,
  via `ORCH_HANDLERS`) and stashes iron when `state.autoCave` is on AND
  iron ≥ `state.caveThreshPct` (default 90, `core.js:288`). Toggle default
  OFF per HIGH-RISK convention (`core.js:287`). Cadence is the orchestrator
  cadence — `ORCH_CADENCE.cave` plus ±20% jitter (`orchestrate.js:115-119`).
- `cave.js:133-140 caveStoreIron(townId, amount, onDone)` posts
  `{model_url: 'BuildingHide', action_name: 'storeIron', arguments:{iron_to_store:+amount}, town_id:+townId}`
  via `bridgePost('cave', ...)`. The payload is **hardcoded** — no learned
  template, no `TPL_FEATURE_MAP` slot. Path-sniff is unnecessary here; the
  schema is set by us.
- `cave.js:26 caveTownInfo(townId)` returns `{hideLvl, iron, cap, hideCap,
  stored, unlimited}` and the `BuildingHide` model probe (`cave.js:62-68`).
  `cave.js:114 caveExcessAmount(info)` returns the iron that's currently
  past the threshold and still fits the hide, or `0` for `unreadable`.
- `dodge.js:53 dodgeIncomingMovements()` is the trusted hostile-source
  funnel — every incoming must pass `dodgeIsHostileMovement` (dodge.js:41,
  the v1.5.3 audit fix). It yields `{id, dest, origin, type, hasCs, arrival,
  units, model}` per movement. `dodge.js:181 DODGE_MILITIA_WINDOW_SEC =
  15*60` is the parallel "ETA < 15min means imminent" anchor for militia;
  same constant should gate emergency cave auto.
- Per-town gating already exists: `cave.js:1 caveTownEnabled(townId)` and
  `cave.js:7 setCaveTownEnabled(townId, on)`, persisted on
  `STORE.CAVE_TOWNS` (world-scoped, `header.js:201`).
- `core.js:685 ironReservedForCave(townId)` is the cave-first claim on iron
  (plan 08, CODED). Culture and trade already honor it (`culture.js:140`,
  `trade.js:217-218`). Emergency stashing does **not** need to register
  here — emergency is *more* conservative than the threshold path, never
  less.
- A captcha feature key already exists for the threshold path:
  `captchaPaused('cave')` is read at `cave.js:167`. `gbAjaxWatch(sig,
  settle)` (`bridge.js:7`) is registered automatically by `bridgePost`.

There is **no** `src/emergency.js` and **no** emergency stash path today.
A grep for `emergency|panic|imminent|storeAll|emergencyStash|panicStash`
across `src/` returned zero matches. The only "Stash NOW" affordance is
the toggle itself (`ui.js:1286-1289`, which calls `caveScan('toggle')` on
ON, but offers no manual one-shot).

## 2. Gap

Auto-cave walks the threshold on the orchestrator cadence; in a raid the
threshold may not be reached before the attacker lands, and even when it
is, a cadence-shaped delay can leave several hundred silver as loot to
the attacker. The user has no one-shot "stash what is here, now, ignoring
the threshold" affordance, and no auto path that watches incoming
movements to pre-stash ahead of a high-risk landing.

## 3. Design

Two coordinated pieces, separate toggles, in one new module:

1. **Manual "Stash iron now" button.** Fires `bridgePost('cave-emergency', …)`
   once per town meeting the unconditional criteria. Reads from the same
   `caveTownInfo`/`caveExcessAmount` path; **does not** consult the
   threshold, but **does** honour `caveTownEnabled` and captcha + lock
   + dryRun (via `tx.js:531`). Per-town one-shot; logs the action;
   confirms only if iron > `state.emergencyCaveConfirm = 1000` (Config).
2. **Auto path.** Subscribes to `dodgeScan`'s incoming stream **via the
   existing `dodgeScan` loop** (panel + production both run the same
   function; the production scanner is the only one that touches the
   bridge — there is no separate panel-only path). The same function
   consults `dodgeIncomingMovements()` and, when the per-town risk is
   high, calls `emergencyStoreNow` on the destination town. **No new
   `gbInterval` / `setTimeout` cadence** (README Hard rule #4); the
   watch rides the already-shipping 5s `gbInterval(dodgeScan)` at
   `boot.js` and inherits its full jitter / orchestrator-aware pause
   semantics.
   - Gating, ALL must hold: `state.emergencyCaveAuto === true`,
     `hostEnabled()`, `!automationPaused({})`, `!captchaPausedAny('cave',
     'dodge')`, `!gbLocked('cave-emergency')`,
     `dodgeEtaSec(mov) != null && dodgeEtaSec(mov) <= DODGE_MILITIA_WINDOW_SEC`,
     `defenseAssessment(mov).risk >= 35` (matches `defenseShouldDodge` at
     `wonder.js:145`),
     `!dodgeSafeTown(mov.dest)` **or** all destinations have iron over
     threshold (decision parity with `defenseShouldDodge`),
     `caveTownEnabled(mov.dest)`, `caveTownInfo(mov.dest).hideLvl >= 1`,
     `caveTownInfo(mov.dest).iron >= 50` (don't break the lock on a town
     that has no meaningful iron to save).
   - Per attack: stash once. The auto path tracks `state.emergencyLastStash`
     keyed by `mov.id` so the same incoming cannot fire twice (TTL = the
     movement's `arrival_at`, plus 10 minutes).

## 5. State & storage

- `state.emergencyCaveAuto` — bool, default `false`, NOT world-scoped
  (urgency policy is per-user). Add `STORE.EMERGENCY_CAVE_AUTO` constant to
  `src/header.js:24-187` `STORE` object; do **not** add to
  `WORLD_SCOPED_BASES` (`header.js:193-215`) since the key is policy, not
  a world payload.
- `state.emergencyCaveConfirm` — integer (default `1000`), persistent
  per-user. Same scope call as above; add `STORE.EMERGENCY_CAVE_CONFIRM`.
- `state.emergencyCaveMinIron` — integer (default `50`), per-user. Scope
  call: `STORE.EMERGENCY_CAVE_MIN`. UI default input `50`.
- `state.emergencyLastStash` — `{[movId]: {townId, ts, expires}}`, TTL
  mirrors the movement's `arrival_at + 10min`. Scope: `STORE.EMERGENCY_LAST`,
  **world-scoped** (`WORLD_SCOPED_BASES`), because two worlds are
  independent incoming streams and a town-id-stamped ledger across worlds
  is meaningless. Migration code (defensive): if a saved `emergencyLastStash`
  has townIds that don't exist on load, drop them in
  `emergencyLastStashPrune()` at boot.
- `state.configVer` must bump from `CONFIG_VER_CURRENT = 10` to `11` in
  `src/header.js:191` so existing installs re-render the new Config rows.
- No prune TTL needed beyond the per-record `expires` (storage never grows
  past a wave's worth of IDs).

## 7. Post surface & safety

- Bridge-first: every emergency post goes through
  `caveStoreIron → bridgePost('cave-emergency', payload, cb)`
  (`cave.js:133-140`, label `feature` becomes `cave-emergency`).
- `gbAjaxWatch(sig, settle)` is registered automatically by `bridgePost`
  via `bridge.js:131-142`. No new sig registration required.
- The `'cave-emergency'` template key is **not** added to `TPL_FEATURE_MAP`
  (`core.js:778-790`): the payload is hardcoded (`cave.js:135-138`), so
  `tplNameFor('cave-emergency', payload)` returns `undefined` and the
  learned-payload health gate is bypassed for this feature. Documented
  intent: hardcoded payloads do not go stale.
- `gbLock('cave-emergency', 60000)` (`GB_LOCK_TTL` lookup; add
  `'cave-emergency': 60000` to `core.js:145-173`). Distinct from `'cave'`
  (cave.js:194 already locks `'cave'` at 180000) so a regular cave stash
  is never blocked by emergency and vice versa.
- `gbCaptchaPause` feature keys (`bridge.js` existing registry): the
  existing check is `captchaPausedAny('cave', 'dodge')` (cave.js paths),
  extend to `captchaPausedAny('cave', 'cave-emergency', 'dodge')`. The
  breaker itself is invoked from `responseIsCaptcha` (bridge.js:113) — no
  new code needed there, the trip function already keys off `feature`.
- Dry-run honoured automatically: `tx.js:531` short-circuits writes when
  `state.dryRun`. Auto path is gated on `txActionGate` via `bridgePost` →
  `txRun`, manual button goes through the same wrapper.
- Manual click → `confirm()` if the iron total is > `emergencyCaveConfirm`.
  No proceed without user click for amounts > threshold.

## 8. Failure modes

- `caveTownInfo` returns `null` or `unlimited: true` — `caveExcessAmount`
  already handles this safely (cave.js:114-131): `null` info → amount `0`,
  `unlimited: true` → only limited by warehouse headroom, no per-stash
  cap check. The auto path's `caveTownInfo(...).iron >= 50` guard still
  applies. `unreadable` is `null` from `getEspionageStorage`, treated as
  unknown; **never block**.
- `dodgeIncomingMovements()` returns no model (game bridge not ready) →
  `gbLogT('cave-emergency-nobridge', 60000, …)` and bail, never blind-fire.
- `caveStoreIron` `timeout` — already handled in
  `txRun`/`bridgeRaw`: 15s timeout, post stays journaled as
  `timeout_unknown`; entry is **not** removed from `emergencyLastStash`
  but a fresh toggle-ON cycle is required to retry. This is the correct
  failure posture for irreversible iron loss (mirrors militia at
  `dodge.js:200-201`).
- A town is simultaneously the destination of two incoming attacks — fire
  once for the first, `state.emergencyLastStash[movId]` blocks the second
  from looking like a new event. With separate `movId`s the second is
  allowed; check that `mov1.id !== mov2.id` (the ID is opaque per-movement;
  the game assigns unique per-movement command_ids).
- A user lands on the `dryRun` Config toggle with `auto-cave` already on,
  then enables `emergency-cave-auto`. The first wave arrives. The auto
  path posts hit the dry-run gate, log shows `DRY-RUN cave-emergency: …`
  and a flood of `skip:dryrun` in the journal. That's the correct UX
  (the same way auto-cave would behave).

## 10. Out of scope

- Auto-stash on neutral / friendly incoming (those are filtered by
  `dodgeIsHostileMovement` — keep that filter; only flip the militia /
  dodge path when the incoming is canonically hostile).
- A "drain all gold into the cave" path (different resource, different
  payload — see plan 03 for the wider alliance-resource-pool view).
- Predicting raid vs full-scale attack from the army composition — we
  can't read incoming composition without a counter-spy, and counter-spy
  is its own feature (plan 4.2). Plan 5.4 covers prediction-by-type-string.
- Cooperating with the watchdog from plan 03 / plan 02 — until the wider
  intelligence surface lands, emergency cave is a pure local reaction.
