## 2. Gap

Plan 27 §4 row: *assign / stamina / equipment / notifications*. The `assign`
column is **done by hand** (transfer coded; see §1). The other three columns
are absent — verified by ripgrep over `src/`: `stamina|heroMana|energy`,
`equipment|inventory|items|gear|slot`, and `autoHero|heroTick|heroScan` all
return zero hits. There is also no `alertWebhook('hero', …)` call anywhere
(`state.webhookEvents` at `src/core.js:313` has `{captcha, attack, warehouse,
culture}`; no `hero` key). The Med-risk surface this plan ships: (a) a read-
only **stamina / mana / equipment panel** in the Attack-tab hero row, (b) an
**equipment swap heuristic** that only proposes moves (never discards), (c) a
**low-stamina notification** wired through `alertWebhook('hero', …)`, and
(d) an **auto-assign loop** behind `state.autoHero` (default OFF) that
requires a per-tick user confirm via the existing `opts.confirmed` opt — same
shape as `dodgeScan` smart-auto (`src/dodge.js:196,261`).

## 3. Design

- **Read: stamina + mana + equipment** — extend `playerHeroesList` to also
  read each model's stamina/mana/equipment. The model's getter names are
  **unknown** until a hand-click is sniffed; §4 item 1 captures the sniff.
  Every field returns `null` when its source getter is `undefined` or a non-
  finite number — precondition invariant, never a block.
- **Read: equipment slots** — same source. Slot ids and item ids are
  **unknown**. Store the raw snapshot per world as
  `state.heroEquip[heroType] = {slots: {…}, items: […]}` for diffing.
- **Decision (heuristic)**: when a hero carries a low-tier item in a slot
  whose **known** upgrade is held by another (free) hero in the same world,
  propose a swap. **Never discard**: the heuristic never moves an item to a
  vault / sale / unknown destination. The proposal lives in
  `state.heroEquipSuggest` and surfaces as a row in the Attack-tab panel.
- **Decision (auto-assign)**: behind `state.autoHero` (default OFF). On every
  `orchTick` (5min cadence), `heroScan()` picks the lowest-fill owned town
  for each free hero and calls `heroAssignToTown(type, tid, {confirmed:
  false}, …)`. The handler short-circuits at `src/military.js:143` and the
  panel surfaces the proposal as a click-to-confirm button; the next tick
  posts via `{confirmed: true}`.
- **Notification**: when stamina ≤ `state.heroLowStaminaPct`% of max,
  `alertWebhook('hero', …)` fires + Log-tab one-liner. Throttled by
  `alertWebhookKey` (`src/alerts.js:19-27`); 5min/webhook rate-limit at
  `src/alerts.js:44`. Captcha-pause key `'hero'` already exists, no new key.
- **Cadence**: `ORCH_HANDLERS.hero` at 5min, no `gbInterval`. Add `'hero'`
  to `PRIORITY_ORDER_DEFAULT` (`src/header.js:189-190`).
- **Dry-run**: `bridgePost` honours `state.dryRun`. `heroScan` posts only via
  `heroBridgePost`, so dry-run coverage is automatic.

## 8. Failure modes

- **Stamina / mana getter returns `undefined`** — surface `null`, never
  block. Panel renders `stamina -/-`; notification path treats the field as
  missing (no `low-stamina` event). Precondition invariant: a check may only
  block on a value it actually read. (CLAUDE.md "Precondition readers".)
- **Equipment slot ids change between client builds** — heuristic returns
  empty proposal list. Preflight `hero stamina readable` emits `warn` when
  no hero exposes stamina; `fail` only when the capture exists AND the live
  model disagrees.
- **Captcha response on auto-assign** — `captchaTrip('hero', …)` from
  `bridge.js` classify path; `heroBridgePost` rejects for the ladder
  duration. `heroScan` short-circuits via
  `captchaPausedAny('hero','attack')` at the top of its handler.
- **`state.dryRun` true + an auto-assign tick** — handler emits
  `skip:dryrun` via `bridgePost` and `gbLog('DRY-RUN hero: …')`. No payload.
- **Bfcache / mobile exit mid-transfer** — `gbLock('hero')` carries TTL +
  `pagehide`/`beforeunload` call `gbUnlockAll()` (CLAUDE.md "Lock registry").
  A stranded `heroTpl` entry is read-only and never posted — the resolver at
  `src/military.js:117` matches `tpl.action_name === action` and aborts on
  mismatch.
- **World switch** — `state.heroEquipSuggest` and `state.heroTpl` are both
  world-scoped (`src/header.js:200` + §5); previous-world proposals do not
  leak.

## 9. Validation gate

Manual, per plan 27 §11 Med-risk class.

1. **Dry-run parity** — `state.dryRun = true`, `state.autoHero = true`, one
   free hero + one town selected. Trigger an `orchTick` (or wait 5min).
   Log shows `hero: auto-assign proposed <name> -> <town>` once; the per-
   tick confirm button reads `Asignar (dry-run)`; `bridgePost` never fires.
   Stats budget does not move.
2. **Live single transfer** — `state.dryRun = false`, one free hero. Click
   `Asignar`; `confirm()` fires, `heroBridgePost` logs
   `hero: assignToTown <type> -> <town> OK`, `txReconcileNow` returns
   `'applied'` once the model's `assigned` flips. Stats probe
   (`src/stats.js:219-223`) still lists `assignToTown`.
3. **Auto-assign with confirm gate** — `state.autoHero = true`. Log shows
   `hero: auto-assign proposed …` every 5min; clicking the proposal posts
   once, then `state.autoHero` does **not** fire again until the hero is
   unassigned. No double-post. `gbSkip('hero', 'auto-need-confirm')` row
   exists for each skipped tick.
4. **Stamina notification** — `state.heroLowStaminaPct = 80`. Wait for a
   hero's stamina to drop below 80% (or hand-edit `state.heroStaminaCache`
   in DevTools for one tick). Log shows `hero: low-stamina <name> <pct>%`.
   Webhook fires once per `(hero, reason)` per 5min
   (`alertLastSent` throttle at `src/alerts.js:44`).
5. **Equipment heuristic** — `state.heroEquipSuggest` populates only when
   two heroes' slot maps are both readable AND a tier difference exists.
   Preflight `hero equipment readable` returns `warn` until
   `archive/captures/hero-attrs.json` exists. With the capture present, two
   free heroes whose slot maps differ produce exactly one
   `state.heroEquipSuggest` row.
6. **HIGH-RISK OFF default** — fresh install (or after `qolResetConfig`):
   `state.autoHero === false`. Config row unchecked.
   `state.dryRun` covers the feature even when ON.

## 10. Out of scope

  heuristic only, NEVER discard". A future "vacate slot" plan would need a
  separate endpoint sniff.
- **Skill / spell selection** — hero ability automation is a different
  surface; belongs with divine-spell automation (4.4) or a future
  hero-skills plan.
- **Auto-recruit while traveling** — not part of hero manager; auto-recruit
  lives in `src/recruit.js` behind its own toggle.
- **Auto-assign while injured** — `playerHeroesList` returns
  `injured: true` (`src/military.js:101`) and `heroAssignToTown` rejects
  with `'injured'` (`src/military.js:147`). Reused as-is; no new code.
- **Hero XP / level-up notifications** — `level` already read
  (`src/military.js:105`); an XP-tracking plan needs a separate capture and
  is deferred.
- **Item swap post route** — payload unknown. Captured in the sniff file
  but not actioned here. Belongs in a future equipment-automation plan.
