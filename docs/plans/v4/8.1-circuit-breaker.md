## 1. What exists today

A per-feature breaker is **already coded**, hidden in `planner.js` under the name `circuit*` and called from the write path in `tx.js`. Evidence:

- `planner.js:170` `CIRCUIT_TRIP = 3`; `:171` `CIRCUIT_STRUCTURAL_RE` (a regex that fires on `unknown.?action|invalid.?action|unknown.?model|...|endpoint.?not.?found`).
- `planner.js:172-208` `circuitSave` / `circuitState` / `circuitOpen` / `circuitNote` / `circuitSuccess` / `circuitClear`. State shape: `state.circuits[feature] = { strikes, open, openedAt, lastError, lastAt }`.
- Persisted via `STORE.CIRCUITS` (`header.js:146`), loaded as `state.circuits = load(STORE.CIRCUITS, {})` (`core.js:350`), normalised in the v3 migration (`core.js:412`), and whitelisted in `WORLD_SCOPED_BASES` (`header.js:209`).
- **Callers — only on the WRITE path.** `tx.js:528` `txActionGate`: if `write && circuitOpen(feature) → 'circuit-open'`. `tx.js:587/589` and `:661/674/686`: `circuitSuccess` on `ok`, `circuitNote` on hard err. `bandit.js:149`: explicit `circuitSuccess('bandit')` after bridge success. `build-auto.js:268` and `:231`: `circuitOpen('build')` short-circuit. `collect.js:29`: `circuitOpen('collect')` short-circuit.
- Surfaced in `stats.js:261-263` (Preflight `guards` row: `OPEN circuits: …`), `stats.js:251-266`, `ui.js:1833/1849` (footer pauseInfo carries `circuits: openCircuits`), `qol.js:146/149/164/170/177/182` (Overview health panel), and a manual `GrepBot: clear circuit breakers` menu entry at `ui.js:2018-2024`.

What is **also already there but narrower** — the farm scrape endpoint breaker from plan 26 §A1 work item 1, coded:

- `state.farmScrapeState = { dead: false, misses: 0 }` loaded at `core.js:243`, persisted via `STORE.FARM_SCRAPE_STATE` (`header.js:181`).
- `farms.js:652-689` `farmScrapeState` / `farmScrapeSaveState` / `farmScrapeEnabled` / `farmScrapeClearErrors` / `farmScrapeNoteSweep` / `farmScrapeRevive`. `FARM_SCRAPE_DEAD_SWEEPS = 2` (`farms.js:650`).
- Hooked at `farms.js:869` (`farmScrapeNoteSweep(ok)` after each sweep), at `farms.js:720` (`farmScrapeRevive` on a real `learnFarmAction`), and at `ui.js:1244-1245` (Config toggle ON → revive, OFF → clear errors). Surfaced in `stats.js:38-50` (Preflight `farm resource scrape` row).
- The two breakers do **not** overlap: `state.circuits` fires on bridge structural errors, `state.farmScrapeState` fires on the village-resource **HTTP scraper** returning 0 OK across two sweeps. Plan 26 §A1 names this distinction explicitly: "the breaker was waiting for a real action from the player's own traffic."

What is **absent**:

- **No breaker on READ paths** (`gbXhr`, scrapes). Plan 26 §A1 names one for farms; nothing generalises it to town scrapes (`towns.js:101-149`, 6-deep `TOWN_ACTION_GUESSES`), report catch-up (`spy.js:117-163`, `fetchReportHttp`), CSRF hunt (`core.js` around `huntCsrf`), or phoenician view sniff.
- **No breaker on bridge NON-structural errors** (timeout, captcha). `circuitNote` (`planner.js:184`) ignores `timeout`/`captcha`/`captcha-pause`/`timeout_unknown` — that is the right call today (own breakers own them), but a feature like `phoenician` whose endpoint silently dies without producing a structural message has no protection.
- **No Config surface.** `CIRCUIT_TRIP` is a hardcoded constant (3); the threshold cannot be tuned. There is no per-feature override, no auto-recovery probe cadence, and no max-open-time before forced half-open.
- **No half-open probe.** Once a circuit opens it stays open until `circuitSuccess(feature)` fires (`planner.js:198`) — but `circuitSuccess` only resets `strikes`, never clears `open`. The only path that closes an open circuit today is the manual `circuitClear` from `ui.js:2020`. A long-running feature can stay disabled until the user notices.
- **Stats only shows "OPEN circuits" by name** (`stats.js:263`); it does not show how long each has been open, what the last error was, or how many strikes it has accumulated.

The journal skip mechanism plan 27 cites (decision-memory at `journal.js:31-247` with `JRN_FAIL_TRIP=3` `bridge.js:450`, `JRN_BACKOFF=[5,15,60]` `bridge.js:451`) is **adjacent but separate**: it gates the **same feature+action+target** for 5/15/60 min on per-target errors, while the circuit breaker gates the **whole feature** on structural errors. The two compose: a `circuit-open` rejection in `txActionGate` (`tx.js:528`) is journaled as `skip:circuit-open` (`journal.js:16`, `JRN_SKIP_ERRS` at `bridge.js:457-466`) and short-circuits future posts.

## 2. Gap

The catalogue promises a generic per-module breaker that **extends the journal skip mechanism**. The reality is that the breaker already exists in a tighter form (per-feature, structural-error only, write-path only, manual clear only). The remaining work is (a) generalise it to **read paths and silent-endpoint failures**, (b) add **half-open probing** so a feature can recover without a manual click, (c) **expose thresholds** in Config, and (d) **show richer state** in Preflight so the user can see *why* each circuit is open.

This plan explicitly generalises plan 26 §A1's farm-specific breaker (`state.farmScrapeState`, `farms.js:652-689`) into the per-feature registry rather than replacing it: the farm scrape breaker is an HTTP-scrape specialisation, not a write structural-error breaker, and the two coexist with `farmScrapeNoteSweep` calling `circuitNote` would be a category error. The plan leaves `state.farmScrapeState` in place and adds a parallel generic mechanism for the other read paths that today lack any breaker.

## 3. Design

One shared registry (`state.circuitBreakers[feature] = { state: 'closed'|'open'|'half-open', strikes, lastError, lastAt, openedAt, halfOpenAt, probeFailures }`) backed by a new `STORE.CIRCUIT_BREAKERS` key. The existing `state.circuits` shape (closed-via-strikes, opens-on-3) is **migrated** into the new shape on first load — `state.circuits` stays as a read-cache used by the existing call sites, so nothing in `tx.js:528` / `build-auto.js:231` / `collect.js:29` / `bandit.js:149` changes.

- **State machine.** `closed` (normal) → on Nth structural error within W → `open` → after `cooldownMs` → `half-open` (next attempt becomes a probe; success → `closed`, failure → `open` with `cooldownMs *= 2`, capped at 1h).
- **Trigger.** `circuitNote(feature, err)` (already at `tx.js:589,674` and `planner.js:181`) becomes the only write path; **plus** a new `circuitNoteRead(feature, err, ok)` for read paths called from `gbXhr` failures in `core.js` (around `:1233-1236` `failEarly`) and from per-loop result handlers (`farms.js:869`, `towns.js` scrape result).
- **Recovery.** A `gbInterval`-free sweeper (`gbTimeout` chain, `setInterval` would conflict with the "no new schedulers" rule) inside `boot.js`'s existing `gbInterval(gbLockSweep, 10000)` line (`boot.js:124`) — half-opens any circuit whose `cooldownMs` has elapsed. The next post attempt then re-tries the endpoint naturally (no new probe scheduler).
- **Stats.** `stats.js:261` `OPEN circuits:` line grows to `OPEN farm:no-endpoint 12m (no data) · scrape:town 4m (404)` — name, age, lastError first 40 chars.
- **Config.** New Config section "Cortacircuitos" with `circuitTripN` (default 3), `circuitCooldownMin` (default 15), `circuitReadEnabled` (default OFF — read breakers are noisy), `circuitAutoClear` (default ON — sweep half-open after cooldown).

Data flow: `bridgePost → txRun → txActionGate` (unchanged; reads `state.circuits[feature].open` via `circuitOpen`); on err: `circuitNote` updates `state.circuits`; every save call (existing `jrnSave` at `journal.js:104` / `txSave` / per-feature saves) piggy-backs a `circuitBreakerSave()` write that goes through `save(STORE.CIRCUIT_BREAKERS, …)`. The 10s `gbLockSweep` line in `boot.js:124` also calls `circuitBreakerSweep()`.

- New `CONFIG_VER_CURRENT = 11` (`header.js:191`); new v11 migration step copies old `state.circuits` into `state.circuitBreakers`.
- `state.circuits` is **kept** as a back-compat mirror written by `circuitSave` (existing call sites keep working). Prune TTL: never (a circuit's `openedAt` lives until `circuitSuccess`/`circuitClear`).
- No prune of `state.circuitBreakers` — entries age out via `circuitSuccess` reset and `circuitClear` clear. Total size: bounded by feature count (~14 features per `PRIORITY_ORDER_DEFAULT` at `header.js:189`) × ~80 bytes ≈ <2 KB. Well under the 5 MB GM budget (`docs/plans/20-storage-quota-alarm.md`).

## 6. Config surface

| Field | Type | Default | Notes |
|---|---|---|---|
| `circuitTripN` | int 1-10 | 3 | Strikes before opening. Overrides the hardcoded `CIRCUIT_TRIP=3`. |
| `circuitCooldownMin` | int 1-120 | 15 | Minutes before an open circuit becomes half-open. Doubles on probe failure, capped at 60. |
| `circuitReadEnabled` | bool | **OFF** | Read-path breakers (`towns-scrape`, `spy-catchup`, `phoenician-view`). OFF because they are noisy and the manual reset is faster than a tripped auto-breaker. |
| `circuitAutoClear` | bool | ON | The 10s sweep half-opens eligible circuits. OFF = manual `GrepBot: half-open all circuits` only. |

HIGH-RISK OFF default applies **only** to `circuitReadEnabled` (read breakers trip on benign noise); the others are tunables, not autonomy. **Do not** add a "force-open" / "force-close" toggle — that would re-introduce a phone-home remote flag (plan 27 §0 dropped that idea).

## 7. Post surface & safety

This is a **read-mostly** feature: no new bridge posts, no new `bridgePost`/`gameAjaxPost` calls, no new `gbAjaxWatch(sig, settle)` registrations, no template additions to `TPL_FEATURE_MAP` / `tplNameFor`. The breaker only **gates** existing posts; it does not create any.

- `gbCaptchaPause` feature key: not needed (no new post surface).
- `gbLock` name + `GB_LOCK_TTL` entry: not needed (no in-flight coordination).
- Dry-run: not applicable (read-only infrastructure).
- **Bridge-first**: irrelevant — no new transport.

## 8. Failure modes

- **Breaker trips on a transient blip.** A user-configured `circuitTripN=1` would open a circuit on a single error. Default 3 absorbs this; the Config input enforces min=1 to allow tuning but the default is the safe value.
- **Auto-clear (`circuitAutoClear` ON) opens a circuit that is still genuinely broken.** The half-open probe will hit the same dead endpoint; `probeFailures` doubles `cooldownMs` up to 1h. After 3 probe failures the circuit stays open until `circuitClear` (manual) or until the next `ok` arrives. This is the correct behaviour — auto-retry storms are the failure mode this plan prevents.
- **`circuitReadEnabled` OFF but a read path keeps hammering the budget.** The Preflight `guards` row (`stats.js:263`) shows the open-circuit count; if it grows, the user flips the toggle ON. Plan 26 §A1 explicitly recommends the breaker over an un-throttled scraper.
- **`state.circuitBreakers` shape diverges from `state.circuits` after a partial migration.** The migration in work item 2 is a one-shot copy in v11; after it runs the two mirrors are kept in sync by every write through `circuitSave`. A `console.warn` from `loadValueOk` (`core.js:1101`) on size >2MB catches accidental divergence (a feature that writes huge `lastError` blobs).
- **Unreadable breaker state ⇒ blind.** `circuitOpen` (`planner.js:177`) returns `false` when `state.circuitBreakers[feature]` is missing or unparseable — the safe default is "act as if closed". A log entry via `gbLogT` (`core.js`'s logger, journal.js:215 shows the pattern) once per 60s prevents log spam.
- **Precondition invariant**: the breaker checks `state.circuitBreakers[feature].state` (read value), never a derived field. The half-open flip reads `Date.now()` (read value) against `openedAt + cooldownMs` (computed from read values). No guard depends on a value that wasn't read.

## 9. Validation gate

Low risk per plan 27 §11. Per Low gate: Preflight + one in-game session, no failure.

1. **Preflight `circuit breakers` row** renders with `0 open, 0 half-open, autoClear ON, trip 3, cooldown 15m` on a fresh install.
2. **Triggered trip:** in DevTools console: `GB_ROOT.__grepbotTest` (exposed at `boot.js:147-160` test hook) — call `circuitNote('bandit', 'unknown action')` three times. Preflight re-run shows `OPEN bandit 0m (unknown action)`. Footer badge shows `⚡circ:1`.
3. **Half-open recovery:** wait 15 min (or temporarily set `circuitCooldownMin=1`). Re-run Preflight: `half-open bandit 15m`. Cause one bandit success (`bandit.js:149` calls `circuitSuccess` on success path) — circuit closes, badge clears.
4. **Read breaker disabled by default:** with `circuitReadEnabled` OFF, simulate 10 dead `towns-scrape` reads — Preflight shows no circuit. Flip ON, repeat — circuit opens after 5 misses (`CIRCUIT_READ_TRIP`), confirming the toggle works.
5. **Manual reset:** `GrepBot: clear circuit breakers` confirms the dialog (`ui.js:2020`), clears the registry, Preflight shows `clear`.
6. **Back-compat:** with a persisted `state.circuits = { build: { strikes: 3, open: true, lastError: 'unknown action' } }` from a pre-v4.1 install, the v11 migration writes an equivalent `state.circuitBreakers.build = { state: 'open', … }`; `circuitOpen('build')` still returns true; `tx.js:528` still rejects writes with `skip:circuit-open`.

## 10. Out of scope

- **Auto-recovery via captcha-bypass / server-side probe.** Plan 27 §0 dropped those. This plan only opens/closes based on observed POST results, never invents a probe.
- **Replacing `state.farmScrapeState` (`core.js:243`, `farms.js:652-689`).** Plan 26 §A1's farm-specific breaker is an HTTP-scrape specialisation (counts 0-ok sweeps, recovers on `learnFarmAction`); the generic breaker here counts structural-error strikes per feature. Work item 7 calls `circuitNoteRead` **in addition to** the existing `farmScrapeNoteSweep`, so both still fire on the same dead scrape. Migration away from the farm breaker would break the `learnFarmAction` revive hook at `farms.js:720`.
- **Decision-memory skip windows** (`journal.js:172-247`, `bridge.js:450-451`). Plan 27's "extends the journal skip mechanism" is true by composition (`circuit-open` rejections journal as `skip:circuit-open` per `JRN_SKIP_ERRS` at `bridge.js:457-466`), not by refactoring. The journal's per-target skip is the right grain for transient per-town failures; the circuit is the right grain for whole-feature structural failures.
- **A new top-level `gbInterval`.** Work item 5 piggybacks on `boot.js:124`'s existing 10s `gbInterval(gbLockSweep, …)` line. Per plan 27 §13 / `docs/plans/v4/README.md` Hard rule 4.
- **Cloud sync, REST API, plugin hooks, automation-recovery bot.** All explicitly dropped by plan 27 §0.
