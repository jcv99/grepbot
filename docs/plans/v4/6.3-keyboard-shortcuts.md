# 6.3 — Keyboard shortcuts (Ctrl-Shift-…)

**Bucket:** v4.1 · **Risk:** Low · **Size:** M
**Module:** extend `src/qol.js` (action table + handler) + `src/core.js`
(`state.keybindings` initializer) + `src/ui.js` (Config surface).
**Depends on:** none.
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.9.0 (`header.js:4`).

---

## 1. What exists today

- **No global keydown handler exists for hotkeys.** The only `keydown`
  listener in `src/` is the activity-pause bump in
  `qolBindActivityPause` (`qol.js:1-11`), bound from `boot.js:116`. It calls
  `bumpUserActivity()` (`core.js:597-600`) and is unrelated to command
  dispatch — different intent, same event.
- **No action-by-keystroke table exists.** `Grep -n 'shortcut\|hotkey\|ctrlKey\|metaKey' src/`
  returns only the `qol.js:5` event name and the modifier-check inside
  `native-ui.js:781,787` for the queue-tile `+5` button. There is no
  registry, no menu, no per-action toggle.
- **Dispose contract is enforced through `gbListen`.** Every `gbListen(...)`
  call pushes into `gbListenerBag` (`core.js:17,56-65`), and the global
  dispose at `core.js:114-143` walks that bag and calls
  `removeEventListener` for every entry (`core.js:124-127`). Any listener
  this plan adds **must** go through `gbListen` — a bare `document.addEventListener`
  would survive `__grepbotDispose()` and leak across Tampermonkey script
  reinstalls.
- **Tab-focus tampering is banned by plan 27 §0 ("Tab-focus simulation:
  Game client owns focus; tampering invites anti-cheat").** Passively
  *reading* `document.activeElement` to decide whether the user is typing
  in a game input is allowed — that is the standard idiom for hotkey
  libraries and does not dispatch, focus, or blur any element.
- **GM menus use `gbMenu` (`core.js:105-112`), which itself pushes the
  returned id into `gbMenuCmds` and is cleaned up by `gbUnregisterMenus`
  on dispose (`core.js:99-104`).** Any shortcut that mirrors a GrepBot
  userscript menu entry (e.g. "GrepBot: diag", `ui.js:2008`) reuses the
  existing handler — no separate menu is needed.

## 2. Gap

There is no way for a power user to trigger GrepBot's panel actions
(open queue center, run preflight, copy findings) from the keyboard. The
panel itself is mouse-only; tabbing through controls works, but a
keyboard-first workflow needs Ctrl-Shift-… shortcuts. Plan 27 §6
explicitly asks for this and warns about not stealing game-input focus.

## 3. Design

A single document-level `keydown` listener, registered via `gbListen`
(`core.js:56-65`), matches a `(modifierFlags, key)` pair against a
user-editable table. Before matching, it bails when `document.activeElement`
is anything the user might be typing into (game inputs, panel inputs,
any `contenteditable` subtree). This is the exact filter plan 27 §6
demands — passively checking focus, not pushing any focus or focus
event.

```
filters, in order:
  1. e.ctrlKey || e.metaKey || e.altKey must be set
     (a bare key without a modifier would steal chat / search / unit-pick)
  2. document.activeElement is INPUT | TEXTAREA | SELECT → bail
  3. document.activeElement has isContentEditable === true → bail
  4. event.target.closest('[contenteditable=true]') → bail
     (the focused element may not be the contenteditable root;
      e.g. a chat input may have contenteditable on a parent <div>)
  5. Otherwise: build the key fingerprint ('Ctrl+Shift+P'), look up
     state.keybindings[fingerprint], call the registered action.
```

The keyset is locked to Ctrl / Cmd + Shift + a single printable key.
Alt is rejected up-front so locale-specific AltGr on European layouts
(`@connect`/`@grant`/`@match` rows in `header.js:1-20` use no non-ASCII
characters, but the user can still type AltGr) does not spuriously fire
a shortcut. This also matches every GrepBot userscript-menu item that a
power user might want to invoke from the keyboard.

Action table (default bindings; user can rebind in Config):

| Fingerprint        | Action                                   | Source                       |
|--------------------|------------------------------------------|------------------------------|
| `Ctrl+Shift+,`     | `showTab('config')`                      | `ui.js` `showTab`            |
| `Ctrl+Shift+P`     | `preflightRunAndRender()` → `showTab('stats')` | `ui.js:217` already wires the button |
| `Ctrl+Shift+F`     | Copy findings to clipboard               | `ui.js:2002` menu handler    |
| `Ctrl+Shift+Q`     | `openQueueCenter()`                      | `ui.js:2007` menu handler    |
| `Ctrl+Shift+R`     | `scrapeInboxDom()` (rescan inbox)        | `ui.js:2010` menu handler    |
| `Ctrl+Shift+L`     | Toggle pause-on-activity (`state.pauseOnActivity`) | `core.js:305,597-600`  |
| `Ctrl+Shift+D`     | `diagRun()`                              | `ui.js:2008` menu handler    |

`Ctrl+Shift+L` flips `state.pauseOnActivity` directly (not a re-route
through the Config checkbox): the listener writes the state and the
display checkbox in `bindConfig()` (`ui.js:1307,1377`) re-reads the new
value next time the user opens Config — the listener does **not** call
the synthetic click handler.

The fingerprint resolver is a single function in `qol.js`:

```
fingerprint(e):
  parts = [];
  if (e.ctrlKey || e.metaKey) parts.push('Ctrl');
  if (e.shiftKey) parts.push('Shift');
  parts.push(normalizeKey(e.key));
  return parts.join('+');
normalizeKey(k):
  // 'P' / 'p' both normalize to 'P'; 'ArrowUp' to 'Up';
  // ' ' to 'Space'; everything else lower-cased.
```

(`e.key` is already case-sensitive — pressing Shift+P produces 'P',
without Shift 'p'.)

## 4. Work items

1. **`src/qol.js`** — add a new helper block at the top of the module
   (next to `qolBindActivityPause` at `qol.js:1`): `qolKeymapDefault()`
   (the table above as a frozen object), `qolKeymapFingerprint(e)`,
   `qolKeymapDispatch(e)` (filter + lookup + invoke). The
   `e.preventDefault()` call goes **after** all four bail checks pass
   — short-circuiting on focus check first avoids cancelling browser
   defaults when the user is typing in a game input.
2. **`src/qol.js`** — add `qolBindKeymap()`, a one-shot
   (`_bound` flag mirroring `qolBindActivityPause._bound`) that calls
   `gbListen(document, 'keydown', qolKeymapDispatch, { capture: true })`.
   `capture: true` is needed because the game's own keydown handlers
   may call `stopPropagation`; we want our filter to run before the
   game sees the event.
3. **`src/boot.js`** — call `qolBindKeymap()` next to
   `qolBindActivityPause()` at `boot.js:116`. Both share the same
   document-level keydown path; both are torn down by the single
   `gbListenerBag` walk in `core.js:124-127`.
4. **`src/core.js`** — in the `state` initializer (`core.js:220-384`),
   add `keybindings: load(STORE.KEYBINDINGS, qolKeymapDefault())`.
   The load must run after `qol.js` declares `qolKeymapDefault` (see
   build order below).
5. **`src/header.js`** — add `KEYBINDINGS: 'grepbot:keybindings'` to
   `STORE` (`header.js:24-187`). **Not** in `WORLD_SCOPED_BASES`
   (`header.js:193-214`) — keybindings are a per-user preference.
6. **`src/core.js`** — add a `ver < 11` migration block at
   `core.js:506` (after the `ver < 10` block at `core.js:482-505`)
   that just calls `save(STORE.KEYBINDINGS, state.keybindings)` and
   bumps `CONFIG_VER_CURRENT` (`header.js:191`) to `11`. Migration is
   idempotent; users without the key get the default table.
7. **`src/ui.js`** — in `bindConfig()` (`ui.js:1137-1540`), add a new
   "Atajos de teclado" block (around `ui.js:1500`, after the
   `trade-min` saveNum) that renders the action table as a list of
   `<select data-cfg=keymap-*>` controls. Each `<select>` lists
   `Ctrl+Shift+` + the alphabet; the value is the action key. On
   change, mutate `state.keybindings[fingerprint] = actionKey` and
   `save(STORE.KEYBINDINGS, state.keybindings)`. A "Restablecer"
   button at the bottom calls `qolKeymapReset()` which re-applies
   `qolKeymapDefault()`.
8. **`src/qol.js`** — in `qolExportConfig()` (`qol.js:248-252`) include
   `keybindings: state.keybindings`, and in `qolImportConfig()`
   (`qol.js:254-275`) add `keybindings` to the `validators` map
   (`qol.js:256`) as an `isObj` check plus a `storeFor.keybindings =

## 7. Post surface & safety

Read-mostly / keyboard-only feature: **no post surface** for the
shortcuts themselves. The actions they invoke (preflight, copy
findings, diag) are read-only. `openQueueCenter()` opens a local DOM
window — no `bridgePost`, no `gbXhr`. `scrapeInboxDom()` reads DOM,
no post. The single write is `Ctrl+Shift+L` flipping
`state.pauseOnActivity`, which is a `state.*` mutation persisted via
`save(STORE.PAUSE_ON_ACTIVITY, ...)` (`ui.js:1377`); no bridge.

- No `gbAjaxWatch` registration needed.
- No `gbCaptchaPause` feature key needed (the feature never posts).
- No `gbLock` / `GB_LOCK_TTL` entry needed (no async work; keydown is
  synchronous).
- No dry-run gate needed (no post).
- **No new `gbInterval`.** The listener is event-driven; there is
  nothing to schedule.
- **No new top-level `function` declarations that risk the
  `build.py` duplicate gate** (`build.py:365-378`). Every helper in
  §4.1, §4.2, §4.7 is at module-indent depth (matches the existing
  `qol.js` helpers at `qol.js:1-12`).

## 8. Failure modes

- **The user is typing in a chat input / textarea.** Filter step 2/3/4
  fires — no shortcut runs, the keystroke reaches the game input. The
  filter reads `document.activeElement` only; nothing is focused,
  blurred, or dispatched.
- **A game client that lives inside its own `<iframe>` (rare on
  Grepolis, but theoretically possible for some promo frames).**
  `document.activeElement` will be the outer `<body>` because the
  iframe captures focus. The filter still passes — that is the safe
  direction (a missed shortcut is recoverable; a stolen chat
  keystroke is not).
- **Two shortcuts assigned to the same fingerprint by mistake.** The
  Config save (`state.keybindings[fingerprint] = actionKey`) is a
  straight property assignment — last write wins. Add an
  `Object.values(state.keybindings).filter(v => v === actionKey).length`
  guard at save time that warns (`flash('atajo ya usado por otra
  accion')`) and refuses the save if a collision exists, so the user
  cannot accidentally orphan another action.
- **`capture: true` interferes with a game handler that expects
  keydown to fire on bubble.** Plan 27 §0 forbids *changing* focus
  semantics, but reading events at capture phase does not affect
  bubble — the game still sees the event on its way up, after our
  filter has already bailed. The only behaviour change is that we
  call `preventDefault()` *before* the game's own keydown runs. Since
  our actions never run inside an input (the filter guarantees it),
  there is no input default to prevent; the worst case is a `Space`
  shortcut swallowing a scroll, which is the intended shortcut
  behaviour.
- **`e.key` returns a localized label (`'Espacio'` on Spanish
  keyboards for Space).** `normalizeKey()` falls back to
  `e.code` (`'Space'`) for known problematic keys. See
  `core.js:1063-1078` `gameNow()` for the prior-art
  "first-non-null read" pattern.
- **Listeners leak across reinstalls.** The bare `document.addEventListener`
  failure mode is the dominant one. Plan §4.2 uses `gbListen`; the
  bag walk at `core.js:124-127` removes it on dispose. Verify after
  build: `grep -c '__grepbotDispose' core.js` returns 1, and
  `core.js:124-127` is unchanged.
- **Build-order hazard.** `state.keybindings` is loaded at module init
  time from `load(STORE.KEYBINDINGS, qolKeymapDefault())`. The
  default is a function defined in `qol.js`, which loads **after**
  `core.js` in `build.py` `MODULES` (`build.py:31-72`). Two safe
  options: (a) inline the default table as a literal object in
  `core.js` and have `qol.js` import it via a shared module-scope
  `var` set in `header.js`; (b) move the `keybindings` initializer
  to a `gbTimeout(...)` in `boot.js` that runs after all modules
  load. Option (b) is the smaller diff and mirrors how `state.health`
  is filled lazily (`core.js:389`).

## 9. Validation gate

Manual, per plan 27 §11 (Low risk = Preflight + one in-game session,
no failure).

- Install the new `grepbot.user.js`. Press `Ctrl+Shift+,` while the
  game tab has focus: panel opens to Config. Press `Ctrl+Shift+P`:
  preflight runs and the Stats tab opens. Press `Ctrl+Shift+F`:
  findings dump appears in the OS clipboard; Log tab records
  `findings copied`.
- **Game-input filter test.** Click into the game's chat textarea
  (or any visible `<input>` / `<textarea>` in the Grepolis UI) and
  press `Ctrl+Shift+Q`. Nothing happens — the listener bailed at
  filter step 2. Repeat with `Ctrl+Shift+L` while the game chat has
  focus: nothing flips. Click outside the input and press the same
  key: the action fires.
- **Config rebind test.** Config → Atajos → change
  `Ctrl+Shift+P` to `Ctrl+Shift+X`. Press `Ctrl+Shift+P`: nothing.
  Press `Ctrl+Shift+X`: preflight opens. Restore via "Restablecer".
- **Collision warning test.** Set both `Ctrl+Shift+P` and
  `Ctrl+Shift+F` to the same key. The second save produces a flash
  and the second assignment is **not** persisted.
- **Dispose test.** Trigger an in-game SPA navigation (open Reports,
  then World) — `boot.js:9-34` `hookSpaNav` wraps `pushState`. The
  panel remains functional and the shortcut still works.
- **Export/Import round trip.** Config → Export, paste to a fresh
  install, Config → Import. The rebound keymap round-trips.
- Log tab shows zero new entries for the shortcut layer itself
  (filter pass is silent; only the action it invokes logs).
- `python3 build.py` passes (no new top-level declarations collide);
  install via paste into Tampermonkey.
- Preflight (Stats → Comprobar sistema) reports no new warn rows.

## 10. Out of scope

- **Per-town hotkeys.** The action table is global; town-specific
  shortcuts (e.g. `Ctrl+Shift+1` jumps to town 1) require a town
  picker UI that already exists in Queue Center (`queue-center.js:342`)
  and can be wired later.
- **Mouse-button / chord shortcuts** (e.g. double-Ctrl). Event
  filtering is a keydown listener; mouse chords need a separate
  click handler and a state machine. Plan 27 §6 specifies
  Ctrl-Shift-…, no chords.
- **Tab-focus SIMULATION** — explicitly banned by plan 27 §0.
  This plan only **reads** `document.activeElement`; it never calls
  `focus()`, `blur()`, `tabIndex`, or dispatches focus events.
- **Game-window-shortcut override** (e.g. `G` to center the selected
  town, which Grepolis itself uses). Plan 27 §0 bans tampering with
  game focus. This plan ignores keydown when game inputs have focus;
  it does not override the game's own single-letter shortcuts.
- **Migrating shortcuts to the panel as on-screen chips.** The 6.2
  Draggable widget system owns the visual surface; this plan owns
  only the keyboard path.
