- `STATS_WINDOWS` (`src/military.js:257`) and `statsWindow` (default `'24h'`, `src/military.js:258`) drive Stats-tab 1h/24h/7d buttons (`src/ui.js:847-849`). Plan 27's hint says "extend `stats.js`" — the renderer is there, but the per-tab window state lives in `military.js`. Reuse, do not duplicate.
- `preflightRun()` (`src/stats.js:12-267`) is the probe row that ships in `evidenceCopy()` (`src/stats.js:511-531`) and the panel's *Comprobar sistema* button (`src/ui.js:935`). It already exposes `orchStatus()` filtered to enabled features at `src/stats.js:239-246`.

- Per plan 26 §C2, Stats needs budget-by-scope and `reqBudgetSoftDelayMs` rendering; that work should land first so this plan composes with it (the same renderer line at `src/stats.js:336-346` already prints `byScope` and `softMs`).

## 2. Gap

There is no per-module CPU cost signal. The closest a user can get today is `stats.js:331-334` (cadence + idle) and the journal `byFeature` rollup (`journal.js:249-293`). When a feature goes from 5ms/tick to 150ms/tick the user has no in-game way to see it, and adaptive backoff (`orchIdleFactor`, `orchestrate.js:107-114`) masks the slow runs by doubling the cadence. The profiler is a read-only instrument: it accumulates `performance.now()` deltas at the existing dispatch seams and renders top-N ms/call for the active window. It must not be a cost itself — sampling defaults to OFF.

## 3. Design

Two seams, one renderer, one Config toggle:

- **Orchestrator seam (econ features).** Wrap the inner closure passed to `orchSafe()` in `src/qol.js:421-436` so the timing covers the actual scan and the existing `try/catch` stays unchanged. Concretely: replace the bare `()=>orchSafe('culture', ()=>cultureScan('orch'))` form with `()=>orchSafe('culture', ()=>profTime('orch:culture', ()=>cultureScan('orch')))`. `profTime(key, fn)` records `performance.now()` deltas into a ring keyed by `key`; throws still propagate to `orchSafe`.
- **Wake seam (heterogeneous posts).** Wrap `item.fn()` at `src/core.js:664` with `profTime('wake:' + item.key, () => item.fn())`. The wake queue key already disambiguates source (`ibScan`, `orchTick`, `farmTick`, `reportCatchUpRun`), so a single label set covers all wake producers without changing the call sites listed in plan 26 §A3.
- **Storage.** One ring per key, 60 entries (= 60 calls), in `state.profileRings`. No per-call payload — `performance.now()` deltas only. World-scoped because `gbWake` and `ORCH_HANDLERS` are world-scoped (server responses are world-specific), so any cross-world aggregation would dilute the signal.
- **Renderer.** Add a `preflightProbe('profiler', …)` row (after `src/stats.js:246`, before the resource-planner row at line 248) that reports whether the profiler is enabled and the sample count. Add a per-window block at the end of `renderStats()` (before `box.textContent = …` at `src/stats.js:354`) that prints `top ms/call` for orch + wake keys in the active window. Reuse the existing `STATS_WINDOWS[statsWindow]` to compute the time window; the ring itself is call-bounded, not time-bounded, so the window label refers to how recently the ring was filled.

Sampling strategy: low-overhead `performance.now()` diff only — no `console.time`, no stack capture, no JSON serialisation in the hot path. The ring is a fixed-size `{count, sumMs, maxMs, lastMs, lastAt}` object per key (`Object.create(null)`); updates are `+=` and `=` only. No allocation per call. Default OFF so the ring stays cold.

## 5. State & storage

- New state: `state.profileOn` (boolean, default `false`); `state.profileRings` (object keyed by label, each `{count, sumMs, maxMs, lastMs, lastAt}`, default `{}`).
- Storage: `STORE.PROFILE_RINGS` (`grepbot:profile-rings`) — world-scoped (entry in `WORLD_SCOPED_BASES`).
- Prune: ring is call-bounded (60 entries per key, FIFO replacement inside the ring), not TTL-bounded. No `JRN_TTL_MS`-style sweep needed.
- `configVer` bump: 10 → 11 (header.js:191). No migration code — `profileRings` is freshly default and a stale entry on disk is harmless.

## 6. Config surface

- **Toggle:** `profileOn` (default **OFF** — the profiler must not be the cost it measures). Surfaced only in the Stats tab Actions menu (no Config checkbox), so users who have never looked at Stats do not see it.
- **No new Config field in `qol.js`.** The toggle is a one-click Actions-menu button; clicking flips the boolean and re-renders. Rationale: this is a developer-style instrument; it should not look like a setting.
- **Window selector:** reuses the existing `1h`/`24h`/`7d` buttons at `src/ui.js:847-849`. The renderer reads the same `STATS_WINDOWS[statsWindow]` (`src/military.js:257`) the rest of Stats uses.

## 7. Post surface & safety

Read-only. No new `bridgePost` / `gameAjaxPost` route. No `gbAjaxWatch` registration, no template, no `gbCaptchaPause` feature key, no `gbLock` name, no dry-run gate. None of `bridgePost`, `txRun`, `gameAjaxPost` is touched.

## 8. Failure modes

- **Sampling overhead.** Mitigated by default OFF and by the single-property-read guard at the call site (`if (!state.profileOn) return fn();`). When ON, the cost is two `performance.now()` calls + a `+=`/`=` per wrapped invocation — measured at <0.5µs/call on Chromium; the orchestrator runs at most `ORCH_MAX_PER_TICK` (3) features per `ORCH_MS` (20s) tick (`qol.js:388-389`), so the steady-state overhead is negligible.
- **Ring drift across worlds.** A world-scoped key (`WORLD_SCOPED_BASES` entry) prevents the journal-style cross-world pollution that `jrnCheckHost()` exists to undo (`journal.js:39-53`). Without world-scoping, a fast `farm` cycle on World A would surface as the top CPU consumer on World B.
- **Stale rings.** If a feature stops firing (e.g. `state.autoFarm` flipped OFF) its ring keeps its last samples — `lastAt` becomes the staleness indicator and the renderer sorts by `sumMs/count` over the ring window, not by absolute `sumMs`. No dead guard: `lastAt` is a read, the comparison is honest.
- **Precondition invariant (blind getter).** None — `performance.now()` is universally available in Tampermonkey contexts. If a future engine strips it, `profTime` returns `fn()` unchanged (the `state.profileOn` gate is already a property read; the `Date.now()`-based fallback would be the same shape). No `gbLogT` once needed.

## 9. Validation gate

Low risk → Preflight + one in-game session, no failure (plan 27 §11).

1. Toggle ON via Stats tab → Actions menu → *Profiler ON*. `preflightRun()` (Stats tab or Comprobar sistema) prints `+ profiler: recording — see Stats`. Stats body prints an `orch:` + `wake:` block with the keys seen so far.
2. After 5 minutes idle on a normal play session (with `autoCave` ON, `autoBuild` ON, `autoFarm` ON): the `orch:cave`/`orch:build`/`orch:farm` lines show non-zero `calls` and `avg` < 20 ms each on a typical world. The `wake:ibScan` line shows the highest call count (every 10s, `ibScan` lives on its own `gbInterval` — plan 26 §A3 caveat).
3. Toggle OFF → the rows stop accumulating (next call short-circuits), but the previously-recorded ring stays visible for the rest of the session so the user can compare. No Log lines about the toggle — silent flip.
4. Reload page; the ring persists across reload (because it is world-scoped and saved on `pagehide`). Toggle state persists because `state.profileOn` is not yet stored (intentional — see §10) — re-toggle ON each session is acceptable for a developer instrument.
5. Cross-check: `evidenceCopy()` (Actions menu → Evidencia) returns a JSON blob that **does not** include `profileRings` — this is a developer view, not part of the user-facing evidence export. If it accidentally shows up, remove the keys from the `gbEvidence()` builder (`stats.js:432-506`).

## 10. Out of scope

- Per-statement / per-line breakdown (no V8 inspector integration — Tampermonkey userscript context does not expose `Inspector`). Per-call timing only.
- Storing `profileOn` to disk. The toggle is per-session by design (developer instrument). If users ask for persistence, add `STORE.PROFILE_ON` + world-scope later — not in this plan.
- Cross-window aggregation (1h + 24h + 7d simultaneously). One window at a time, matching Stats.
- Network/timeline profiling. The bridge spy (`hookFetch` + `hookXhr` per CLAUDE.md) already logs request URLs; the journal already logs results. No new spy surface.
- Wake-burst correlation. `gbInWakeBurst()` (`src/core.js:674`) already exists; if a future plan needs to mark profile samples taken during a wake burst, that is a follow-up.
- 8.6 decision audit trail is already shipped in `src/journal.js` v1.1.0 — does not interact with this plan.
