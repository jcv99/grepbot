## 1. What exists today

**There is no `cs-tracker.js`.** `src/` holds 40 modules (`ls src/`), none named
`cs-tracker.js`, and `build.py` MODULES (build.py:32-72) has no such slot.
`find . -name '*cs-tracker*' -o -name '*snipe*'` returns nothing. The string
"snipe" appears exactly once in the whole tree — `ui.js:801` "Merchant sniper",
an unrelated Config label. **Nothing about counter-sniping is coded.**

Where CS actually lives (CLAUDE.md's "Dodge / militia / CS (`dodgeScan`) …
CS badge + webhook" line):

- `dodgeIncomingMovements()` (`dodge.js:53-84`) reads the `MovementsUnits`
  collection, keeps only movements whose destination is one of my towns
  (`dodge.js:59-63`) and only canonically hostile ones (`dodgeIsHostileMovement`,
  `dodge.js:41-52`). It returns `{id, dest, origin, type, hasCs, arrival, units, model}`.
- `hasCs` is derived at `dodge.js:73`:
  `units.colonize_ship || units.colony_ship || /^(revolt|colonize|take_over|conquer)$/.test(type)`.
- `dodgeEtaSec(mov)` (`dodge.js:175-180`) normalizes `arrival` (÷1000 when
  `> 1e12`) and returns `arrival - gameNow()`, or `null` when unreadable.
- The "CS badge" is **not** a footer badge. It is three `[CS]` string prefixes:
  the flash/log line in `dodgeNotify` (`dodge.js:186`), the Intel board row
  (`intel.js:88`) and the Discord embed title (`alerts.js:59`).
- The CS webhook is the existing `alertWebhook('attack', {…, cs:!!mov.hasCs})`
  call at `dodge.js:191`, gated by `state.csAlert` (default `true`,
  `core.js:335`, key `STORE.CS_ALERT` `header.js:124`, Config checkbox
  `[data-cfg=cs-alert]` `ui.js:821`, bound `ui.js:1428`).

The only wave-aware code that exists:

- `defenseAssessment(mov, incoming)` (**`wonder.js:144`**, *not* `military.js`)
  computes `simultaneous = all.filter(x => x.dest === mov.dest).length` — a
  **count of movements per town with no time analysis at all** — and adds
  `+60` risk for `hasCs`, `+min(25,(n-1)*8)` for multiple movements.
  It is consumed by `defenseShouldDodge` (`wonder.js:145`) and rendered per row
  by the Intel board (`intel.js:87-89`).
- Preflight has an `incoming` row that only prints a count
  (`stats.js:225-228`).
- `intelPatternScan` (`intel.js:206-245`) is **not** related: it buckets
  `state.findings` (spy/battle reports) by attacker over 24h. Different source,
  different time scale.

So: arrival timestamps are read and thrown away, wave membership is reduced to a
scalar count, and nothing anywhere computes an inter-arrival delta
(`grep -rn '\bwave\b|snipeWindow|interArrival' src/` → one unrelated hit,
`attack.js:588`).

## 2. Gap

The defender-relevant fact is not "how many attacks", it is **where the gaps
are**: the interval between the clearing wave and the colony-ship landing is the
window in which support can be sniped in, and attackers cover that window with
extra waves. `defenseAssessment` (`wonder.js:144`) collapses exactly that
structure into `simultaneous`, so a 3-wave train landing 4s apart around a CS and
3 unrelated attacks spread over 6h produce the identical assessment. The delta is
one pure function over the list `dodgeIncomingMovements()` already returns —
group by `dest`, sort by `arrival`, expose the gap around the CS and how many
waves sit inside it — plus four read-only display sites.

## 3. Design

Pure analyzer + existing surfaces. No new data source, no new timer, no post.

Data in: `dodgeIncomingMovements()` (`dodge.js:53`), which `dodgeScan` already
calls once per pass (`dodge.js:263`) on the 5s `DODGE_CHECK_MS` interval
(`wonder.js:150`, wired `boot.js:100`).

Decision (`csWaveClusters(incoming)`, new, in `dodge.js`):

1. Bucket movements by `String(mov.dest)`.
2. Per bucket, map each movement to `dodgeArrivalSec(mov)` (see work item 1).
   `null` ⇒ counted into `unknownArrival`, **excluded from the maths**.
3. Sort ascending; split into *trains* wherever the gap between consecutive
   arrivals exceeds `csClusterGapSec` (default 900 = the existing 15-min
   imminence horizon, `DODGE_MILITIA_WINDOW_SEC` `dodge.js:181`).
4. Per train, `csAt` = arrival of the **last** entry with `hasCs`
   (`dodge.js:73`); `prev` = the entry immediately before it.
   - `gapSec = csAt - prev.at` — the snipe window.
   - `cover` = entries whose arrival lies in `(csAt - csCoverSec, csAt)`,
     excluding the CS itself — the counter-snipe waves that would eat a snipe.
5. Verdict, in this order (first match wins):
   - `unknownArrival > 0` ⇒ `'unknown'` (a blind read may never produce a
     reassuring verdict — §8).
   - no `hasCs` entry ⇒ `'no-cs'`, and report `tightestGapSec` instead.
   - no entry before the CS ⇒ `'cs-solo'` (window not computable from
     incoming alone).
   - `gapSec <= csTightSec` (default 5) ⇒ `'tight'`.
   - `cover >= 1` ⇒ `'covered'`.
   - else ⇒ `'open'`.

Action out — four read-only sinks, all existing:

- `dodgeNotify` (`dodge.js:183-194`): the per-movement flash/log line and the
  **existing** webhook payload gain the train verdict. No new webhook event, no
  new call site, no extra alert volume.
- `dodgeScan` (`dodge.js:266-287`): one throttled `gbLogT` train summary per
  destination, re-emitted only when the verdict string changes — `dodgeNotify`
  fires once per movement (`entry.notified`, `dodge.js:184`), so a wave added
  *after* first notification would otherwise be invisible.
- Intel board row (`intel.js:88-89`).
- Preflight `incoming` row (`stats.js:225-228`).

Gap arithmetic is a difference of two server arrival stamps, so it is immune to
local clock drift; only the ETA display uses `gameNow()` (`dodge.js:179`).

## 5. State & storage

No new `state.*` root field and **no new `STORE.*` key**. The four tunables live
inside the existing `state.defenseCfg` object (`core.js:359`, key
`STORE.DEFENSE_CFG` `header.js:155`), which is **already** in
`WORLD_SCOPED_BASES` (`header.js:209`) — so nothing new is id-bearing and
`load()`/`save()` already apply `wkey()`.

`configVer`: 10 → 11 (`header.js:191`; ladder tail `core.js:482-506`). The
`ver < 11` block sets the defaults on persisted configs that predate them and
clamps: `csClusterGapSec` to `[60, 21600]`, `csCoverSec` to `[5, 900]`,
`csTightSec` to `[0, 120]`, `snipeDetect` to a boolean, then
`save(STORE.DEFENSE_CFG, state.defenseCfg)` — mirroring the existing
`returnMarginSec` clamp at `core.js:503`.

Prune TTL: none. Every train is recomputed from the live collection each 5s
pass; nothing is persisted, so nothing can go stale or leak. The existing
`dodgeQueue` TTL sweep (`dodge.js:289-294`, `DODGE_QUEUE_TTL` 1h
`wonder.js:152`) is untouched.

## 7. Post surface & safety

**No post surface.** The feature sends nothing: no `bridgePost`, no
`gameAjaxPost`, no `gbXhr`, no DOM write. Therefore no `gbCaptchaPause` feature
key, no `gbLock` name, no `GB_LOCK_TTL` entry, no `gbAjaxWatch` registration,
no `TPL_FEATURE_MAP`/`tplNameFor` entry and no dry-run gate are added. The only
outbound traffic it touches is the **already existing** `alertWebhook('attack', …)`
at `dodge.js:191`, which gains payload fields; its call site, its 5-min
per-key rate limit (`alerts.js:43`) and its dry-run short-circuit
(`alerts.js:30-33`) are unchanged.

## 8. Failure modes

- **Unreadable arrival ⇒ `blind`, never a safe verdict.** `dodgeArrivalSec`
  returns `null` when `arrival` is absent or non-finite (`dodge.js:176-178`).
  Such movements are counted into `unknownArrival` and the train verdict becomes
  `'unknown'` — it must never fall through to `'open'` or `'no-cs'`, because a
  guard that reports "no threat" from data it could not read is worse than no
  guard (CLAUDE.md precondition invariant). One `gbLogT('cs-blind-'+dest, 600000, …)`
  naming the field it failed to read.
- **`hasCs` may never fire — UNVERIFIED, must be measured.** `dodge.js:73`
  needs either `units.colonize_ship`/`units.colony_ship` **or** a type in
  `/^(revolt|colonize|take_over|conquer)$/`. Whether the server exposes the
  attacker's unit breakdown on an *incoming* movement is **not verifiable from
  `src/` or from `archive/captures/`** (`grep -o 'arrived_at…' game.min.js` →
  no hits; one `MovementsUnits` occurrence, no attribute schema). If units are
  hidden, only the type branch can fire. The detector must therefore degrade
  honestly: with no `hasCs` entry it reports `'no-cs'` + `tightestGapSec`, and
  it must **not** print "no colony ship". Work item 9's Preflight detail plus
  the §9 gate is how this gets settled on the live world.
- **No `MovementsUnits` collection** (`dodge.js:57-58` returns `[]`): zero
  trains, zero log lines. No crash path — `csWaveClusters([])` returns `[]`.
- **Single-wave noise.** Trains of `n === 1` with no CS produce no output at
  all; only `n >= 2` or a CS-bearing train logs.
- **Cross-town merging is impossible** — grouping is keyed on `mov.dest`
  (`dodge.js:75`), so two towns attacked at the same second never form one
  train.
- **Cost of being wrong is bounded.** The only consumer that can change
  behaviour is work item 7's `+10` risk on `'covered'`; `defenseShouldDodge`
  fires auto-dodge at `risk >= 35` and only when `state.autoDodge` is on
  (`dodge.js:205`) — which is HIGH-RISK and default OFF (`core.js:321`). If
  item 7 is judged too risky for a "read-only" plan, ship items 1-6 and 8-12
  and defer item 7 to 5.3; the feature is complete without it.

## 10. Out of scope

- **Acting on the verdict** — sniping support in, cancelling, dodging on a
  covered window. Any of those is a post surface: 3.2 (support auto-send),
  5.4 (smart dodge), 3.6 (militia smart activation).
- **Re-weighting the risk model.** `defenseAssessment`'s existing constants
  (`wonder.js:144`) and the `risk >= 35` auto-dodge threshold
  (`wonder.js:145`) belong to **5.3 threat assessment engine**, which should
  consume `csWaveClusters` rather than re-derive it.
- **Inferring wave composition** (clear vs fake vs anti-snipe) from unit counts
  — not readable for incoming movements, see §8. Never guess it.
- **Report-derived history** ("this player always covers at 4s"): that is
  `intelPatternScan`'s data source (`intel.js:206`), owned by 2.5 / 5.3.
- **Sharing trains with the alliance** — 7.2 defense coordination board.
- **A new `cs-tracker.js` module and its `build.py` MODULES slot.** Rejected:
  three functions on a list that `dodge.js` already produces do not justify a
  module, and splitting them from `dodgeScan` would put the analyzer in a file
  that concatenates after its only caller for no benefit.
