# 6.5 — Quick-action toolbar (1-click collect / farm / dodge / panic)

**Bucket:** v4.0 · **Risk:** Low · **Size:** S
**Module:** extend `src/ui.js` (panel + Actions menu + footer wiring). The
underlying one-shot functions already exist in their feature modules; this
plan binds buttons to them.
**Depends on:** **1.1** Panic mode (instant-pause button) — planned
separately. Toolbar exposes a Panic button that calls whatever surface 1.1
defines; this plan does **not** re-specify the panic semantics.
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.9.0 (header.js:4).

---

## 2. Gap

Every one-shot trigger lives two clicks away (open the footer Actions
`<details>`, then click the inner button). On mobile / collapsed panel this
costs the user extra taps; on desktop it costs context. A persistent toolbar
of large buttons at the top of every tab lets the user fire the most common
actions without opening menus.

## 3. Design

A horizontal toolbar rendered just below the panel header (above
`.gb-nav`, line 562). Five buttons, each 1-click:

| Button | Handler | Lock | Notes |
|---|---|---|---|
| `Recoger ahora` | `autoCollectResources()` | `collect-bg` (taken inside) | Already gated; shows the same flash the Actions menu shows. |
| `Cobrar aldeas` | `autoClaimFarms('manual')` + `scrapeAllFarms(true)` + `farmTick()` | `claim` (taken inside) | Exact body of `ui.js:1101-1111` is factored into a new `runActionManual('scrape-farms')` helper. |
| `Dodge scan` | `dodgeScan('manual')` | `dodge` (taken inside) | Notify/auto respects `state.autoDodge`; flash is whatever `dodgeScan` logs. |
| `Cola ahora` | `abScan('manual')` | `ab` (taken inside) | Already exists at `ui.js:1056-1059`. |
| `Panico` | `panicActivate()` (from plan 1.1) | n/a (panic owns its state) | Button is **disabled** with title `Requiere plan 1.1` if `typeof panicActivate !== 'function'` — degrades safely until 1.1 ships. |

All five buttons are read-mostly; they do not introduce new post routes. They
delegate to the same functions the existing footer/Actions buttons already
delegate to, so no new `gbAjaxWatch` registration is needed.

The toolbar sits **above the tab nav**, not below it. Reasoning: it is the
most-clicked surface in the panel, and the tab nav is a row of small tabs —
burying it would defeat the purpose. CSS reuses the existing `.gb-quick` /
`.gb-action` classes (`ui.js:514-516`).

A second `.gb-quick` row is **not** rendered inside Overview (the existing
one at `qol.js:192-222` becomes redundant once the toolbar is permanent).
The Overview quick row can stay as a separate surface — duplication is
acceptable here because the toolbar is global and the Overview quick row is
contextual. The plan does not delete the Overview row in this change (see
§10).

Layout & hide-on-collapse: the panel already hides chrome when
`.collapsed` (`ui.js:440`). The toolbar inherits that rule via the
existing `#grepbot-panel.collapsed .gb-nav, ... section, footer {display:none}`
selector — the new toolbar gets added to that selector list.

## 5. State & storage

- **No new `state.*` field.** The toolbar is stateless; every click
  delegates to functions whose state lives in `state.autoCollect`,
  `state.autoDodge`, `state.autoFarm`, `state.abAuto`, `state.defenseCfg`
  — all already in `core.js:220-384`.
- **No new `STORE.*` key.** Toolbar buttons do not persist anything.
- **No `WORLD_SCOPED_BASES` entry.**
- **No `configVer` bump.** Toolbar adds no config surface; the existing
  `CONFIG_VER_CURRENT = 10` (`header.js:191`) stays.
- **No prune TTL.** Nothing is stored.

## 6. Config surface

- **No Config toggle.** The toolbar is always-on chrome; per-button
  availability is gated by existing toggles (`state.autoCollect` for
  collect, `state.autoFarm` for farms, `state.autoDodge || state.csAlert ||
  state.autoMilitia` for dodge scan, `state.abAuto` for cola ahora,
  `typeof panicActivate === 'function'` for panic).
- Visual affordance: disabled buttons get the existing
   `.gb-action:disabled` style (`ui.js:515-516`) — already used by the
   Build tab's instant-complete button (`ui.js:488-489`).

## 7. Post surface & safety

The toolbar introduces **no new post surface**. Every click delegates to an
existing function whose `bridgePost` / `gameAjaxPost` / `gbDomClick` call is
already inside `state.dryRun`'s coverage (`core.js:941-951`,
`tx.js:535`/`tx.js:646-647`).

- **No `gbAjaxWatch` registration.** Sniffers already register via the
  underlying scans.
- **No new `gbCaptchaPause` feature key.** Each button delegates to a
  feature that already owns its captcha key (`collect`, `claim`, `dodge`,
  `ab`).
- **No new `gbLock` / `GB_LOCK_TTL` entry.** Locks are taken inside the
  delegated functions; the toolbar is a synchronous caller and returns
  before any async work settles. The five locks used (`collect-bg`,
  `claim`, `dodge`, `ab`, `ib`) are already in `core.js:145-173`.
- **Dry-run gate.** Already in effect through every delegated path. The
  toolbar buttons themselves never bypass `state.dryRun` — they cannot
  (`bridgePost` and `gameAjaxPost` short-circuit at the top of their
  bodies, plan 26 §0).

## 8. Failure modes

- **`panicActivate` is undefined** (1.1 not shipped yet). The Panic button
  is rendered `disabled` with `title="Requiere plan 1.1 (panic mode)"` —
  no crash, no flash, no log. Once 1.1 lands the button enables on next
  panel re-render (handled in work item 3).
- **User double-clicks a toolbar button.** Each handler runs immediately
  and is re-entrancy-safe: `autoCollectResources` guards with
  `gbLocked('collect-bg')` (`collect.js:108`), `scrapeAllFarms` guards with
  `gbLocked('farm-scrape')` (per `GB_LOCK_TTL` at `core.js:147`), `dodgeScan`
  guards via `gbLocked('dodge')` (`dodge.js:210`), `abScan` via
  `gbLocked('ab')` (`core.js:150`). The second click either no-ops or, in
  the rare case where the first call is still synchronous, simply enqueues
  behind the existing in-flight run.
- **Toolbar is on screen during `panel.classList.add('collapsed')`.** The
  new `.gb-qat` rule is added to the existing collapsed-hide list at
  `ui.js:440` so it disappears with the rest of the chrome. No
  double-rendering on minimize/restore.
- **A button calls into a feature whose state is paused** (captcha, budget,
  server cooldown). The underlying scan logs its skip reason
  (`captcha-pause`, `budget`, `skip:dryrun`) and the toolbar button does
  not change behaviour. The user sees the same `flash()` they'd see from
  the Actions menu.

## 9. Validation gate

Manual, per plan 27 §11 (Low risk = Preflight + one in-game session, no
failure).

- Install. Toolbar appears above the tab nav. Each of the five buttons
  shows with the enabled/disabled state matching the underlying toggle
  (Panic disabled until 1.1 ships; the other four enabled since each
  default toggle is OFF but the button just invokes the function which
  exits early).
- Click `Recoger ahora` once. If `state.autoCollect` is ON and the page
  has a Recoger button, it clicks (flash `auto-collect xN` matches the
  Actions-menu behaviour). If OFF, the call short-circuits at
  `collect.js:28` and no post is made. Log shows the same line either way.
- Click `Cobrar aldeas` once. Log: `manual: Farms now pressed` followed
  by `manual farm claim` lines per village (same as the Actions menu).
- Click `Dodge scan` once with no incoming. Log: nothing (the scan finds
  no hostile movements and exits).
- Click `Panico`. With 1.1 not yet shipped: button is disabled, no
  effect. With 1.1 shipped: orchestrator.skip becomes true; footer shows
  the panic indicator from 1.1's spec.
- Dry-run ON: every button still works (each delegated function respects
  `state.dryRun`); the log shows `DRY-RUN ...: ...` for any path that
  would otherwise post.
- `python3 build.py` passes; install via paste into Tampermonkey.

## 10. Out of scope

- **Removing the existing Actions `<details>` menu.** Stays as-is. The
  toolbar covers the four most-clicked actions; the menu keeps the long
  tail (export, copy, diag, presets, evidence, clear, reset).
- **Removing the Overview `.gb-quick` row.** Stays. The two coexist
  intentionally: the toolbar is global and persists across tabs, the
  Overview row is contextual (lets a first-time user fire the same
  actions from the Resumen tab without scrolling up).
- **Adding a "Sleep claim" button to the toolbar.** Sleep claim already has
  its own prominent button at `#gb-sleep-claim` (`ui.js:567`). Adding a
  sixth toolbar button would crowd the row.
- **Adding a draggable toolbar** (plan 6.2 owns dragging). The toolbar
  lives in the panel header strip; not detachable in v4.0.
- **Re-specifying the panic semantics.** Owned by plan 1.1. This plan
  references `panicActivate()` as a black box.
