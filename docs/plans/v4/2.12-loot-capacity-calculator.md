## 2. Gap

Three modules (farm duration picker, farm profitability ranker, attack
boat gate) each carry their own per-domain math for "how much can the
town absorb / how much can the units haul". A future tweak (research
multiplier, hero boost, world-specific rate) has to land in three places.
There is also no single `{wood, stone, iron, total, blind, blindReason}`
return shape — callers that want one uniform value (e.g. plan **5.2**
adaptive farming, **5.5** academy timing) have to branch by domain.

## 3. Design

One module-local function in `src/bridge.js`, declared near
`townResState` (`bridge.js:235-273`) — same two-space-indent IIFE style as
its neighbours, not a top-level `function` (no consumer imports it
across modules; it is reached by the IIFE-scoped name).

```
gbLootEstimate(ctx) -> {
  wood, stone, iron, total: number,
  blind: boolean, blindReason: string|null,
  meta: object,           // kind-specific
}
```

`ctx.kind` discriminates three domains:

| `ctx.kind` | Inputs | Today | After 2.12 |
|---|---|---|---|
| `'farm-claim'` | `{townId, durationSec, loyalty?, headroom?}` | inline in `farmDurationPick` (`farms.js:435-444`) | extracted; both `farmDurationPick` and 2.6's `farmProfitScore` call it |
| `'attack-boat'` | `{units, sameIsland}` | `boatCapacityCheck` (`attack.js:106-140`) | wrapped — same answer, uniform shape |
| `'attack-loot'` | `{units, target?}` | **absent** | returns `blind:true, blindReason:'unit-carry-unknown'` until §4.7 sniffs the field |

The three branches all return the same shape, so a planner can compose
checks without branch-by-branch plumbing.

### Farm-claim branch (extract, NOT new math)

```
const LOOT_RATE_PER_HOUR = 8000;        // mirrors farms.js:435
const SAFE_FILL_PCT = 0.6;              // mirrors farms.js:434
if (ctx.kind === 'farm-claim') {
  const dur = Math.max(0, +ctx.durationSec || 0);
  const loyalty = ctx.loyalty != null ? +ctx.loyalty : 1.0;  // 1.0 = researched
  const headroom = ctx.headroom != null ? +ctx.headroom : null;
  const expectedTotal = Math.round((dur / 3600) * LOOT_RATE_PER_HOUR * loyalty);
  const fits = headroom != null ? expectedTotal <= headroom * SAFE_FILL_PCT : null;
  return { wood: expectedTotal, stone: expectedTotal, iron: expectedTotal,
           total: expectedTotal, blind: false, blindReason: null,
           meta: { durationSec: dur, loyalty, headroom, fits } };
}
```

The estimate splits 1/3 each into wood/stone/iron — same flat split
2.6 uses, matching the in-game equal-share reward shape.

### Attack-boat branch (wrap, NOT rewrite)

Delegates to `boatCapacityCheck`; the wrapper lives in `attack.js`
(§4.8), not in `bridge.js`, so `bridge.js` keeps no `attack.js`-only
imports. Returns the same `{ok, need, cap, reason}` inside `meta.boats`
for callers that need the discriminator.

### Attack-loot branch (honest unknown)

Returns `{wood:0, stone:0, iron:0, total:0, blind:true,
blindReason:'unit-carry-unknown', meta:{units: ctx.units}}`. No silent
zero — a caller can render "loot: unknown" instead of "loot: 0".

## 5. State & storage

- **No new `state.*` fields.** The calculator is stateless; consumers
  own their own memo (sibling 2.6 §5 already keeps `farmProfitCache` with
  5min TTL).
- **No new `STORE.*` keys.** All inputs already world-scoped or
  module-local.
- No `configVer` bump (read-only plumbing, no Config surface).
- No prune TTL (no persisted state to age).

## 6. Config surface

- None. The calculator has no user-tunable knobs. The per-domain
  constants (`LOOT_RATE_PER_HOUR`, `SAFE_FILL_PCT`) are module-scope and
  only retuned in a code change. If a future plan wants them exposed,
  add a single Config group "Estimación de botín" with `Tasa por hora`
  (default `8000`) and `Margen seguro %` (default `60`). Out of scope
  for v4.0.

## 7. Post surface & safety

**No post surface.** Read-only. Reads `townResState`, `farmLoyaltyResearched`,
`GameDataUnits.calculateCapacity`, and the (yet-to-be-sniffed) unit-carry
field. No `bridgePost`, no `gameAjaxPost`, no `gbXhr`. Therefore: no

## 8. Failure modes

- **`townResState(townId)` returns null.** `'farm-claim'` reads
  `ctx.headroom`, which the caller passes in. If the caller could not
  read headroom, the branch returns a non-blind `expectedTotal` and
  `meta.fits === null`. `farmDurationPick`'s ladder walk only skips a
  duration when `fits === false`, so a missing headroom causes the
  longest learned duration to win — identical to today.
- **`farmLoyaltyResearched` returns false** (research not done or id not
  in `FARM_LOYALTY_IDS` (`farms.js:367`)). Default `loyalty = 0.5`,
  matching the in-game multiplier assumption baked into 2.6 §3. Known
  detector failure on worlds with renamed research ids; documented in
  2.6 §8 and unchanged by 2.12.
- **`GameData.units[id]` rename / missing carry field.** `'attack-loot'`
  returns `blind:true, blindReason:'unit-carry-unknown'`. Never silent
  zero — a caller renders "loot: unknown", not "loot: 0".
- **`GameDataUnits.calculateCapacity` missing on this build.** The
  existing fallback chain in `boatCapacityCheck` (`attack.js:128-139`)
  handles it. 2.12 does not change it. `'attack-boat'` returns the
  fallback shape unchanged inside `meta.boats`.
- **Branch called with an unknown `ctx.kind`.** Returns
  `{wood:0, stone:0, iron:0, total:0, blind:true,
  blindReason:'unknown-kind'}`. Logs once via `gbLogT('loot-calc-bad-kind',
  300000, …)`.
- **Bridge model renames a getter.** `townResState` already wraps in
  `try/catch` (`bridge.js:244,250`); `farmLoyaltyResearched` wraps in
  `try/catch` (`farms.js:406`). The calculator inherits those guards.
  A rename surfaces as `null` to the caller, never as a wrong number.

## 10. Out of scope

- **Per-unit attack loot carry.** Implementation depends on sniffing a
  field name that is not present in `src/` today (§4.6). The
  `'attack-loot'` branch is a `blind` sentinel until that sniff lands;
  adding the actual reader is a one-day follow-up, not a 2.12 task.
- **Per-village stock and per-village historical yield.** Plan 26 §A1
  proved neither is in the bridge model. Sibling 2.6 §10 owns this
  honest-unknown line.
- **Booty-camp ranker (5.8) does not consume this hook.** Sibling 5.8
  `5.8-booty-camp-optimizer.md` ranks by per-unit resource **build cost**
  (a combat-effectiveness proxy), not by loot carry. The bandit reward
  path (`bandit.js:206-209`) is reward-by-power-id, not per-unit carry.
  5.8 §10 explicitly excludes a per-unit carry factor. 2.12 does not
  change 5.8.
- **Cross-island transport haul** (plan **1.3**). Transport has its own
  post-route math; once 1.3 ships and calls `gbLootEstimate({kind:
  'attack-loot', units, target})`, the `blind:true` sentinel will
  surface naturally as "transport loot: unknown" in the planner HUD.
- **A `'cave-stash'` or `'culture-cost'` branch.** The calculator is
  scoped to *loot* (income), not *spend*. Spend math belongs in
  `planner.js` (already has `plannerLive`/`plannerAvailable`
  `planner.js:37-45,82-86`).
- **Config-tunable haul rate / safe-fill %.** §6 notes the future knob;
  not added in v4.0.
