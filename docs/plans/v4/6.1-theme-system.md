# 6.1 — Dark mode / theme system

**Bucket:** v4.0 · **Risk:** Low · **Size:** S
**Module:** extend `src/ui.js` (theme is pure CSS) — no `theme.css` file, the
existing `GM_addStyle` block in `ui.js:397-549` already ships the panel CSS.
**Depends on:** none (read-only over the panel; does not touch the game DOM,
does not register a post surface).
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.9.0 (header.js:4).

---

## 1. What exists today

- The panel is a single `#grepbot-panel` element injected into `document.body`
  by `ui.js:560-898` (the `panel.innerHTML` template). All styling is inlined
  via one `GM_addStyle` call: `ui.js:397-549` (`#grepbot-panel { background:#181a1f;
  ... }`). The Queue Center window uses a second scoped root
  `#grepbot-queue-center` defined later in the same style block
  (`ui.js:525-543`).
- Colours are **hardcoded hex** at every rule: background `#181a1f` / `#22252b`
  / `#262626`, borders `#333` / `#414650`, accent `#f5a623` (warning amber),
  text `#eef1f5`, error `#f55`, success `#8fe0a8`. ~30 rules reference them.
- No CSS custom properties (`--gb-bg`, `--gb-fg`, …) are declared today
  (`grep -n -- '--gb-' src/` returns zero matches). The panel has no
  light-mode alternative, and no theme toggle exists.
- The `Config` tab is rendered by `bindConfig()` at `ui.js:1137-1540`; toggles
  use `data-cfg="..."` selectors and `state` mutations like
  `state.foo = e.target.checked; save(STORE.X, state.foo)`. This is the
  template a new theme toggle must follow.
- The migration ladder is `migrateConfig()` at `core.js:394-511`. The current
  version is `CONFIG_VER_CURRENT = 10` (`header.js:191`); the latest migration
  block is the `ver < 10` branch at `core.js:482-505` (native queue migration).
  Any new persisted field needs a `ver < 11` block that writes its default.
- Sniffer contracts that plan 27 §0 ties to "Shadow-DOM UI hiding / variable
  rename":
  - `sniffBridgeBody` (`farms.js:1-60`) matches the bridge request **body**
    string against `/FarmTownPlayerRelation/` and `/BuildingOrder/` + `/Instant/`.
    These are URL/body regexes; CSS class names in the panel are invisible to
    them.
  - `TPL_FEATURE_MAP` and `tplNameFor` (`core.js:778-808`) key off JS symbol
    names (`claimTpl`, `attackTpl`, `ibAction`, `ibActionR`). CSS class names
    on the panel do not appear in this map and are not part of any sniffer.
  - The Queue Center template `native-ui.js:2-15` reads `state.nativeQueue` —
    pure state, not CSS. `nativeTownAction` (`native-ui.js:590`) injects
    `+` / `-` / `×` buttons into the game's own DOM via `GPWindowMgr`; CSS
    on `#grepbot-panel` cannot affect those nodes.
- **Conclusion:** changing panel colours is safe. Renaming panel CSS classes or
  ids, hiding the panel inside Shadow DOM, or restructuring the
  `panel.innerHTML` template would be unsafe — plan 27 §0 already bans that.

## 2. Gap

There is one fixed dark theme. Players who want a light panel either live
with it or hand-edit CSS. The plan delivers a small, scoped theme toggle
(dark/light/system) backed by CSS variables, with zero impact on the
sniffers, the game DOM, or the build queue / Queue Center contracts.

## 3. Design

Convert every literal colour in `GM_addStyle` (`ui.js:397-549`) to a CSS
custom property on the panel root, then resolve those properties under three
classes (`#grepbot-panel.gb-theme-dark`, `#grepbot-panel.gb-theme-light`,
`#grepbot-panel.gb-theme-system`). A fourth default rule (`#grepbot-panel`
without a theme class) keeps today's look, so no migration is required for
existing installs. The active class is set at boot and on Config toggle change.

Data flow:

1. `state.theme` (new, default `'dark'`) drives which class is on the panel
   element.
2. On boot, `boot.js` runs `applyTheme()` after the panel exists.
3. In Config, a new `select[data-cfg=theme]` writes the value to
   `state.theme`, calls `applyTheme()`, and `save(STORE.THEME, ...)`.
4. `applyTheme()` removes the three theme classes and adds the one
   corresponding to `state.theme`. For `'system'`, it reads
   `window.matchMedia('(prefers-color-scheme: dark)').matches` once at apply
   time and applies `'dark'` or `'light'` accordingly (no live listener —
   this is a small toggle, not a sync engine).

CSS variable set (declared on `#grepbot-panel`, scoped so the game's own DOM
is untouched):

```
--gb-bg        #181a1f
--gb-bg-alt    #22252b
--gb-bg-row    #262626
--gb-border    #414650
--gb-border-soft #353a44
--gb-fg        #eef1f5
--gb-fg-soft   #aeb5c0
--gb-fg-mute   #888
--gb-accent    #f5a623
--gb-ok        #8fe0a8
--gb-warn      #ffd27a
--gb-err       #ff9aa3
--gb-link      #6cf
```

The light-theme rule overrides each variable with a near-white pair. The
dark-theme rule is a no-op (defaults already match today's palette, so it
exists only as an explicit anchor for the system-mode resolver).

The Queue Center window (`#grepbot-queue-center` at `ui.js:525-543`) and the
panel share the same variable names — both scopes declare a re-binding under
each theme class so a light theme also lights the Queue Center. No rule
outside `#grepbot-panel` and `#grepbot-queue-center` is touched.

## 6. Config surface

- Label: `Tema del panel` (panel theme). Three options:
  `oscuro` (dark, default), `claro` (light), `sistema` (follows OS).
- Position: top of Ajustes, just above the per-town checkboxes (around
  `ui.js:800`). Rationale: theme is the first thing a user customizes; the
  existing layout puts always-shown, safe toggles there.
- Default: `oscuro` — matches what every existing install renders today.
- No HIGH-RISK toggle involved; risk stays Low.

## 7. Post surface & safety

Read-mostly feature: **no post surface**. No `bridgePost`, no `gbXhr`, no
`bridgePost`-covered DOM click. The only DOM side effect is toggling classes
on the panel and Queue Center, which is not a write and is not under
dry-run.

- No `gbAjaxWatch` registration needed.
- No `gbCaptchaPause` feature key needed (the feature never posts).
- No `gbLock` / `GB_LOCK_TTL` entry needed (no async work; class swap is
  synchronous).
- No dry-run gate needed.

## 8. Failure modes

- **`window.matchMedia` unavailable** (rare; covers Tampermonkey contexts
  without a `window`). `matchMediaDark()` returns `false` (treat as light);
  the user can still pick `oscuro` from the Config dropdown. No crash path.
- **User picks a theme before the panel is mounted.** `applyTheme()` is a
  no-op if `panel` is `null` (it is set at `core.js:386` and assigned during
  `panel.innerHTML = ...` at `ui.js:560`). On first boot the call from the
  boot sequence happens after `appendChild` (`ui.js:899`), so this is moot.
- **CSS variable inheritance across shadow boundaries.** The plan does not
  introduce any shadow DOM (plan 27 §0 explicitly forbids Shadow-DOM UI
  hiding). The two scoped roots (`#grepbot-panel`, `#grepbot-queue-center`)
  are both in the light DOM, so `var(--gb-...)` resolves in both.
- **Theme breaks the sniffer contracts.** Cannot happen — sniffers
  (`farms.js:1-60`, `core.js:778-808`, `native-ui.js:2-15`) key off URL/body
  regexes and JS state, not panel CSS. Plan 27 §0's "would break template-sniff
  contracts" wording targets DOM restructuring and shadow hides, not colour
  changes. This plan does neither.

Manual, per plan 27 §11 (Low risk = Preflight + one in-game session, no
failure).

- Install the new `grepbot.user.js`. Confirm panel still renders dark on first
  boot — no flash of unstyled content, no missing glyphs (font fallback at
  `ui.js:399-401` is intact).
- Config → Tema → `claro`. Panel background goes light; text stays dark; the
  amber accent at `ui.js:403-404` remains. Queue Center window (open it via

- Config → Tema → `sistema`. With OS in dark mode, panel is dark; switch OS
  to light mode and click the dropdown again — panel goes light (no live
  listener, so the toggle is re-applied on each user action, which matches

- Log tab shows zero new entries (theme emits no log).
- `python3 build.py` passes; install via paste into Tampermonkey.
- Preflight (Stats → Comprobar sistema) reports no new warn rows.

## 10. Out of scope

- **Per-theme font choice.** Theme only swaps colour tokens. Font stack is
  declared at `ui.js:399-401` and stays.
- **Per-theme icon set.** All icons are unicode glyphs (`_`, `[]`, `↑`,
  `×`, …) declared inline; no asset swap.
- **Auto-switch on time-of-day.** Some games have a day/night theme. Out of
  scope — plan 27 §6 lists only a static toggle.
- **Game-window theming.** The plan only touches the GrepBot panel and Queue
  Center. The Grepolis game UI itself is not restyled (ToS-adjacent and out
  of scope per CLAUDE.md "no Shadow-DOM UI hiding").
- **Theme picker UI** beyond the Config dropdown. No draggable swatch palette
  (that belongs to 6.2 Draggable widget system, planned separately).
