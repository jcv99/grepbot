# 6.2 — Draggable widget system

**Bucket:** v4.1 · **Risk:** Low · **Size:** M
**Module:** extend `qol.js` (introduces `gbWidget` API). The draggable handlers
currently live inline in `src/queue-center.js:372-388` — they get factored into
the new helper. `queue-center.js` becomes a consumer.
**Depends on:** none (6.11 and 6.14 consume this contract once it lands)
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.8.2

## 1. What exists today

The repo ships exactly **one** draggable GrepBot surface, and its drag logic is
not factored out:

- `src/queue-center.js:373-388` — the Queue Center window. The `mousedown` on
  `<header>` captures `{dx, dy}` into module-local `gbQueueCenterDrag`
  (`queue-center.js:15`); `mousemove`/`mouseup` listeners are added directly to
  `document` and then **manually re-registered** into `gbListenerBag`
  (`queue-center.js:388`) for the dispose path. The position is set inline with
  a viewport clamp; the listeners teardown cleanly but the **position is
  never persisted** — every `openQueueCenter()` call lands at `display:flex` in
  whatever the SPA last gave it (the inline CSS).
- `src/ui.js:1560-1580` — the main panel drag (header `<header>` of
  `#grepbot-panel`). Identical pattern, but uses `gbListen(handle, …)` +
  `gbListen(document, …)`, which routes through `gbListen`
  (`core.js:60-64`) into `gbListenerBag` automatically. Calls
  `savePanelGeom()` (`ui.js:1578`) which writes `state.panelGeom` to
  `STORE.PANEL_GEOM` (`core.js:281`, `header.js:63`). The persistence pattern
  is correct; the same pattern is what 6.2 generalises.
- `src/core.js:114-143` (`grepbotDispose`) removes the `#grepbot-queue-center`
  element at line 137; the main panel is removed at 135. Every widget we add
  has to register its own element id (or selector) for this loop.
- `src/queue-center.js:362` uses `document.body.appendChild(w)` for the
  singleton window; multiple widget instances need a different lifecycle (one
  per widget kind, plus persisted per-instance position).

Already shipped / not in scope: panel drag (above), panel resize
(`ui.js:1582-1630`), Queue Center drag (above), `gbListenerBag` dispose
contract (`core.js:124-127`).

## 2. Gap

The drag-handler code is duplicated across `queue-center.js` and `ui.js`, has
no shared contract (mount → enable drag → persist position → teardown), and
does not survive a reload for the Queue Center. Every new widget (6.11, 6.14,
plus anything 6.x adds later) would re-invent the listeners, clamp math, and
persistence. The plan extracts the API once and lets 6.11/6.14 consume it.

## 3. Design

A new module-local helper `gbWidget(opts)` in `qol.js`, modelled on the proven
Queue Center pattern. Three entry points:

```
gbWidget.register({ id, title, defaultPos, render(host), tickMs? })
  → returns { open(), close(), isOpen(), el, dispose() }
gbWidget.unregister(id)       // removes element + drag state + listeners
gbWidget.list()               // returns registered ids (Config UI helper)
```

Data flow:

1. `register` allocates a host `<div>` with the standard `.gb-widget` chrome
   (header + close + content slot), appends to `document.body`. Position
   pulled from `state.widgetGeom[id]` (new key, see §5); falls back to
   `defaultPos = { left: '8px', top: '60px' }`.
2. `render(host)` is called once on mount and again whenever
   `gbWidget.refresh(id)` fires. The widget owns its own DOM inside `host`;
   the helper only owns the chrome.
3. `mousedown` on the header (excluding `button, select`) captures the
   viewport-relative delta. `mousemove`/`mouseup` listeners are added to
   `document` **and** registered via `gbListen` (so they land in
   `gbListenerBag` automatically — same mechanism the main panel uses,
   `ui.js:1568-1579`). On `mouseup` if the position changed, write
   `{left, top}` to `state.widgetGeom[id]` and `save(STORE.WIDGET_GEOM, …)`.
4. `dispose()` removes the element, **and** calls `gbListenClear`-equivalent
   cleanup by deleting the widget's stored listener ids. Falls back to manual
   `gbListenerBag` removal if the helper is unmounted mid-tick. Idempotent.
5. `grepbotDispose` (`core.js:114-143`) is extended with one line: iterate
   `state.widgetGeom` keys, look up live widget handle, call `dispose()`.
   This is the same shape as the existing line 137 that removes
   `#grepbot-queue-center`.

The clamp math is taken verbatim from `queue-center.js:381-382`:

```
left = max(0, min(innerWidth - el.offsetWidth, clientX - dx))
top  = max(0, min(innerHeight - el.offsetHeight, clientY - dy))
```

Optional `tickMs` fires `render(host)` on a `gbInterval` — see 6.11 (1s
countdown refresh) and 6.14 (1s ETA countdown). The interval is owned by the
widget, registered through `gbInterval` (`core.js:23-29`), and torn down on
`dispose()`. **No new scheduler** — these go through the existing
`gbInterval` wrapper which already entries into `gbTimerBag`.

The Queue Center becomes a thin wrapper:

```
gbWidget.register({
  id: 'queue-center',
  title: 'Colas GrepBot',
  defaultPos: { left: '50%', top: '40%' },
  render: (host) => renderQueueCenterInto(host),
});
```

Its current `openQueueCenter(tab, townId)` shim still exists but routes the
mount through `gbWidget`. The header `mousedown` handlers at
`queue-center.js:373-388` are deleted.

## 5. State & storage

- `state.widgetGeom = { [id]: { left: '120px', top: '80px', hidden: false } }`
  — keyed by widget id (`queue-center`, `production-overlay`, `attack-eta`,
  etc.). Persisted via `STORE.WIDGET_GEOM` (`grepbot:widget-geom`).
- **World-scoped**: yes. A player who plays two worlds typically wants the
  same widget layout on each, but a multi-account setup where the windows
  are sized to one screen resolution does not. World-scoping matches the
  `WORLD_SCOPED_BASES` convention (`header.js:193-215`). Add to the Set.
- `configVer`: bump `CONFIG_VER_CURRENT` in `header.js:191` (currently 10)
  to 11 — new storage key.
- **Prune TTL**: not applicable. Widget geometry is small, never times out.

## 6. Config surface

- `Widget posiciones: recordar al cerrar` — default ON. When OFF, `mouseup`
  does not call `save(STORE.WIDGET_GEOM, …)`. Existing `state.panelGeom`
  already has this affordance (`ui.js:1578`); copy it verbatim into the new
  code path.
- Per-widget visibility toggle under the Config → *Widgets* subsection
  (added by work item 6). Default for each new widget = OFF until the
  shipping widget itself flips its default; see 6.11/6.14 for those.
- **No HIGH-RISK toggles** (read-only positioning). No `gbCaptchaPause`
  feature key needed.

## 7. Post surface & safety

This feature is read-only (no posts). The widget API does not call
`bridgePost`, `gameAjaxPost`, or `gbDomClick`. The Config row in work item
6 is a plain toggle — no post. Skip the rest of the checklist.

## 8. Failure modes

- **Listener leak on dispose.** If `dispose()` is called while a `mousedown`
  is mid-flight (race), the `mouseup` will set position on a detached
  element. Mitigation: track an `alive` flag per widget; `mouseup` early-
  returns if `!alive`. The same pattern lives at `queue-center.js:374-388`
  today (no flag, but the inline closure frees `gbQueueCenterDrag` on
  `mouseup`, which still no-ops if the element is gone — relies on
  `document.body.contains(w)` at `queue-center.js:330`).
- **Two widgets overlapping.** The default positions are deterministic
  (top-left corner with a 30px cascade) so two widgets never open at the
  same pixel. If the user manually drags them on top of each other, the
  click target is whichever was appended last (`document.body.appendChild`
  z-order). Out of scope — this is intentional freedom.
- **SPA navigation detaches the widget.** `core.js:124-127` clears
  `gbListenerBag` on dispose, but SPA `pushState` (handler at
  `boot.js:9-34`) calls `ensurePanelMounted` to re-append the main panel.
  Extend `ensurePanelMounted` (`boot.js:1-8`) to re-append any registered
  widget whose host is missing (`!document.body.contains(host)`).
- **Unreadable viewport during boot.** `innerWidth`/`innerHeight` is 0 if
  the script fires before layout; the clamp math then pins the widget to
  the corner. Acceptable.

Manual, per plan 27 §11 (Low risk). One in-game session on `es146`:

- Open Queue Center, drag to (300, 200), close. Reopen — lands at
  `(300, 200)` (this is **new** behaviour; before this plan it reset).
  Log shows `widget: geom saved queue-center {left: 300px, top: 200px}`.

  Reports → World). No console errors. Widgets remain visible at saved
  positions.

  .__grepbotDispose()` then `unsafeWindow.location.reload()`. Log shows
  `grepbot: dispose` and the next boot starts clean (no orphan listeners,
  no `#grepbot-widget-*` nodes left over).
- **Preflight**: add a `widget system` row to `preflightRun`
  (`src/stats.js:12-191`) that checks `typeof gbWidget === 'function'` and
