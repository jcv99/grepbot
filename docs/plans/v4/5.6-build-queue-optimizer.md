# 5.6 — Build queue optimizer (local reorder for minimum idle)

**Bucket:** v4.2 · **Risk:** Low · **Size:** S
**Module:** extend `native-ui.js` (the native FIFO queue and its planner
adapter live there); UI in `queue-center.js`. **NOT** `build-targets.js` —
plan 27's module hint is wrong on this one; `build-targets.js` only owns
`state.abOrder` / `state.abTargets` and has no FIFO queue surface.
**Depends on:** 1.2 (city profiles) for the per-town profile read, used only
to gate the suggestion threshold; the swap itself needs no profile data.
**Status:** PLANNED — written 2026-08-10 against `src/` @ v3.8.2

## 1. What exists today

- **The queue being optimized is `nativeQueueList(townId,'build',false)` in
  `native-ui.js:21`.** It is a stable FIFO list of `{id, building, fromLevel,
  toLevel, status, reason, …}` jobs, populated by `nativeQueueAddBuild`
  (`native-ui.js:205-269`) from the Senate window's `[+]` tile or the Queue
  Center's **+ Añadir secuencia** button (planned by 2.9). Each town has its
  own list with a `mode: 'legacy' | 'fifo'` (`native-ui.js:11`); a town in
  `fifo` mode ignores `goalEffectiveBuildTargets` entirely
  (`build-auto.js:180-181`).
- **The auto-queue already skips a blocked head.** `nativeQueueBuildPlan`
  (`native-ui.js:337-352`) returns `{hasJob:true, plan:null, why}` with
  `why ∈ {'paused','lane-review','manual-review','inflight',
  'special-conflict','max-unreadable','max-level', ...}` and the head is
  marked `waiting-resources` / `waiting-population` / `blocked` via
  `nativeQueueSetJobState` (`native-ui.js:309-317`). `abFinalValidate`
  (`build-auto.js:204-224`) re-checks the head right before posting, and
  `abPickNextFromLevels` (`build-auto.js:178-202`) only ever picks
  `list[0]`.
- **No swap.** The FIFO contract is "head posts, rest wait". When the head
  is `waiting-resources`, the rest of the list sits idle even if a later
  entry is currently affordable. `abScan` (`build-auto.js:266-369`) walks
  town-by-town and stops at `q.len >= q.max` (`build-auto.js:335-338`), so a
  town with a blocked head and a free queue slot does nothing — the next
  town is processed instead. That is the "idle gap" 5.6 targets.
- **No `abCustomQueue` / `abPin` / `abQueueStrict` in `src/`.** Plan 23's
  symbols do not exist (verified by grep; same finding as 2.9 §1 and the
  plan 26 §B2 mistake). The user's "explicit queue" here is the native
  FIFO.
- **Reorder API exists.** `nativeQueueMove(townId, lane, jobId, delta)`
  (`native-ui.js:45-50`) reorders within the list and is what the Queue
  Center ↑/↓ buttons call (`queue-center.js:150-156`). It refuses to move
  any job whose `inflight` or `manualReview` flag is set; this is the gate
  the optimizer must respect.

## 2. Gap

When the FIFO head is `waiting-resources` for more than a few minutes the
user's later entries are paying no dividend. A local swap — promote an
**affordable** successor past the blocked head — recovers the slot without
violating the user's authorship: the user said "these, in this order", not
"wait until the first is affordable even if another is ready now". The
optimizer proposes a swap, never silently performs one.

## 3. Design

Add two helpers in `native-ui.js` and one UI affordance in
`queue-center.js`. No new posts; the swap is a list mutation that goes
through the existing `nativeQueueMove` API.

**`nativeQueueHeadBlockedFor(townId, opts)`** — returns
`{townId, jobId, why, forMinutes}` where `forMinutes` is how long the head
has been in a `waiting-*` state. Backed by `job.status`, `job.reason`,
`job.reasonUpdatedAt` (set by `nativeQueueSetJobState`
`native-ui.js:309-317`). Threshold: ≥ 5min (configurable via
`state.buildSwapThresholdMin`, default 5, OFF = disabled).

**`nativeQueueSuggestSwap(townId, opts)`** — scans
`nativeQueueList(townId,'build',false)` from index 1 forward; for each job
calls `abResolvePrerequisite(townId, j.building, levels)` and
`abCanAfford(townId, j.building)` (both already in `build-auto.js`),
returning the first affordable, non-blocked entry. Returns
`{successorIndex, successor, swap: {headId, successorId, from, to}}` or
`null` if no successor is affordable in the same town. **One town at a
time** — cross-town reordering is out of scope.

**UI — Queue Center Construcción card.** When the head has been
`waiting-resources` ≥ threshold and a successor is affordable, render a
small banner under the FIFO plan card with text "Sugerencia: ascender
`<successor>` mientras se esperan recursos para `<head>`" and two buttons
**Ascender** / **Ignorar**. Click **Ascender** calls `nativeQueueMove(
townId,'build', successorId, -successorIndex)` — the existing API
(`native-ui.js:45-50`), which refuses on any inflight/manualReview so the
optimizer cannot break a frozen head. **Ignorar** stamps
`state.buildSwapIgnore[townId+headId]` (TTL 10min) so the same suggestion
does not flash again before the head recovers.

**Precedence rule.** FIFO head still wins for the auto-queue: nothing in
5.6 changes `abPickNextFromLevels` (`build-auto.js:178-202`) or
`nativeQueueBuildPlan` (`native-ui.js:337-352`). The optimizer is a UI
suggestion that mutates the list on a user click; the auto-queue then
respects the new order naturally. The user's explicit queue wins in both
the original and the swapped order — there is no case where 5.6 displaces
the head without consent.

## 5. State & storage

- `state.buildSwapThresholdMin` — number, default 5, OFF=0. Not
  id-bearing; no world-scope.
- `state.buildSwapIgnore = {}` — `{ [townId+':'+jobId]: untilTs }`.
  Id-bearing ⇒ **`STORE.BUILD_SWAP_IGNORE` is a new key, add to
  `WORLD_SCOPED_BASES` in `header.js:193-214`** next to `STORE.NATIVE_QUEUE`
  (line 209).
- `configVer` bump (CLAUDE.md / plan 27 §13).
- Prune TTL: 10min (the `untilTs` is what enforces it; no 7d ring needed —
  the cache never grows beyond a few entries per town because the user can
  only ignore a head once per block cycle).

## 6. Config surface

- `state.buildSwapThresholdMin` — number input, **default 5**. Low risk,
  no HIGH-RISK rule applies (the user-confirmed swap is the consent gate;
  see §3).
- `state.buildSwapIgnore` reset button — parity with other
  reset-style rows in `qol.js`.
- No new top-level toggles.

## 7. Post surface & safety

- **No new post surface.** `nativeQueueMove` (`native-ui.js:45-50`)
  mutates the list and calls `nativeQueueRebaseBuild` /
  `nativeQueueSave` — neither posts. The next `abScan('native-watch')`
  (`boot.js:91`) sees the new head and `nativeQueueBuildPlan`
  (`native-ui.js:337-352`) returns its `ready` / `waiting-resources` plan.
  The post that fires is the same `bridgePost('build', …)` from
  `abBuildUp` (`build-auto.js:246`) — already journaled, captcha-gated,
  and dry-run-aware.
- `gbCaptchaPause` — no new feature key needed.
- `gbLock` — no new lock; the swap runs between two `abScan` calls, not
  inside one, and the gate (`inflight` / `manualReview`) is enforced by
  `nativeQueueMove` itself. Adding `ab` to `GB_LOCK_TTL` is unnecessary.
- `gbAjaxWatch(sig, settle)` — no new template.
- `TPL_FEATURE_MAP` — no change.
- **Dry-run behaviour** — with `state.dryRun = true`, the swap still
  works (it is a list mutation); the subsequent `abScan` posts become
  `DRY-RUN build: … buildUp` lines. This is the right parity — the user
  can validate "swap promotes Y, head recovers" without spending a slot.

## 8. Failure modes

- **Unreadable levels / costs** (`abCurrentLevels(townId)` returns `null`,
  `build-auto.js:14-33`) → `nativeQueueSuggestSwap` returns `null`; the
  banner does not appear; `gbLogT('build-swap-blind-'+townId, 60000, …)`
  once.
- **Unreadable planner ledger** (`plannerAvailable(townId)` returns
  `null`, `planner.js:82-86`) → swap suggestion suppressed; the banner
  reads "planificador ilegible" and **Ascender** is disabled.
- **`nativeQueueMove` refuses** on `inflight` / `manualReview`
  (`native-ui.js:47`) → flash the same reason the Queue Center × button
  uses (`queue-center.js:103-114`); the banner stays visible so the user
  can retry once the head recovers.
- **Cycle in prerequisite walk** (`abResolvePrerequisite` returns
  `{error:'dependency-cycle'}`, `build-auto.js:162`) → `nativeQueueSuggestSwap`
  skips that successor and tries the next; no log spam (`gbLogT` keyed on
  the successor id+townId, 60s throttle).
- **The user has zero FIFO entries** (`nativeQueueList(townId,'build',
  false).length === 0`) → no banner; this is also the legacy-mode path
  where `goalEffectiveBuildTargets` already drives picks and the head is
  never "blocked on resources for 5min" in the same way.
- **Cross-town ambiguity** — the suggestion is always intra-town. If the
  user has a blocked head in town A and an affordable build queued in
  town B, the banner does not appear and the swap does not happen.
  Cross-town rebalancing is plan 5.1 territory and depends on
  transport automation (1.3); out of scope here.

## 9. Validation gate

Manual, per plan 27 §11 Low class: Preflight + one in-game session, no
failure.

1. **Preflight** — `build swap suggestion` row reports
   `cabeza esperando Xm · sucesora: Y` for a town whose head has been
   `waiting-resources` for ≥ 5min and whose second FIFO entry is currently
   affordable. With threshold = 0 the row reads `desactivado`.
2. **Queue Center Construcción** — open the Build tab on a town with a
   blocked head and an affordable second entry; the banner appears with the
   correct suggestion. Click **Ascender**; the FIFO card repaints with the
   two jobs swapped (head now affordable, second now head). `abScan` fires
   within ~80ms (`native-ui.js:268`); the first build lands.
3. **Head recovery** — when the resources for the original head arrive, the
   FIFO order remains swapped (we are not auto-reverting). `abScan` will
   build the now-affordable head and reconcile the rest naturally via
   `nativeQueueReconcileBuild` (`native-ui.js:325-335`).
4. **Ignore path** — click **Ignorar**; the banner hides. Within 10min the
   suggestion does not re-appear even if the head is still blocked. After
   10min it can appear again.
5. **Precedence preserved** — with `state.abAuto` ON and the FIFO head
   swapped, `abPickNextFromLevels` picks the new head (the now-affordable
   successor), never the original head. The original head, now in slot 2,
   gets built when resources arrive.
6. **Dry-run parity** — `state.dryRun = true`; perform the swap; verify
   the post line `DRY-RUN build: BuildingOrder/buildUp …` fires for the
   new head, not the old one.

## 10. Out of scope

- **Auto-swap without user click.** Plan 27 §5.6 says "local reorder for
  minimum idle", which reads as user-confirmed; an auto-swap variant
  would need a HIGH-RISK toggle (default OFF per CLAUDE.md) and is
  deferred. The current plan's contract is "suggest, never silently do".
- **Cross-town reorder.** See §8; cross-town balancing belongs with 5.1
  resource balancing AI.
- **Reorder to minimise *gold* idle, not just resource idle.** Grepolis
  has no gold cost on `buildUp`; the planner ledger covers wood/stone/
  iron/population/tradeCap only (`planner.js:1`). No further dimension
  to optimise without inventing a new cost.
- **A general "auto-promote to head" rule for the legacy (non-FIFO) lane.**
  The legacy lane picks targets one at a time from
  `goalEffectiveBuildTargets` and skips past `waiting-resources` via
  `afford` (`build-auto.js:197-198`). The skip is already correct for the
  legacy case; 5.6 only addresses the FIFO lane.
- **Implementing plan 23's `abCustomQueue` / `abQueueStrict` knobs.**
  Those are owned by plan 23's eventual rewrite; 5.6 reuses the native
  FIFO surface they were meant to wrap.
