## 1. What exists today

The decision plumbing is split across `wonder.js` and `dodge.js`. None
of it is in `military.js` despite the plan 27 hint.

- `wonder.js:144 defenseAssessment(mov, incoming)` — per-incoming
  `{eta, simultaneous, local, supports, safeTown, evac, militia, risk,
  hasCs}`. Risk is built by literal increments (`if(mov.hasCs) risk+=60;
  if(eta!=null&&eta<15*60) risk+=25; …`) — no per-attack-type breakdown
  beyond `hasCs`.
- `wonder.js:145 defenseShouldDodge(mov, incoming)` — wraps with a
  literal `if(a.hasCs || a.risk >= 35)` threshold; returns `{yes,
  assessment, why}` consumed by `dodgeTrySend` (`dodge.js:207`).
- `wonder.js:142 defenseLocalStrength(townId)` — `dodgeTownUnits` per
  unit id, scores defense/both kinds weighted by `unitMeta.population`;
  naval units (`m.is_naval`) excluded.
- `wonder.js:143 defenseSupportOptions(dest, eta)` — own towns whose
  defense-shaped units can reach `dest` before `eta`; boat capacity and
  `isSameIsland` validated. Sorted by travel time ascending.
- `dodge.js:39 DODGE_HOSTILE_TYPES` — canonical vocabulary
  `attack|attack_sea|raid|siege|revolt|colonize|take_over|conquer|portal_attack`.
- `dodge.js:203-251 dodgeTrySend(entry, mov)` — the firing path; posts
  `bridgePost('dodge', payload)` with hardcoded `attackTpl.action_name
  || 'sendUnits'` (`dodge.js:130-138`).
- `dodge.js:252-296 dodgeScan(reason)` — main loop, scheduled on
  `gbInterval(() => dodgeScan('loop'), DODGE_CHECK_MS=5000)`
  (`boot.js:100`, `wonder.js:150`).
- `state.defenseCfg = {mode: 'notify'|'safe'|'smart', smartAuto: false,
  returnMarginSec: 120}` (`core.js:359`). UI at `ui.js:824`,
  `ui.js:1350-1353`, `ui.js:1470-1472`. `smartAuto` default false per
  HIGH-RISK (`core.js:504`), force-migrated when `dodgeMode === 'auto'`
  (`core.js:502-504`). `DEFENSE_CFG` is world-scoped (`header.js:209`).
- The literal `35` threshold is hardcoded inside `defenseShouldDodge`
  (`wonder.js:145`); it is **not** in `state.defenseCfg` today.

**Wrong-module-hint finding.** Plan 27 §5 row 5.4 says "extend
`military.js`". `military.js` has no smart-dodge logic — it owns

(per-type risk table + threshold pin) + `dodge.js` (consumer).

## 2. Gap

`defenseAssessment` treats every non-CS hostile incoming as the same
risk baseline (`+25` for any eta<15min, +10 for low local, etc.). A
ten-archer scout and a 200-sword siege both score identically on the
non-CS path. The smart dodge the user actually wants:

- is **calmer** for `raid` (small, fast, often loot-only, dodge is over-
  reaction);
- is **firm** for `attack` and `attack_sea` (default posture);
- is **aggressive** for `siege` (cata damage, no milita match);
- is **forced** for `revolt|colonize|take_over|conquer|portal_attack`
  (the town is gone anyway if it lands; the units are the only salvage).

The literal threshold `35` in `defenseShouldDodge` was chosen when CS
was the only type-bump; with per-type risks, the threshold needs to
move with them. Exposing the threshold and the per-type scores as
Config is the smallest delta that gives the user agency without
introducing a new surface.

## 3. Design

A typed risk table replaces the literal `hasCs` branch. The dodge
threshold is pinned in `state.defenseCfg.riskThresholdDodge` and
defaulted to the current `35`.

```
incoming movement →
  dodgeScan (dodge.js:252) →
    dodgeTryMilitia (parallel, plan 3.6) and
    dodgeTrySend (dodge.js:203) →
      defenseShouldDodge (wonder.js:145) →
        defenseAssessment (wonder.js:144) →
          defenseAssessmentFor(mov, incoming)  ← NEW, replaces literal
            ├── typedRisk = state.defenseCfg.attackRisk[type] ||
            │               state.defenseCfg.attackRisk._default
            ├── risk = typedRisk
            │         + etaRisk(eta)               (≤15min:+25, ≤5min:+35)
            │         + simultaneousRisk(n)         (max +25, +8/stack)
            │         + weakLocalRisk(local.score)  (≤200:+10)
            │         - supportRisk(supports)       (max -20, -5/option)
            ├── alwaysCsRisk: if (mov.hasCs || type in COLONIZE_TYPES)
            │       risk += state.defenseCfg.attackRisk.csBonus (60)
            └── return {eta, simultaneous, local, supports, safeTown,
                       evac, militia, risk, hasCs, attackType:type}
        decision: yes = (mode==='safe') ||
                       (mode==='smart' &&
                        state.defenseCfg.smartAuto &&
                        a.evac.ok && (a.hasCs || a.risk >= threshold))
```

Per-type keys (default values, configurable later):
`raid:5, attack:15, attack_sea:15, siege:40, revolt:70, colonize:70,
take_over:70, conquer:70, portal_attack:70, _default:25,
csBonus:60`.

The risk formula itself is unchanged shape; the typed lookup is a
single replacement. The supporting branches (`eta`, `simultaneous`,
`local`, `supports`) stay in `defenseAssessment`.

## 8. Failure modes

- Unrecognised `mov.type` string → `riskForAttackType` falls back to
  `attackRisk._default` (25); `gbLogT('risk-type-unknown', 60000)` once
  per session. Decision path identical to today.
- Malformed `attackRisk` object from `qolImportConfig`:
  `core.js:464` migration resets to defaults; the validator at
  `qol.js:251` requires `isObj` (non-array object). `Number.isFinite`
  guard in `riskForAttackType` for any operator-typed value.
- Smart-auto ON, support in a hostile island with no boats:
  `dodgeSupportValidate` already refuses (`dodge.js:162-163`). The smart
  threshold is irrelevant; no post without green validate.
- Wave of 5 simultaneous low-risk raids on the same town:
  `simultaneous=5 → simultaneousRisk = min(25, (5-1)*8) = 25`. Combined
  with `raid=5` we land at ~30 — below threshold 35, smart-dodge does
  NOT fire (militia path may). If the operator wants simultaneous
  waves to elevate risk further, it's a per-type tuning — exposed in
  Config.
- Stats panel rendering with stale entries: the 1h TTL prune keeps the
  buffer bounded; an overnight tab is empty by morning. No leak.

Per plan 27 §11 High risk: **payload sniff against live UI + confirm-gate
screen + dry-run + manual re-fire, then still default OFF**. Plus plan

Steps on `es146`:

1. With `state.dryRun === true` and `state.defenseCfg.mode === 'smart'`,
   `smartAuto === true`: stage a single hostile attack. The Log MUST

2. Sniff: with the dry-run decision `no`, re-run with a CS-flagged

3. Re-fire manually once with `state.dryRun === false`; verify dodge
   fires **only** when smart decided yes. Stat counter +1.
4. Per-type calibration: run `raid`, `attack`, `siege` in sequence
   against the same defender. Risk scores MUST rank
   `raid < attack < siege`. If they don't, debug per-type Config.
5. CS path: `colonize_ship`-bearing incoming — risk MUST include
   `csBonus` regardless of type lookup; smart-autododge fires
   (verifiable in journal).
6. Confirm-gate: every fire of `dodgeTrySend` runs through
   `dodgeSupportValidate` and `safeTown` (`dodge.js:215-217`). This
   plan adds **no** new human-visible confirm dialog (auto-dodge has
   never had one).
7. **Shipping default**: `mode = 'notify'`, `smartAuto = false`. Do
   **not** flip the default to `'smart'` even if validation passes.

## 10. Out of scope

- Predicting attacker composition from `mov.units` — those are the
  attacker's, not the defender's; reading them requires a counter-spy
  (plan 4.2).
- Friendly-return dodging — filtered by `dodgeIsHostileMovement`; this
  plan stays hostile-only.
- Re-evaluating decisions within the same wave. `defenseAssessment`
  re-runs every 5s tick; a wake-on-incoming optimization is a separate
  change (the wake queue is heterogeneous, `core.js:632`).
- A "force-dodge all" toggle. `defenseMode === 'safe'`
  (`wonder.js:145`) already does that. Plan 5.4 is the smart axis
  only.
- Crossing the `[10..200]` validator on the threshold. Operators
  who need extremes must use `qolImportConfig` (documented power-user
  path).
