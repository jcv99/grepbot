# 27 - User-wishlist sweep (v4 candidates)

Written 2026-08-10 against `src/` @ v3.8.2 (post v3.x sweep). Derives the next
~50 features from a single user intake. This is **not** the next plan of record
(current: plan 26) — it is a future-feature catalogue that feeds a future
plan-of-record after plan 26 ships + TASKS gates pass.

**How to use this plan:** P0 features in §1 unblock the rest. Coding order is
§6. Before each feature reaches runtime it must go through the validation path
in §5, which mirrors the per-package discipline in `ROADMAP.md`.

Every feature in this plan must satisfy:

- **Bridge-first.** `bridgePost` / `gameAjaxPost`; DOM only as fallback through
  `gbDomClick`. Same rule as plan 26 §0.
- **Precondition invariant.** No guard on a value that wasn't read. Unreadable
  getter ⇒ `blind` + `gbLogT` once + let the server decide.
- **No new `*InFlight` booleans.** Use `gbLock` + `GB_LOCK_TTL` entry.
- **No new schedulers.** Economy/scout features wire into the orchestrator.
- **World-scoped id storage** for any id-bearing key.
- **Dry-run gate** before any live post (per v1.4.0 + ROADMAP P15.1).
- **HIGH-RISK toggle default OFF** for any spendy/autonomous action, per
  `CLAUDE.md` ("HIGH-RISK toggles ... default OFF").

## 0. Out-of-scope bucket (policy)

Per `CLAUDE.md`: never ship anticaptcha solvers, never reintroduce a phone-home
server, never load credentials. The following user ideas are dropped for this
reason:

| Dropped idea | Policy line |
|---|---|
| Bezier mouse / click randomization / typing WPM / scroll injection | GrepBot ships no user-event I/O — it talks only to the bridge + DOM-fallback hooks. No fingerprintable surface. |
| Canvas / WebGL / font fingerprint noise | Requires WebExtension privileges the userscript context doesn't have. |
| Shadow-DOM UI hide / variable rename in artifact | Would break template-sniff contracts (`claimTpl`, `attackTpl`, `ibAction`). |
| Tab-focus simulation | Game client owns focus; tampering invites anti-cheat. |
| Cloud sync (Google Drive / Dropbox) | OAuth outside userscript context. |
| REST API / WebSocket feed / hot-reload server | No local server. Past 0.5.0 explicitly retired the WebExtension + standalone. |
| Plugin / extension system | concat-order brittleness + ToS. |
| Auto-recovery relogin | Cookie session can't be restored from Tampermonkey safely. |
| Auto-update XPI | No `.xpi` since v0.5.0. |
| Remote feature flags | Needs server. |
| Delta updates | Needs server. |
| Automated test harness | CLAUDE.md: "No linter, no test runner." |
| Anti-pattern detection (anti-counter-farm) | Anti-cheat avoidance; explicit policy ban. |
| Auto-recovery / bot companion (Telegram bot replying to chat) | Needs server / cross-context auth. Outbound webhooks already ship in `alerts.js`. |
| Auto cookie / alt-account isolation | Browser cookie boundary, not GrepBot's responsibility. |

**Conditional / gray-area**

| Idea | Disposition |
|---|---|
| Google Sheets export | Requires user-supplied Apps Script webhook URL; add as an optional `alerts.js` sink (default OFF). |
| Telegram bot **inbound** (chat → GrepBot) | Needs server. Outbound is already coded; inbound stays out. |
| Inventory auto-sell | Game auto-sells on warehouse full; bot adds no value. |

These do not become features here.

## 1. P0 — cross-cutting infra before any UX/data-plane feature

These three are the foundations that almost every later feature reads. Build in
this order.

| # | Feature | Risk | Size | Module hint |
|---|---|---|---|---|
| 1.1 | **Panic mode (instant-pause button)** | Low | S | `core.js` wrapper; wire `qol.js` Actions menu |
| 1.2 | **City specialization profiles (offensive/defensive/resource/balanced/custom)** | Low | M | new `city-profiles.js` |
| 1.3 | **Inter-city transport automation** (`transport.js` + island routing) | Med | M | new `transport.js` |

- **1.1** halts every loop immediately: orchestrator.skip = true; all locks
  expire-now; `dryRun` ON; footer red `⚠ PANIC`. Recovery: 30s grace + Clear
  skips. Honors `CLAUDE.md`'s `automationPaused` semantics.
- **1.2** writes per-town profiles into `state.cityProfiles[townId]`. Each
  existing feature (build, recruit, research, transport) reads
  `gbCityProfile(townId)` and rebalances. Profiles already partially exist via
  `qol.js` templates (9.2); this widens the schema.
- **1.3** is the prerequisite for resource balancing (5.4), resource dump
  (3.4), trade route manager (3.2), and the AI solver (5.1). Sniff
  `transportTpl`. Island-routing reuse from `trade.js` `islandShip`.

Validation gates (do all three before opening 2.x):

- 1.1: Action → Panic → 30s grace → resume all loops intact; Log
  `panic: activated`, `panic: resumed`.
- 1.2: pick profile 'defensive' for a town → Log shows recruit mix bias changed
  for that town only; other towns unaffected.
- 1.3: two towns, one surplus wood, one deficit → bridge `transport` fires once
  per tick until balanced; idempotent (re-firing with 0 delta = skip).

## 13. Cross-cutting conventions (re-stated)

- Every learned template registered with `gbAjaxWatch(sig, settle)`. Cross-ref
  `core.js`, `tx.js` (v1.6.1).
- No new top-level `function` declarations that risk the build.py gate
  (duplicate top-level declarations). Module-local IIFE wrapping when adding
  helpers.
- Storage prune TTL: 7d uniform unless the slice needs longer (journal.js).
- Every Config toggle has a `configVer` bump and ships with redaction off by
  default (`qol.js`).
- Captcha breaker coverage: every new post surface gets a feature key in
  `gbCaptchaPause` (the registry `bridge.js` already exposes).
